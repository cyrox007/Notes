# My Local Server System
## Description
PHP суперприложение для работы с: 
* персональными заметками на корпоративном предприятии;
* Хранение и работа с личными файлами пользователя;
* Плеер мультимедия;
* CodeExplorer;
* Мессенджер;
* Ежедневник;
* Задачи;
## Requirement
-> PHP7.1
-> SQLite3
## Условия для запуска
Для работы системы требуется файл .htaccess со следующим содержимым
``` apache
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule .* index.php [L]
```
Так же необходимо установить зависимости для работы сервера WebSocket
``` bash
composer install
```
Запуск сервера WebSocket'a 
``` bash
php ws_server/server.php start
```
Так же для работы приложения необходима база данных SQLite, которую необходимо сформировать самостоятельно
## Работа с приложением
### Маршрутизация
Приложение автоматически считывает GET-запрос и определяем наличие запрашиваемого котроллера для работы.
Порядок обработки запросов следующий: 
``` 
http://mysite.ru/controller_name/action_name/
```
где controller_name -- имя котролера,
а controller_name -- имя функции в контроллере.

Таким образом, если мы, например, запрашиваем страницу авторизации, то адрес страницы будет следующим:
```
http://mysite.ru/Auth/login/
```
где Auth -- является классом Controller_Auth в файле controller_auth.php,
a login относится к функции action_login, в выше указанном классе.

По умолчанию маршрутизатор загружает "controller_main" и "action_index"

Если по каким-либо причинам происходит несовпадение по одному их параметров при запросе, то вызывается исключение 404 Page Not Found.

Не рекомендуется располагать приложение на сервере таким образом что запрос будет к нему не из корня доменного имени, а дочерней директории. В таком случае приложение не будет работать, и всегда вызывать исключение 404.
### Контроллеры
При запросе к приложению вызывается специальный класс Сontroller_Name, являющийся дочерним класса Controller.
Контроллер отвечает за логику того или иного аспекта приложения, будь то, главная страница или страница авторизации или регистрации. После выполнения работы контроллера происходит загразка шаблона, с передачей всех необходимых параметров в него.

Располагать файлы контроллера необходимо в папке `app/controllers`.
Имя файла контроллера всегда должно начинатся с имени `controller_`, и после нижнего подчеркивания указываем имя контроллера, cуказанием расширения `.php`, например: `controller_admin.php`.

Когда вы будет разрабатывать логику своего контроллера, необходимо в первую очередь указать имя класса контроллера, и что это расширение класса контроллера, например: 
``` php
class Controller_Admin extends Controller {
    #code...
}
```
Вы должны помнить, что любой контроллер должен иметь в себе функции. По умолчанию маршрутизатор будет искать в загружаемом контоллере `action_index`, а это значит вы должны его указать в своем контроллере
``` php
class Controller_Admin extends Controller {
    function action_index() {
        #code...
    }
}
```
Можно указать и другие функции для загрузки. В этом случае их имя должно всегда начинатся с `action_`, после нижнего подчеркивания пишете имя функции, например: `function action_users () {}`.
### Модели
Модели необязательный класс, подключаемый к контроллеру, для работы с ресурсами базы данных. Для того чтобы создать модель для работы с БД, вы должны создать файл в директории `app/models`, с именем, который начинается с `model_` и заканчивается указанием расширения `.php`, например: `model_admin.php`.

Непосредственно в файле модели вы указываете название класса и расширение класса модели: 
``` php
class Model_Admin extends Model {
    #code...
}
```
Таким образом ваша модель будет наследовать стандартные функции для работы с базой данных, и вы сможете настроить эти функции для выполнения своих специализированных задач. 
Для того чтобы иметь возможность вызвать ваши функции, или даже стандартные функци модели в вашем контроллере, вы должны создать объект класса модели.
``` php
public function __construct() {
    $this->model = new Model_Admin();
}
```
### Шаблонизатор 
Шаблоны - это лицо вашего приложения. Шаблонизатор реализован таким образом, что при загрузке и выполнении логики любого действия контроллера можно вызвать в самом конце функцию представления. Для этого необходимо в вашем контроллере создать объект класса представления.
``` php 
public function __construct() {
    $this->view = new View();
}
```
После этого вам становиться доступным функция представления в дейсвии контроллера:
``` php
function action_admin() {
    $this->view->render_template('admin_view.php', 'template_view.php', $data);
}
```
Располагать файлы шаблона необходимо в директории `app/views`. 
`template_view.php` будет хранить у вас базовый шаблон страницы следующего вида
``` html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <?php include 'app/views/'.$content_view; ?>
</body>
</html>
```
При помощи `<?php include 'app/views/'.$content_view; ?>` в шаблон будет встроен код вашей HTML верстки.
Последний параметр "$data" -- это массив, который может быть передан в шаблон. С его помощью вы можете динамически передавать данные из своего контроллера в шаблон, например:
`controller_admin.php`
``` php 
$data = [
            'style' => 'style.css',
            'title' => 'Админ панель',
        ];
```

`template_view.php`
``` html 

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title><?php $data['title']; ?></title>
    <link rel="stylesheet" href="<?php $data['style'];?>">
</head>
<body>
    <?php include 'app/views/'.$content_view; ?>
</body>
</html>
```
