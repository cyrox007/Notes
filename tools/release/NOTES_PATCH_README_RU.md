# Исправительный патч Notes 1.2.0-rc.1 — r2, 14 ноября 2026

Патч сохраняет номер версии `1.2.0-rc.1`. Предназначен **только** для исходной сборки GitHub `v1.2.0-rc.1`, коммит `29b0dd959733651fc8e6f326af5c8997f4e337a8`. Другие сборки и частично применённые патчи нельзя заменять вручную.

## Изменения

- «Дефекты»: доработка формы регистрации и просмотра.
- «Журнал нарядов допусков и распоряжений»: отдельная навигация по документам, журналу и справочникам.
- Админка: раздел резервных копий, проверка и восстановление данных.

Последняя функция ещё **не прошла окончательную приёмку на Windows и при аварийном прерывании**. Прежде чем применять патч к рабочему сайту, сделайте **независимую копию MySQL и всех приватных пользовательских файлов**, а также сохраните файлы сайта. Автоматическая защитная копия установщика содержит только изменяемые файлы приложения, **не** заменяет полную резервную копию данных.

## Установка, как в прежних исправительных патчах

1. Завершите активное обновление, остановите фоновые задания и временно исключите изменения сайта пользователями.
2. Распакуйте ZIP **вне** каталога установленного сайта, например в `C:\OSPanel\home\test`.
3. В папке распакованного патча откройте командную строку и выполните **одну команду**:

```bat
php repair.php --yes --root="C:\OSPanel\home\notes.local"
```

На Linux:

```sh
php repair.php --yes --root="/путь/к/Notes"
```

Установщик сам:
- проверяет исходную версию и контрольные суммы каждого изменяемого файла;
- проверяет целостность файлов патча;
- создаёт каталог защитной копии **рядом с установленным сайтом, но вне его** (например, `C:\OSPanel\home\.notes.local-notes-repair-...`);
- сохраняет и проверяет прежние файлы до первой замены;
- заменяет 16 файлов и проверяет результат;
- при штатно обработанной ошибке пытается вернуть прежние файлы.

**Отдельная папка `--backup`, команды `--check` и `--apply` не нужны.** Дополнительная проверка без установки, если необходима: `php repair.php --check --root="C:\OSPanel\home\notes.local"`.

4. Перезапустите PHP в OSPanel (или очистите OPcache) и обновите страницу через Ctrl+F5.
5. Проверьте «Дефекты», ЖНДР и «Админка → Резервные копии». Для последнего раздела полноценную проверку восстановления выполняйте **только на отдельной тестовой копии**, не удаляя рабочие данные.

## Архив и ограничения

В корне ZIP находятся `repair.php`, `manifest.json`, `ИНСТРУКЦИЯ.md` и **16 файлов приложения в штатных каталогах** `app/`, `core/`, `modules/`. Никакой дополнительной обёртки `files/` нет.

Архив не содержит `core/Version.php`, `.env`, SQL-миграций, приватных данных, секретов или установочных настроек. Версия и структура базы данных не изменяются.

**Не копируйте весь архив поверх сайта:** `repair.php` предназначен для запуска из отдельной папки, а установщик дополнительно проверяет исходное состояние и создаёт защитную копию. При обнаружении несовпадения контрольных сумм он не применяет патч.

Новый архив не является подписанным offline-пакетом раздела «Админка → Обновления». Это отдельный исправительный патч для установленной версии.

## Если установка завершилась ошибкой

- Сохраните текст ошибки и путь к автоматически созданной защитной копии, если он появился.
- Не переустанавливайте Notes и не удаляйте его каталог.
- Если автоматический возврат не завершён, восстановите заменённые файлы из автоматически созданной копии по их исходным путям.
- При неожиданном завершении процесса или отключении питания автоматический откат **не гарантирован**. Полная независимая копия сайта и данных необходима.
- Если исходные суммы не совпадают, нужен патч для точного фактического состояния сайта, а не принудительная замена.
