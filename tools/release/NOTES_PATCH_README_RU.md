# Патч Notes 1.2.0-rc.1 — 14 ноября 2026

**Архив изменяет только файлы приложения. Номер версии остаётся прежним.**

Включает:
- улучшение формы «Дефекты»;
- ЖНДР: название, разделение документов, журнала и справочников;
- админку: «Резервные копии», создание, проверка и восстановление данных.

**Важное ограничение:** раздел восстановления данных ещё требует окончательной приёмки на Windows и проверки аварийного прерывания. Не применяйте этот экспериментальный патч к рабочей системе без полной внешней копии базы и вложений.

## Что в архиве

- `files/` — только 16 изменённых файлов приложения;
- `manifest.json` — контрольные суммы исходного и нового состояния каждого файла;
- `apply.php` — установщик с предварительной проверкой и возвратом файлов при ошибке;
- `ИНСТРУКЦИЯ.md` — эта инструкция.

**В архиве нет пользовательских данных, дампа MySQL, `.env`, установки PHP и нового номера версии.**

## Перед установкой

1. Через панель хостинга создайте **независимую резервную копию MySQL и пользовательских файлов** (включая `uploads/` и внешний `PRIVATE_STORAGE_PATH`). Храните её отдельно от сайта.
2. Убедитесь, что приложение сейчас имеет версию `1.2.0-rc.1`, и что это та же исходная сборка, которая использовалась при подготовке патча.
3. Остановите фоновые задания, пользовательские изменения и поставьте сайт в обслуживание штатными средствами хостинга.
4. Распакуйте архив **во внешний временный каталог**, не поверх файлов сайта.
5. Создайте ещё один внешний каталог для резервных копий файлов патча. Он не должен лежать внутри сайта.

## Проверить совместимость без изменений

В каталоге распакованного патча:

```bash
php apply.php --check --target="/абсолютный/путь/к/Notes"
```

Для Windows CMD перед запуском русскоязычного вывода:

```bat
chcp 65001
php apply.php --check --target="C:\путь\к\Notes"
```

Если проверка сообщает, что контрольные суммы не совпали, **ничего не заменяйте вручную**. Возможно, на сервере другая сборка: нужен отдельный патч для её фактических файлов.

## Применить

Только после успешной проверки и сохранения данных:

```bash
php apply.php --apply --target="/абсолютный/путь/к/Notes" --backup="/папка/вне/сайта"
```

В Windows:

```bat
php apply.php --apply --target="C:\путь\к\Notes" --backup="D:\notes-patch-backups"
```

Каталог `--backup` должен **уже существовать** и быть доступным на запись. Установщик создаст в нём отдельную защитную папку с оригинальными файлами.

Установщик выполняет:
1. проверку номера версии и **всех** исходных SHA-256 без изменений;
2. проверку целостности всех файлов самого ZIP;
3. сохранение старых файлов и их повторную проверку;
4. замену файлов и контроль SHA-256 после каждой замены;
5. попытку автоматического возврата прежних файлов, если произошёл сбой.

После успешной замены очистите кеш PHP/OPcache средствами сервера и проверьте «Дефекты», «ЖНДР» и «Админка → Резервные копии». Только затем верните пользователей.

**Установщик не изменяет таблицы SQL, `.env`, файлы пользователей и номер версии.** Резервное копирование через новую админку не заменяет сделанную **до установки** внешнюю копию данных.

## Если появились ошибки

- Не запускайте установщик Notes повторно и не удаляйте существующую систему.
- Сохраните журналы ошибок, название защитной папки, вывод команды и результаты проверки контрольных сумм.
- Если автоматический файловый откат не сработал, восстановите прежние файлы из каталога `--backup/patch-...` с сохранением вложенных путей. Для БД и личных файлов используйте отдельную независимую копию, созданную перед установкой.
