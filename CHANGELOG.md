# История версий Workspace Organizer

Формат основан на принципах Keep a Changelog. Начиная с `1.0.0` проект имеет stable platform contract: совместимость upgrade-path и пользовательских данных является release contract, а изменения схемы выполняются через явные compatibility migrations. Canonical `*_schema.sql` остаются источником текущей схемы fresh install.

## 1.0.15 — 2026-10-09

### Пользователи и сопровождение
- В Admin добавлено редактирование логина, email, ФИО, телефона и отдельная смена пароля управляемого пользователя.
- Блокировка и деактивация получили разные объяснения: блокировка сохраняет место лицензии, деактивация освобождает его без удаления данных.
- Добавлено явное отложенное удаление пользователя: после `RETENTION_ACCOUNT_DELETE_DAYS` регистрационные данные обезличиваются, а техническая tombstone-запись сохраняет целостность общих объектов.
- Простая деактивация больше не является кандидатом на автоматическую очистку по возрасту.
- Существующий retention-контур поддерживает ежедневный cron и ручной запуск просроченной очистки суперадминистратором.
- Добавлен резервный подписанный offline-пакет обновления: один ZIP можно загрузить в Admin, проверить production-подпись и установить тем же транзакционным updater без доступа к feed.

### Messenger
- Первичный список диалогов запрашивается быстрым HTTP snapshot сразу при входе и больше не ждёт WebSocket/Long Poll.
- До подтверждения списка показывается состояние загрузки; ошибка загрузки не маскируется под «Диалогов пока нет», а создание нового чата временно блокируется.
- Добавлен безопасный session-кэш метаданных списка диалогов для мгновенного повторного отображения в пределах вкладки.
- Владелец группового чата может удалить группу целиком; участники получают realtime-событие удаления, а файлы группы очищаются после успешного удаления БД.

- При возврате во вкладку успешное обновление realtime-ticket больше не оставляет Long Poll в паузе.
- WebSocket считается восстановленным только после фактической авторизации; старое неавторизованное соединение не блокирует новое подключение.
- На мобильных экранах действия сообщения свёрнуты в одну кнопку под сообщением и раскрываются под ним, не уменьшая ширину текста.

### Файловый менеджер
- После загрузки файла и создания папки список обновляется сразу без ручного обновления страницы.
- После частичного обновления синхронизируются поиск, сортировка и квота хранилища.
- Переименование и удаление сохраняют текущий маршрут и не требуют полной навигационной перезагрузки.
- Браузерные проверки закрепляют работу File Manager без F5 и под нестандартным `BASE_PATH`.

### Регистрация и приглашения
- На странице регистрации используется настоящий фирменный знак Workspace Organizer.
- Подсказка номера телефона исправлена с `+49` на `+7`.
- Одноразовый код приглашения получил отдельную кнопку «Копировать» с безопасным запасным механизмом для браузеров без Clipboard API.

### Резервные копии БД
- Убраны явные `DESC` из трёх индексов Notes, которые старые phpMyAdmin могли экспортировать с потерей имени колонки.
- Добавлена миграция 1.0.15, пересобирающая эти индексы без изменения пользовательских данных.
- Добавлен `bin/repair_phpmyadmin_dump.php` для исправления уже созданных повреждённых SQL-дампов 1.0.14 без перезаписи исходного файла.

### Безопасность
- Workspace закрыт от поисковой индексации через `robots.txt`, `X-Robots-Tag` и `meta robots`.
- Добавлен ранний защитный контур от типичных внешних scanner-probes к `.env`, `.git`, WordPress/phpMyAdmin/Adminer/PHPUnit и служебным endpoint.
- Добавлена скрытая crawler-ловушка; обращения к ней и повторные probes пишутся в security event log и ограничиваются через `429 Retry-After`.
- IP-адреса сканеров не пишутся в security event log открытым текстом: используется HMAC/хэш-отпечаток клиента.
- Искусственные задержки не используются, чтобы защитный механизм нельзя было превратить в удержание PHP workers.

### Обновление
- Основной проверяемый путь выпуска — `1.0.14 → 1.0.15` штатным подписанным web-updater без повторного bootstrap/handoff.
- Сквозная проверка обязана начинаться с exact опубликованного `v1.0.14`, сохранять пользователя, лицензию, заметку, задачу, файл, private storage, диалог и сообщение Messenger и завершаться на `1.0.15 (10015)`.
- Минимальные требования линии 1.0 не меняются: PHP 8.1+, MySQL 8.0+ или MariaDB 10.5+.

> Переработка палитры тёмной темы намеренно не входит в 1.0.15 и будет принята отдельным решением после дополнительной визуальной оценки.

## 1.0.14 — 2026-10-01

### Бренд и интерфейс
- Workspace Organizer получил единый брендовый слой по утверждённым светлому и тёмному референсам: глубокий синий контур, голубой/синий градиент, фирменный фиолетовый и цветовые роли модулей.
- Старый текстовый бренд `Notes / N` удалён из общего shell и экрана входа; добавлены векторные знак и логотип Workspace Organizer, используемые в навигации и favicon.
- Светлая и тёмная темы используют одну систему токенов, стеклянную верхнюю панель, тёмный фирменный sidebar, более выразительные карточки и единые радиусы/тени.
- Цветовые роли закреплены за разделами: Notes — синий, Tasks — зелёный, Files — оранжевый, Messenger — фиолетовый, Profile — голубой, Admin — бирюзовый.
- Главная страница, авторизация, карточки модулей и основные действия приведены к одному визуальному языку без изменения маршрутов и прав доступа.
- Нижняя информационная строка корректно прижата к нижнему краю короткой страницы без перекрытия содержимого, а аватар публичного профиля приведён к единому стилю рамки.
- Нижняя информационная строка корректно прижимается к нижнему краю короткой страницы, а аватар публичного профиля получил единое с основным профилем оформление рамки.

### Updater и восстановление
- Подтверждённые состояния `rollback_verified` и `committed` больше не ждут истечения 180-секундного web-lease: maintenance завершается сразу, если журнал уже доказал безопасный итог транзакции.
- После автоматического восстановления удаляется устаревший continuation-token, поэтому следующий обычный запрос не попадает в ложное состояние «обновление или восстановление уже выполняется».
- Пофайловая замена и удаление release-owned файлов явно инвалидируют OPcache, чтобы PHP-FPM/shared hosting не выполнял старый байткод после переключения версии или rollback.
- При автоматическом откате сохраняется безопасный диагностический код первичной ошибки, который показывается суперадминистратору без раскрытия путей и секретов.
- Добавлена регрессия для сценария `rollback_verified + активный web-lease`, воспроизводящего эксплуатационный сбой обновления 1.0.12 → 1.0.13.
- Исправлена работа установок без `schema_migrations`: updater инициализирует журнал из подтверждённого baseline исходной опубликованной версии и не запускает заново уже вошедшие в неё исторические миграции.
- Сквозная матрица теперь использует пользователя MySQL без `CREATE ROUTINE`/`ALTER ROUTINE`, чтобы ограничения виртуального хостинга не скрывались root-доступом CI.
- Добавлен сервисный JSONL-журнал updater/recovery/runtime и диагностический пакет поддержки с очисткой секретов и ранней выдачей до schema/maintenance-barrier.
- Суперадминистратор может отправить тот же обезличенный ZIP напрямую в активированный JSInteractive control plane; сервер возвращает `diagnostic_id`, а произвольный внешний адрес для отправки не принимается.

### Совместимость
- Минимальные требования не меняются: PHP 8.1+, MySQL 8.0+ или MariaDB 10.5+.
- Основной публичный путь после снятия 1.0.13 с ленты — `1.0.12/1.0.13 → одноразовый совместимый updater-handoff → штатный подписанный web-updater → 1.0.14`; handoff меняет только updater-контур и не меняет версию приложения или БД.
- При публикации в реестре обновлений `min_source_version_code` для 1.0.14 должен допускать `10012`.

## 1.0.13 — 2026-09-30

### Модули и лицензирование
- Лицензия теперь явно определяет доступный состав модулей по значениям `workspace.*` из подписанного поля `features`. Отсутствующее разрешение не трактуется как полный доступ.
- Модуль без разрешения лицензии сохраняет операторское намерение и данные, но получает фактическое состояние `unlicensed`, не загружает runtime, маршруты и межмодульные возможности.
- Добавлен раздел **Admin → Модули** для включения и отключения разрешённых лицензией модулей.
- Admin объявлен обязательным системным модулем: его нельзя отключить операторским переключателем. Если текущая лицензия не разрешает `workspace.admin`, остаётся независимый core-маршрут восстановления лицензии.
- Отключение модуля является недеструктивным: таблицы, файлы, настройки ролей и политики сохраняются для последующего повторного включения.

### Межмодульная изоляция
- Общая навигация, главная страница, Profile и Messenger используют только фактически загруженные capability.
- При отключении Notes/Tasks/Files соответствующие действия исчезают из Messenger, а их HTTP-маршруты интеграции не регистрируются.
- Profile не показывает публикации, показатели и настройки видимости отключённых Notes/Tasks/Files.
- Настройки File Manager и его ролевые политики скрываются при отключённом модуле без удаления сохранённых значений.
- Глобальные ресурсы Messenger и Admin-зависимые скрипты не загружаются, когда соответствующий модуль отсутствует в активной композиции.

### Обновление и совместимость
- Добавлена совместимая миграция `module_lifecycle.effective_state` с состоянием `unlicensed`.
- Обновлятор учитывает изменение лицензионного состава: если после обновления Messenger больше недоступен, прежний WebSocket-процесс останавливается вместо ошибочного перезапуска и отката всей версии.
- Основной проверяемый путь выпуска: `1.0.12 → 1.0.13` через встроенный подписанный updater.
- Минимальные требования остаются прежними: PHP 8.1+, MySQL 8.0+ или MariaDB 10.5+.

## 1.0.12 — 2026-09-30

### Messenger
- Объединены исправления компактной раскладки Messenger: общий сайдбар снова доступен на промежуточной ширине, действия шапки, сообщений и редактора остаются видимыми без горизонтальной прокрутки.
- Восстановлено понятное отображение активного транспорта: WebSocket показывается зелёным, Long Poll — синим; резервный HTTP-транспорт остаётся полноценным состоянием online.
- Реальные аватары пользователей показываются в списке диалогов, шапке личного чата и выборе контактов.
- Имя и аватар собеседника в личном диалоге открывают его профиль.
- Исправлен публичный профиль пользователя и актуализирован контракт самовосстановления Long Poll.

### Файловый менеджер и общий доступ
- Добавлен раздел «Общий доступ» со всеми созданными публичными ссылками, их состоянием, сроком действия и действиями «Копировать», «Открыть», «Срок» и «Отозвать».
- Публичная ссылка больше не является одноразовым действием интерфейса: её можно найти и отозвать без удаления исходного файла или папки.
- При создании ссылки можно выбрать доступ без срока, на 1 день, 7 дней, 30 дней или до указанной даты.
- Папку можно опубликовать одной ссылкой; публичная навигация ограничена деревом этой папки и не раскрывает соседние объекты хранилища.
- Истёкшие, отозванные ссылки и ссылки на удалённые объекты перестают выдавать содержимое.
- Папка открывается кликом по всей карточке или строке, а не отдельной кнопкой.
- Максимальный размер одного загружаемого файла стал системной настройкой. Admin показывает известный фактический потолок PHP/веб-сервера и предупреждает о конфликте с инструкцией по исправлению `upload_max_filesize`, `post_max_size`, Apache, Nginx или IIS.

### Profile
- Добавлен каталог пользователей с поиском по имени, фамилии и логину и переходом в профиль выбранного пользователя.
- Настройки публикации переименованы в «Видимость профиля» и явно отделены от публичных ссылок File Manager.
- Профиль другого пользователя показывает только те заметки, задачи и файлы, которые владелец разрешил видеть другим пользователям Workspace.

### Проверка и обновление
- Browser E2E проверяет создание ссылки на папку, вложенную навигацию, открытие файла, отзыв ссылки, пользовательский срок и истечение доступа.
- Добавлена миграция системной настройки максимального размера файла.
- Поддерживаемый штатный переход для этого выпуска: `1.0.11 → 1.0.12` через встроенный подписанный updater.
- Минимальная версия PHP остаётся `8.1+`; БД — MySQL `8.0+` или MariaDB `10.5+`.

## 1.0.11 — 2026-09-29

- Сквозной drill проверяет ошибки миграции и post-health, `rollback_verified`, boot recovery и сохранность заметки, задачи, файла, private storage, диалога и сообщения Messenger.

### Profile
- Исправлена регрессия 1.0.9: TOTP-ресурсы больше не перезаписывают собственные CSS/JS Profile.
- Браузерный тест проверяет скрытую форму редактирования и корректную геометрию аватара.

### Messenger
- Исправлена гонка общей realtime-ревизии между HTTP fallback и локальными WebSocket-мутациями.
- WebSocket-маркер остаётся зелёным; активный Long Poll отображается ярко-синим, восстановление — жёлтым, отсутствие связи — красным.
- Long Poll остаётся полноценным состоянием online и не требует доступного WebSocket.

### Файловый менеджер
- Добавлена загрузка VSD, VSDX, DJVU и ZIP с серверной MIME-проверкой.

- Отдельная кнопка с глазком удалена: файл открывается одиночным кликом по самому объекту; изображения, аудио, видео и текст используют встроенный предпросмотр, остальные типы — защищённый маршрут выдачи файла.
- Действия «Поделиться», «Переименовать» и «Удалить» не запускают просмотр; клавиатурное открытие по Enter сохранено.

## 1.0.10 — 2026-09-29

> Релиз отозван. Не использовать в stable-feed; номер не переиспользуется.


### Messenger
- Рабочий Long Poll отображается как обычное состояние «В сети» и не показывает пользователю фоновое подключение или переподключение WebSocket.
- WebSocket продолжает подключаться и восстанавливаться в фоне только как ускоритель; реальная деградация Long Poll по-прежнему отображается отдельно.

### Интерфейс
- Исправлено сворачивание боковой панели: основной layout теперь синхронно переключается на `--ui-sidebar-collapsed`, поэтому между панелью и шапкой/контентом не остаётся пустой полосы.
- Состояние свёрнутой панели корректно восстанавливается из `localStorage` и очищается при переходе в мобильный режим.
- Исправлена геометрия специализированных Messenger-модалок: единую ширину задаёт только базовый `.messenger-dialog-modal`, а внутренние формы занимают `100%`; локальные `width:min(...)` для workspace/group/storage удалены, поэтому модалки больше не смещаются внутри overlay.

### Публикация релиза
- Новые GitHub Release больше не прикладывают устаревший `bootstrap-1.0.2-updater.php` и его checksum.
- Публикуются только основной hosting ZIP, его SHA-256 и source-SHA; автоматические GitHub `Source code (zip/tar.gz)` остаются платформенными ссылками GitHub.

### Совместимость и обновление
- Глобальная кнопка обновления в колокольчике переведена на тот же пошаговый web-updater, что и страница Admin; на shared hosting она больше не пытается выполнить длинное синхронное обновление одним запросом.
- Схема БД и формат пользовательских данных не меняются.
- Минимальная версия PHP остаётся `8.1+`.
- Основной проверяемый путь обновления — `1.0.9 → 1.0.10` через встроенный подписанный updater.

## 1.0.9 — 2026-09-29

### Messenger
- Long Poll стал обязательным базовым транспортом Messenger: текст, файлы и медиа, редактирование и удаление, реакции, пересылка, группы, статусы доставки и прочтения, activity, поиск, архив, закрепление и mute работают без WebSocket.
- WebSocket подключается параллельно только как ускоритель и после успешной авторизации временно заменяет Long Poll; при его недоступности функциональность не урезается.
- Глобальные уведомления и счётчик непрочитанных сохраняются через Long Poll, пока открыта хотя бы одна вкладка Workspace.

### Двухфакторная аутентификация
- При настройке TOTP показывается локально сгенерированный QR-код для `otpauth://`; TOTP-секрет не передаётся во внешние API, CDN или сторонние сервисы.
- Ручной Base32-секрет и URI остаются запасным способом настройки.

### Виртуальный хостинг
- Базовый web-runtime и Messenger не требуют `proc_open`, `exec`, `shell_exec`, `system`, `passthru`, `popen`, `pcntl` или собственного WebSocket-сервера.
- Installer разделяет обязательные требования и необязательные ускорения; при `WS_ENABLED=0` Messenger сразу работает через Long Poll.
- Installer заранее проверяет `ini_get/getenv/putenv`, PHP session/upload temp, файловые блокировки, поддерживаемую версию БД, права `CREATE/ALTER/TRIGGER/DROP`, ограничения загрузки и низкий `memory_limit`; MySQL 5.7 отклоняется до импорта схем, поддерживаются MySQL 8.0+ и MariaDB 10.5+.
- Long Poll освобождает простаивающее PDO-соединение между тиками, чтобы не занимать дефицитный MySQL connection всё время ожидания.
- Локальная доступность `stream_socket_client` больше не трактуется как доказательство разрешённого исходящего TCP/443; updater readiness отдельно показывает сетевые предпосылки, память, PHP timeout и свободное место, а загрузка ZIP, распаковка кандидата и rollback backup имеют ранний disk preflight.
- Profile проверяет число пикселей и запас памяти до GD-декодирования аватара.
- Private storage проходит функциональную пробу `flock` + атомарного `rename`; CI содержит жёсткий hosting-профиль с отключённым `putenv` и отдельную проверку канонических схем на MariaDB 10.11.

### Совместимость и обновление
- Схема БД и формат пользовательских данных в этом patch-релизе не меняются.
- Основной проверяемый путь обновления — `1.0.8 → 1.0.9` через встроенный подписанный updater.

### Установка и восстановление

- Короткоживущая активность чата синхронизируется через общий TTL-контур и доступна обоим транспортам.
- Видимые вкладки координируют владение глобальным realtime-транспортом, чтобы не удерживать лишние PHP workers.

### Двухфакторная аутентификация
- Добавлен стандартный TOTP по RFC 6238 с отдельным зашифрованным секретом каждого пользователя.
- В профиле пользователь может самостоятельно включить 2FA, подтвердить настройку кодом, перевыпустить резервные коды и отключить 2FA с повторным подтверждением.
- В Admin добавлена общесистемная политика: 2FA может оставаться добровольной либо быть обязательной для всех активных аккаунтов.
- При обязательной политике пользователь без TOTP после правильного пароля проходит принудительную настройку до получения обычной сессии; самостоятельно отключить 2FA в этом режиме нельзя.
- Выключение обязательной политики не удаляет персонально настроенные TOTP-секреты.
- Резервные коды показываются один раз, хранятся только как SHA-256-хеши и поглощаются после использования.
- Проверка второго фактора имеет отдельное ограничение частоты попыток и журналируется как событие безопасности.
- Ротация `UNIQUE_KEY` теперь включает TOTP-секреты вместе с заметками: поддерживаются предварительная проверка, пакетная обработка, продолжение после прерывания, повторный проход и rollback.

## 0.10.0-alpha — 2026-09-13

### Security baseline
- Закрыта возможность исполняемых публичных upload-файлов; File Manager переведён на private storage и авторизованную выдачу.

- `CryptMethods` использует `UNIQUE_KEY` и libsodium XChaCha20-Poly1305.

- Legacy AES-CBC чтение Messenger возможно только при явно заданном временном legacy key.
- Silent plaintext fallback для новых зашифрованных данных запрещён.

- Каноническая схема `users / dialogs / user_to_dialogs / messages / messenger_attachments / message_user_deletions`.

- Явные read/delivered cursors и UI статусов отправки/доставки/прочтения.
- Multi-device WebSocket registry: события доставляются всем активным вкладкам/устройствам пользователя.
- Per-user состояния диалогов: pin, mute, archive.
- Private media attachments с MIME allowlist, ACL и Range streaming.
- Групповые роли owner/admin/member, добавление/удаление участников, transfer ownership, rename и private group avatar.
- Media reply-to и cleanup orphan uploads.
- Bounded encrypted search без plaintext message index.
- Голосовые сообщения: MediaRecorder upload, private storage, player, seek и скорости 1x/1.5x/2x.
