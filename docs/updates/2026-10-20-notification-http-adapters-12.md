# Notes 1.2 — подписанный Webhook, Telegram и MAX

## Контракт
Источники событий не знают об API внешнего канала. NotificationService записывает уведомление, учёт получателя и задание; общий обработчик очереди доставляет его через адаптеры, обновляя состояние и журнал попыток.

## Подключение

В админке «Каналы уведомлений» добавлены настройки:
- Webhook: публичный HTTPS-адрес без query-секретов и переменная окружения с ключом HMAC (не менее 32 символов).
- Telegram: ID пользователя Notes, личный chat_id и ссылка на токен бота env:NOTES_TELEGRAM_TOKEN. Бот должен быть добавлен в чат, пользователь должен разрешить Telegram в личных настройках категории. Один общий Telegram-чат не заменяет адресатов пользователей.
- MAX: ID пользователя Notes, личный user_id MAX и ссылка на токен env:NOTES_MAX_TOKEN. Используется официальный адрес https://platform-api2.max.ru/messages с заголовком Authorization; токен не передаётся в параметрах адреса. Получатель должен начать диалог с ботом и разрешить доставку в настройках Notes.

Для проверки нажмите кнопку теста после создания личного адресата для своей учётной записи. Тест через NotificationService и штатную очередь даёт номер задания и код результата. «Принято внешним сервисом» не равнозначно прочтению сообщения получателем. На целевом сайте необходимо проверить фактическое получение.

## Безопасность

Webhook получает только имя события, версию, ID уведомления, категорию и важность. Пользовательские заголовки и текст E2EE не передаются наружу. Подпись считается как HMAC-SHA256 от строки «Unix-время + перевод строки + байты JSON-тела»; получатель проверяет X-Notes-Timestamp, X-Notes-Signature и X-Notes-Delivery-Id, отклоняя запросы старше 5 минут и повторные идентификаторы. Рекомендуется хранить уже обработанные идентификаторы для дедупликации.

HTTPS транспорт проверяет сертификат, публичность DNS-адресов, запрещает внутренние подсети, подмену разрешения DNS и редиректы. Для доставки требуется расширение PHP cURL и доступность публичного DNS. В Windows/OSPanel отдельно проверьте доверенные корневые сертификаты; отключать TLS-проверку нельзя.

Telegram и MAX получают только обезличенный текст «есть новое уведомление». ID чата и токен задаются только в административных настройках; токен хранится во внешнем секрете. Проверка владения личным адресатом пока административная, требуется дополнительная самостоятельная пользовательская процедура привязки для эксплуатации несколькими независимыми пользователями — не считать массовую привязку завершённой.

## Миграция

20261020_notifications_max_channel.sql добавляет независимый флаг max_enabled в notification_subscriptions; Telegram и MAX никогда не используют один и тот же флаг. Перед обновлением действующей установки запустите штатные миграции. Базовая схема новых установок содержит max_enabled, повторное применение миграции не должно создавать дубликат колонки.

## Ограничения

Проведённые контрактные тесты подтверждают запросы к подменным HTTP-приёмникам, формат подписей и обработку ошибок. Для полного закрытия #424 нужны живые токены ботов, реальное получение сообщений, PWA Push, SMS, надёжная самостоятельная привязка пользователей и действия из уведомлений. Не объявлять канал полученным только по коду 200 без проверки адресата.
