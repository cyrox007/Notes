## Реальная копия установки

Из установленной 1.0.16 получены отдельные копии кода, базы и private storage. Исходная установка не менялась. Проверка выполнена на Open Server PHP 8.2.30 и MySQL 8.4:

- исходная база: 36 таблиц; после миграций кандидата: 49;
- количество записей исходных таблиц не уменьшилось;
- 9 258 приватных файлов совпали по SHA-256 (служебные журналы и rate-limit не относятся к пользовательским байтам);
- .env тестовой копии сохранён, pending-миграций после повторной проверки нет;
- healthcheck кандидата: OK;
- восстановление снимка базы и исходного кода: healthcheck 1.0.16 OK, количества записей совпали с исходными.

Результаты и снимки находятся вне web-root: `C:/OSPanel/audit/rc1-real-copy-fixed`. Снимки содержат приватные данные и не входят в релизный пакет или CI-артефакты.

Проверка выявила зависимость исторических checksum от LF/CRLF. Упаковка теперь сохраняет байты SQL из Git; проверка допускает только точные байты и их равномерные варианты LF/CRLF, а содержательные изменения SQL по-прежнему отклоняются. Записи schema_migrations не переписываются.

## GitHub Actions

Полный набор PR прошёл, включая PHP 8.2/8.3, Windows, чистую HTTP-установку, Calendar/Notes в браузере, уведомления, MySQL/MariaDB и пять переходных сценариев:

- успешное обновление с журналом;
- восстановление после SQL-ошибки с фактическим изменением базы;

- прерывание клиента на postcheck.

Сохранность контрольных пользовательских данных и .env/Version.php/доверенных ключей проверяется отдельно. Один запуск SQL-сценария повторён из-за занятого DNS-порта тестового сервера; это инфраструктурный отказ до начала обновления, повтор завершился успешно.

Старый updater 1.0.16 не знает платформенные миграции 1.1: переход требует предварительного моста, после которого версия приложения и данные остаются 1.0.16 до штатной транзакции. Это требование отражено в инструкции обновления.
