# Notes 1.2 — предел памяти для ответов внешних HTTP-каналов

## Исправленная проблема

До исправления обработчики Webhook, Telegram, MAX, SMS и Web Push накапливали весь HTTP-ответ в памяти PHP и только после этого обрезали его либо вообще игнорировали. Если внешний сервис ответит большим телом, воркер может исчерпать память ещё до обработки ошибки.

Теперь оба транспорта используют потоковый приём через `CURLOPT_WRITEFUNCTION` с отдельным счётчиком байтов. Для Webhook, Telegram, MAX и SMS принимается не более 64 КиБ, в результат передаются только первые 4 КиБ. Для Web Push весь ответ ограничен 8 КиБ и не сохраняется. Сверхлимитный ответ прерывается, передача считается неуспешной и подчиняется обычному механизму повторов канала.

Общий HTTPS-транспорт отключает неявные системные прокси, чтобы они не обходили проверку и закрепление публичного DNS-адреса. Проверка сертификата, запрет перенаправлений и внутренних IP сохранены.

## Проверки

```bash
php tests/integration/notification_http_response_limit_12.php
php tests/integration/notification_external_channels_12.php
```

Тест проверяет точные границы размера, отсутствие накопления тела Push, отказ после превышения и фактическое подключение ограниченного обработчика в оба транспорта. Это проверка безопасности кода **без реальной сетевой доставки**. Для завершения №424 и №429 дополнительно необходимы приёмка на реальном SMTP, Web Push и других настроенных каналах с проверкой получения уведомления. Нельзя считать HTTP 2xx подтверждением вручения человеку.
