# Архитектурные границы модулей в 1.1

Дата: 11 октября 2026 года.

## Что изменено

- Добавлен общий адаптер `Core\AeadCipher` для XChaCha20-Poly1305. Messenger сохраняет существующий формат `v2` и совместимость чтения переходного и старого AES-CBC форматов, но больше не вызывает AEAD напрямую.
- Добавлен `Core\PrivateStoragePath`, который объединяет разрешение корня приватного хранилища и проверку принадлежности файлов разрешённым каталогам. Для существующих установок сохраняется поддержка исторического каталога `notes-private-storage`.
- Files, Notes, Messenger и Profile переведены на `Core\Environment`, `Core\ServiceLog` и общий разрешатель приватного хранилища там, где раньше оставались прямые обходы.
- `TaskBoardService` больше не создаёт таблицы во время пользовательского запроса. Схемой общих досок владеет миграция `20260915_shared_task_boards.sql`, уже включённая в манифест миграций.
- Добавлен архитектурный контракт, запрещающий возврат прямых `getenv()`, `error_log()`, runtime-DDL в Tasks и прямого AEAD в Messenger.
- Профиль Core CI теперь запускается для ветки `1.1`, проверяет синтаксис затронутых модулей и новый архитектурный контракт.

## Совместимость

Изменения не меняют структуру БД, формат текущего шифротекста Messenger, URL вложений или публичные контракты модулей. Старые пути File Manager и старые аватары продолжают читаться через совместимый контур.

## Проверка перед слиянием

Слияние в `1.1` допускается только после зелёного CI для PR. В первую очередь должны пройти синтаксические проверки изменённых PHP-файлов, архитектурный контракт Core и существующие профильные проверки Messenger, Notes, Files, Profile и Tasks.
