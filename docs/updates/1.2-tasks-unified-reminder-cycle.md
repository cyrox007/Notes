# Единый фоновый цикл напоминаний Tasks 1.2

## Назначение

Один запуск объединяет четыре этапа: утренние сводки, повторные напоминания личных задач, повторные напоминания командных задач, затем обработку общей очереди внешних уведомлений.

Существующие личные и командные правила не меняются: требуется согласие пользователя; сводка публикуется в 08:00–08:59, повторы — в 09:00–09:59 **местного времени**. Канал доставки выбирается настройками центра уведомлений.

## Настройка планировщика

После применения миграции `20261022_tasks_reminder_cycle_runs.sql` добавьте **одну** периодическую команду вместо раздельного запуска четырёх обработчиков:

```sh
php bin/tasks_reminder_cycle.php --page-size=100 --delivery-limit=20 --json
```

Запускайте каждые 15 минут средствами cron (Linux) либо планировщика заданий (Windows / OSPanel). Команду запускают из корня приложения, используя PHP 8.3 и настроенный файл .env. Не публикуйте служебный скрипт через веб-сервер. Не включайте одновременно отдельные команды `tasks_morning_digest.php`, `tasks_overdue_reminders.php` и `tasks_board_overdue_reminders.php`: они обходят общую блокировку.

Команда использует блокировку MySQL/MariaDB (`GET_LOCK`) с учётом имени базы и префикса таблиц, поэтому параллельный запуск того же приложения вернёт `status=busy` без публикации. Блокировка автоматически освобождается при завершении соединения, в том числе при аварийном завершении PHP. Результаты публикации защищены ранее реализованными уникальными ключами событий.

## Диагностика

Для чтения последнего прохода и итогов доставки за 24 часа без отправки:

```sh
php bin/tasks_reminder_cycle.php --diagnose --json
php bin/notifications_diagnose.php --json
```

В `task_reminder_cycle_runs` сохраняются только даты, итоговые счётчики, состояние и название этапа ошибки. Содержание задач, адреса получателей, секреты и тексты исключений не сохраняются. `status=failed` означает ошибку этапа или безвозвратно не доставленные задания; код завершения — 3. `status=busy` означает, что другой проход ещё работает; код завершения — 0. Статус `running` у старой записи может означать прерывание процесса.

Значение `delivery_sent` отражает подтверждение обработчика отправки, но **не доказывает получение** письма или Push конечным адресатом. Команда не включает каналы доставки автоматически; обязательны настройки и активные подписки.

При сбое одного этапа другие этапы продолжаются, а состояние не маскируется как успешное. Внешние задания очереди продолжают штатные повторы.

## Границы

Автоматическое добавление задания в cron/Windows не выполняется приложением. Длинный цикл не имеет искусственного ограничения длительности; интервалы планировщика могут пересекаться, но блокировка исключает второй одновременный проход. Записи журнала старше 30 дней удаляются небольшими порциями при очередном запуске. Если планировщик не работает, очистка также не выполняется.
