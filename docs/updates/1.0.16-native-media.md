# 1.0.16: native messenger media

## Runtime contract

The implementation adds no third-party JavaScript/PHP library, SDK, SaaS, external signaling, STUN or TURN service. Camera, recording, audio decoding, WebRTC and on-device speech recognition use browser APIs. The existing Notes HTTP session, CSRF middleware, membership ACL, private storage and media database remain authoritative.

## Calls

One-to-one audio/video calls use `RTCPeerConnection({iceServers: []})`. Signaling stays on this Notes installation through authenticated `/messenger/calls` routes. Offers/answers are bounded, private, checked against current active dialog members, and stored under external private storage with a lock and atomic replacement. No audio/video recording is stored by the calls service.

Busy participants, rejection, hangup, late answers, another tab accepting first, a 45-second ringing timeout, expired heartbeats, two ICE restart attempts and media-track cleanup are handled. SDP state is removed shortly after a call finishes; no credentials or SDP enter application error responses.

Direct connections cannot cover every NAT/firewall combination. Without a relay, incompatible networks show a connection failure. Group calls, a self-built relay and a self-built universal recognition engine are not supplied by this change.

## Recorded messages

Video recording uses browser-supported WebM/MP4 formats, the recorder's actual MIME, conservative bitrate/resolution, a 60-second limit, an 8 MiB recording ceiling, preview and local download. Upload/confirmation failures retain the blob and uploaded attachment for a manual retry.

Voice recording likewise retains failed submissions, uses actual MIME for the extension, rejects overlapping permission/recording attempts and waits for HTTP confirmation. `/messenger/recorded/{uid}/send` validates membership and original uploader; retrying an already-sent attachment acknowledges it without creating another message. The existing media transaction still serializes concurrent send attempts.

## Transcription

Voice messages and note voice attachments receive a local transcription panel with Russian/English selection, editable text and an explicit action to insert the result into the note or message draft. Nothing is sent automatically.

Recognition is forced to `processLocally=true`; browser availability is checked before reading audio. No remote fallback, microphone workaround, automatic model download or external URL is allowed. Recorded audio is decoded into a local MediaStreamTrack and passed to the browser engine.

This is capability-dependent: the browser must support on-device recognition, the selected language must already be available, and audio-track recognition must work. It does not bundle an owned speech model and does not claim universal Russian recognition. Accuracy on real Russian speech and browser/model coverage remain unverified; unsupported browsers show a clear explanation.

## Validation

- PHP contracts cover call membership/privacy, busy state, caller/callee roles, restart, multiple tabs, rejection, terminal states and expiry.
- Media contract covers confirmed voice/video send, same-attachment retry and uploader/non-member denial with a real isolated database transaction.
- Browser test establishes real two-peer direct audio and video connections using synthetic local devices, receives remote tracks/video frames, mutes audio and verifies all tracks end on hangup.
- Browser test records real voice/video, simulates a confirmation outage and retries without a second upload.
- Local transcription adapter is tested with a deterministic on-device engine substitute and real audio decode/track routing. This validates privacy and event flow, not model accuracy.
- No external HTTP requests are permitted by the browser regression.

The automated evidence is local-peer evidence. Real-device interoperability and calls between separate networks remain release acceptance checks. Version publication/signing remain separate from this implementation.
