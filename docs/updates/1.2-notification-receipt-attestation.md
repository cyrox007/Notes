# Ручное подтверждение получения уведомления

Новая функция **не утверждает**, что внешний канал гарантированно доставил сообщение. Она позволяет администратору зафиксировать результат личной проверки контролируемого почтового ящика или устройства.

В разделе **Администрирование → Каналы уведомлений** укажите номер задания, отметьте «Сообщение найдено» либо «Сообщение не найдено» и подтвердите операцию текущим паролем администратора. Доступ ограничен разрешением на управление настройками, проверяется CSRF. Операция журналируется с номером задания и результатом; адреса, секреты и содержание сообщений не сохраняются.

Перед отметкой «получено» система требует успешное состояние штатной очереди (`sent`). Это дополнительное ограничение безопасности; оно не заменяет личную проверку.

После миграции `20261023_notification_receipt_attestations.sql` отчёт:

```bash
php bin/notifications_acceptance_report.php --job-id=123 --json
```

покажет `recipient_receipt_status` (`not_verified`, `received`, `not_received`) и дату отметки оператора. `recipient_receipt_verified=true` означает **ручное свидетельство администратора**, а не ответ SMTP, Push или подтверждение прочтения самим получателем. Повторное указание результата заменяет прежнюю отметку с фиксацией очередного действия в журнале действий администратора.

Миграция применяется штатным обновлятором перед открытием административной страницы. Ни один тест GitHub Actions не отправляет реальные письма и не изменяет настройки на установленном сервере.
