# 1.2 — SMS через локальный Headwind GSM

На одном Windows-сервере с Workspace используется COM-драйвер Headwind GSM из
предоставленного референса `sms_gateway/hsms`. Внешний HTTP/HTTPS-шлюз и его
API-ключ для этой схемы не нужны. Старые скрипты, установщики и файлы регистрации
из архива в приложение не копируются.

## Настройка

1. Установите Headwind GSM на сервер Workspace и настройте модем и SIM-карту
   средствами самого Headwind GSM.
2. Включите расширение `com_dotnet` в PHP, который обслуживает сайт, а также в PHP
   обработчика очереди, если он запускается отдельно. После изменения PHP
   перезапустите соответствующий процесс. См. [установку PHP COM](https://www.php.net/manual/en/com.installation.php).
3. Проверьте регистрацию `HeadwindGSM.SMSDriver` и `HeadwindGSM.SMSMessage`,
   совместимость разрядности и права учётной записи службы веб-сервера/очереди.
   Работа Headwind из интерактивного рабочего стола ещё не подтверждает доступ
   к COM и модему из службы. Для проверки не требуется запускать Workspace
   с правами администратора.
4. В «Админ → Каналы уведомлений → SMS через Headwind GSM» укажите ID активного
   пользователя Workspace и его телефон E.164, например `+79990000000`.
   Сохранение требует пароль администратора и CSRF. URL и API-секрет не запрашиваются.
5. Для своего адресата нажмите «Пробная SMS на мой номер» и проверьте исходящие
   Headwind GSM и фактическое получение на телефоне. Эта кнопка отправляет SMS.

Страница показывает только доступность Windows/PHP COM, не запускает драйвер и
не отправляет SMS при открытии. Окончательную доступность драйвера, SIM-карты и
модема подтверждает пробная доставка. На Linux остальные каналы продолжают работать,
а локальный Headwind сообщает о необходимости Windows.

## Отправка и результаты

Общая очередь создаёт `HeadwindGSM.SMSDriver`, проверяет `StatusStr` и вызывает
`Connect()` только при `disconnected`. При `ready` создаётся `HeadwindGSM.SMSMessage`:
поле `To` получает номер без начального `+`, `Body` — текст уведомления в UTF-8,
`Flags` — 0; затем вызывается `Send()`. COM-объекты создаются с `CP_UTF8`, согласно
[контракту PHP COM](https://www.php.net/manual/en/com.construct.php).

- `sms_headwind_accepted`: драйвер принял SMS в исходящие, доставка на телефон не подтверждена.
- `sms_headwind_not_ready`: модем занят, настраивается или не готов; общая очередь повторяет попытку.
- `sms_headwind_unavailable` / `sms_headwind_driver_unavailable`: исправьте окружение,
  регистрацию COM или права учётной записи, затем повторите доставку.
- `sms_headwind_prepare_failed`: ошибка до вызова `Send()`; допускается повтор.
- `sms_headwind_send_unknown`: ошибка во время `Send()`. Автоматический повтор
  остановлен, потому что SMS уже могла попасть в исходящие. Перед ручным повтором
  проверьте Headwind GSM. Аварийное завершение процесса после принятия драйвером
  также не позволяет гарантировать отправку ровно один раз: COM API референса
  не предоставляет ключ дедупликации.

SMS содержит обезличенный сигнал, а для подтверждения задачи — её временную ссылку.
Тексты личной переписки и защищённых объектов в SMS не передаются. Сохраняются
личный адресат, подписки по категориям, очередь и журнал попыток. Сообщения исключений
COM с потенциально чувствительными данными в историю не записываются.

## Совместимость и проверка

Миграция БД не нужна. Сохранение SMS через новую форму меняет существующую настройку
пользователя на Headwind и убирает прежнюю ссылку на API-секрет. Старые конфигурации
с HTTPS URL продолжают работать прежним адаптером до явного пересохранения.

`notification_sms_gateway_12.php` проверяет сценарии COM на подставном драйвере,
переход disconnected → ready, неготовый модем, ошибки регистрации и Send, отсутствие
HTTP/секретов, приватность, сохранение в изолированной SQLite и совместимость старого
HTTPS-канала. Контракт включён в Linux и Windows CI. Браузерная проверка проверяет
форму и допустимость международного номера без отправки.

Реальная отправка с физическим модемом автоматическими проверками не подтверждается.
