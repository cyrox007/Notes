# Notes 1.2 — настройка SMTP и диагностика внешних уведомлений

## Проблема

Наличие очереди и адаптера SMTP не означает, что администратор может отправить письмо на настоящем сервере. Ранее у администратора не было полной настройки и проверки доставки.

## Настройка

1. Задайте пароль в окружении PHP под именем NOTES_SMTP_PASSWORD (например, в закрытом .env). Не добавляйте секрет в Git.
2. Откройте Админка → Каналы уведомлений. Укажите хост, порт, режим TLS, имя пользователя, отправителя и ссылку на секрет env:NOTES_SMTP_PASSWORD. Сам пароль в интерфейс не вводится.
3. Подтвердите сохранение текущим паролем администратора. Для обычной доставки пользователь должен разрешить E-mail для соответствующей категории.
4. Нажмите «Отправить пробное письмо». Будет создано семантическое событие notifications.smtp_test, запись встроенного уведомления и задание штатной очереди. Включается только диагностическая подписка текущего администратора. Ограничение — один раз в минуту.
5. Страница показывает номер задания, состояние и код результата. Резервный шаг очереди пробует выполнить одно задание, но при наличии backlog тестовое может остаться pending.
6. Основной планировщик: php bin/notifications_worker.php --limit=20 --json по cron или планировщику Windows. Без него доставку гарантировать нельзя. HTTP fallback ограничен частотой и пакетом.

## Как интерпретировать статус

- pending: ожидает очереди.
- processing: в работе.
- retry: временная ошибка, будет повторено.
- failed: попытки исчерпаны или ошибка постоянная.
- sent: SMTP-сервер принял письмо. Это не доказательство фактического получения в почтовом ящике.

При отказе проверьте notification_delivery_attempts, last_result_code, окружение PHP-FPM/CLI и доступность SMTP/TLS/DNS, не выводя секреты в журнал. При sent проверьте спам и почтового провайдера.

## Безопасность и границы

Сохранение требует admin.settings.manage, CSRF и текущего пароля. Тест требует той же роли и CSRF, выполняется только для E-mail текущего администратора с ограничением частоты. Пользовательские подписки остальных категорий не меняются.

CI тестирует программные контракты и работу очереди с эмулятором почты. Для закрытия #429 требуется фактическое письмо, принятое SMTP-сервером на установленном сайте, подтверждение в почтовом ящике и журнал результата. Telegram, MAX, Web Push, Webhook и SMS — следующие адаптеры общей очереди (#424); они пока не объявляются готовыми.
