# Tasks 1.2 — ручной порядок дневной очереди

Дата: 19 октября 2026 года.

## Назначение

На страницах «Сегодня» и «Завтра» задачи можно перемещать вверх и вниз.
Это именно личная очередь: общие доски и чужие задачи не затрагиваются.

## Реализация

Данные порядка принадлежат модулю Tasks:

- `task_personal_day_queues`: версия очереди для пары пользователь/день.
- `task_personal_day_positions`: позиции задач внутри соответствующего дня.
- `TaskDayOrderService`: одна транзакция для сохранения порядка и квитанции
  изменяющей команды через платформенный `MutationCommandStore`.

Перестановка не увеличивает `tasks.version`. Это важно: изменение порядка
не конфликтует с одновременным изменением названия задачи из другой вкладки.
Однако два изменения самого порядка с одной исходной версией несовместимы —
устаревший запрос получает HTTP 409 и должен обновить представление.

Прежняя сортировка по сроку применяется до первого пользовательского
перемещения. Новые задачи без сохранённой позиции отображаются после
ранее расставленных задач, в порядке срока и идентификатора.

Сервис проверяет владельца, день, архив, мягкое удаление и рабочее
состояние задачи непосредственно в транзакции. Не допускается
перенос задачи в чужую очередь или другой день.

## Сценарии отказа

- Повтор `command_id` после потери ответа возвращает предыдущий результат.
- Другой запрос с тем же `command_id`, но изменённым содержимым отклоняется.
- Несовпадение `expected_version` возвращает конфликт 409 без перезаписи.
- Перемещение на краю списка ничего не меняет и не увеличивает версию.
- Для защитного ограничения операция доступна, пока в одном дне не более
  500 незавершённых задач. Выход за границу возвращает понятную ошибку,
  а не частичное сохранение.
- Кнопки остаются доступными с клавиатуры, запрос выполняется без полной
  перезагрузки; при переходе через страницу пагинации представление
  согласовывается с сервером.

Сроки `tasks.due_date` по-прежнему интерпретируются в зоне текущей
установки; индивидуальный часовой пояс и его миграция относятся к
следующему самостоятельному контракту 1.2.

## Проверка и установка

Новая каноническая схема — `database/tasks_schema.sql`, обновление
установленных систем — неизменяемая миграция
`database/migrations/20261019_tasks_personal_day_order.sql`.
Обе таблицы объявлены в `modules/tasks/module.json`.

`php tests/integration/data_integrity_12_contract.php` запускает
сценарии `task_day_order_12_scenarios.php` на MySQL 8.4 как без
префикса, так и с ним. Проверяются повтор команды, конфликт, сохранённый
порядок, разные дни и отсутствие побочных изменений версий задач.
