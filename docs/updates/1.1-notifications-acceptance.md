# 1.1 — Приёмочный барьер уведомлений

## Что изменено

Обязательные проверки общего слоя уведомлений 1.1.0 собраны в одном CI-сценарии `Уведомления 1.1 — MySQL`.

Теперь один барьер проверяет:

- базовый контракт `NotificationService` и идемпотентность событий;
- очередь доставки, повторные попытки, окончательное состояние `failed` и запрет доставки отключённому получателю;
- реальную MySQL-схему уведомлений и задания внешней доставки;
- SMTP и безопасное разрешение получателя;
- встроенный центр уведомлений и состояние внешней доставки;
- пользовательские подписки;
- ограниченный HTTP catch-up для shared hosting;
- CLI worker;
- интеграцию Calendar через общий `NotificationService`;
- одиночные и повторяющиеся напоминания Calendar;
- восстановление пропущенных напоминаний после простоя без дублей.

Изменения в механизме напоминаний Calendar и его миграциях теперь также запускают этот сценарий, поэтому связь Calendar с общим слоем уведомлений больше не проверяется только отдельным workflow модуля.

## Что не изменено

- визуальный стиль интерфейса не менялся;
- API центра уведомлений не менялся;
- схема БД и существующие миграции не менялись;
- SMTP, очередь и HTTP fallback не переписывались: текущая реализация используется как есть и проходит единый набор приёмочных проверок.

## Ограничение релизной готовности

Функциональный приёмочный барьер #233 не заменяет нагрузочную проверку. Критерий для 1000 одновременно активных пользователей остаётся частью отдельной задачи производительности #274 и по решению владельца проекта перенесён на 1.2.0; он не блокирует стабильную 1.1.0.
