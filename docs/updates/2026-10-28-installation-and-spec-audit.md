# Проверка перехода с 1.1 и соответствия новых модулей ТЗ

Дата проверки: 28 октября 2026 года. Исходники: локальная сборка на основе
`4f1c2bad` с исправлением чистой схемы, описанным ниже. Среда: Windows,
Open Server, PHP 8.3, MySQL 8.4. Проверка не является нагрузочной приёмкой.

**Вывод:** миграции, замена файлов и сохранение новых модулей на испытательных
копиях подтверждены. Найден и исправлен блокирующий дефект чистой установки.
Полного соответствия документовым требованиям нет. Публиковать это как полностью
готовую 1.2 и обещать штатное обновление из существующего канала пока нельзя.

## Что именно проверено

Основная локальная установка содержит код 1.1.0, но использует общую с dev
базу, уже мигрированную до 1.2. Поэтому выполнены два разных испытания:

| Испытание | Результат |
|---|---|
| Импорт схем локального кода 1.1, без префикса и журнала миграций | Применены 33 миграции 1.2; повтор ничего не применяет; тестовый пользователь сохранён |
| Импорт схем 1.1 с `qa_` и журналом из 36 исторических миграций | Применены те же 33 миграции; посторонняя таблица без префикса сохранена; повтор безопасен |
| Чистая схема 1.2 без префикса | После исправления готовы все 99 принадлежащих пакету таблиц и 9 модулей |
| Чистая схема 1.2 с `qa_` | Тот же результат в отдельном пространстве имён |
| Копия текущей общей БД и копия файлов основной 1.1 | Штатные `UpdateBackupManager` и `UpdateLiveApplier` выполнили резервирование и пофайловую замену; `.env` сохранён |

| Пользовательские файлы в отдельном private storage | Дополнительно восстановлена копия кода 1.1 и повторена замена на тестовую 1.2; SHA-256 всех 5 скопированных пользовательских файлов не изменились, .env сохранился |
| Файлы после замены | Проверены все 798 файлов тестового пакета: отсутствующих и отличающихся нет |
| Новые модули после замены | Все 17 файлов defects и 29 файлов work-permits присутствуют и совпадают с пакетом |
| Настройка префикса в браузерном установщике | Полный мастер пройден с `web_` в БД, уже содержащей таблицы без префикса; неверный префикс отклонён, DBPREFIX записан в .env, установщик после завершения закрыт |

| Первый HTTP-запуск новой установки | После мастера корневая страница возвращает HTTP 200; PHP 8.2 получает раннее понятное сообщение о необходимости 8.3 |

| PDF | Генерация, Unicode, извлечение текста и отрисовка проверены; лицевая страница печатного макета осмотрена |

Рабочие установки не обновлялись и их таблицы не изменялись. Все записи,
импорт, миграции и переключение кода выполнялись в отдельных тестовых каталогах
и БД. Контроль `.env` основной установки подтвердил отсутствие изменения файла.
Испытательные ключи доступа к БД и дамп находятся вне веб-каталогов и репозитория.
Прохождение 20 контрактов подтверждает реализованные сценарии, но не заменяет
сверку с ТЗ: отсутствующие функции этими тестами не становятся реализованными.

Для испытания механизма замены использовалась **локальная тестовая идентичность
1.2.0/12000**, заданная только в отдельном пакете. Это не опубликованный релиз.
Проверка не включала загрузку production feed, production-подпись и полную
браузерную транзакцию обновления через админку. Поэтому она подтверждает
миграции и локальный механизм замены, но не обещает успешность любого будущего релиза.

## Исправления по результатам проверки

1. `notification_action_tokens` была обязательной по контракту пакета, но
   отсутствовала в `database/notifications_schema.sql`. Чистая установка
   получала `SchemaReadiness.ready=false`, хотя новые модули уже присутствовали.
   Добавлена актуальная таблица из существующей миграции; сама миграция и её
   checksum не менялись. Повторные установки на двух новых БД прошли.
2. Добавлены отдельный исполняемый контракт чистой установки и CI с двумя
   вариантами DBPREFIX. Старый workflow `installer-upgrade.yml` не проверяет
   ветку 1.2, что позволяло такой ошибке оставаться незамеченной.
3. В сборке hosting ZIP теперь явно проверяются manifests, runtime и схемы
   обоих новых модулей, а не только Messenger.
4. PDF-контракт больше не требует слитного текстового фрагмента «кабельный
   отсек» через границу строк ячейки. На отрисованной странице оба слова
   присутствуют; проверяются оба слова. Производственный PDF-рендерер не менялся.
5. Ранняя проверка install.php приведена к минимуму PHP 8.3 линии 1.2:
   она больше не предлагает PHP 8.2 перед загрузкой исходников с синтаксисом 8.3.

## Условия настоящего обновления

- В проверенном рабочем дереве `core/Version.php` всё ещё объявляет 1.1.0/11000.
  `release_12_source_preflight.php` блокирует релиз: идентичность версии,
  README, changelog и release notes ещё не оформлены как выпуск 1.2.
- До публикации нужен пакет с настоящими согласованными 1.2.0/12000,
  manifest и подписью, минимальным источником 11000 и минимумом PHP 8.3.
- PHP веб-сервера и исполнителя обновления должен быть совместим с 1.2.
  Наличие работавшей 1.1 на PHP 8.2 не подтверждает этого условия.
- При необходимости подготовки обновлятора 1.1 должна быть отдельно проверена
  доставка подготовительного патча через согласованный пользовательский путь.
- Наличие модуля в ZIP и БД не означает автоматическое появление его пункта
  меню: для новых модулей необходимы разрешение лицензии, включение и RBAC.
  `default_enabled=false` не удаляет модуль и его данные. Миграции состава
  пакета выполняются независимо от его текущего включения.

## Дополнительный образец бланка

После начала проверки предоставлен файл
`Болдыревка_В_10_Т_1,_контроль_РЗА,_АУВ (2).docx`.
Разобраны 139 текстовых абзацев и 7 таблиц. Образец включён в сверку,
отсутствие приложения больше не считается причиной отложить эту часть анализа.

- В образце номер `1013 / 076688`: текущий документ использует числовой ID,
  не имеет отдельного редактируемого печатного номера такого формата.
- Образец содержит стандартные последовательные разделы: реквизиты, мероприятия,
  выдача/продление, инструктаж выдающего, разрешение на подготовку/допуск,
  оставшееся напряжение, первичный инструктаж, ежедневные допуски,
  инструктаж руководителя/производителя, изменения бригады и завершение.
  Эти сведения в значительной части хранятся модулем, но текущий renderForm
  размещает их в собственной системе таблиц с заголовком и пояснением
  «ПЕЧАТНЫЙ МАКЕТ». Это не подтверждение воспроизведения предоставленного бланка.
- В образце фраза «Оборудование и токоведущие части, оставшиеся в работе под
  напряжением» помещена в колонку ограждения. В форме приложения она является
  значением по умолчанию другого поля — remaining_live. Для isolated_parts
  требуется отдельный ввод. Нужна явная сверка назначения этих полей с образцом.
- В образце плановые начало и окончание совпадают: 28.09.26 17:00.
  Приложение требует положительный интервал. Перед воспроизведением этого
  конкретного заполнения следует уточнить время, а не автоматически ослаблять проверку.
- Проверка была содержательной и структурной; оригинальный DOCX не рендерился
  в Word/LibreOffice, поэтому попиксельное совпадение страниц не заявляется.
