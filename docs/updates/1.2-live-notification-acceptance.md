# Приёмка реальной доставки уведомлений Notes 1.2

Настоящая доставка проверяется **на установленном экземпляре приложения**, только с адресом или устройством, которым управляет оператор. Зелёные проверки GitHub Actions не доказывают получение сообщения человеком.

1. Обновите Notes до версии с отчётом и примените миграции. Убедитесь, что расписание работает: в админке откройте «Каналы уведомлений» и проверьте последний фоновый проход.
2. Выберите контролируемую учётную запись с разрешённой категорией уведомлений и настроенным каналом. Не используйте учётную запись постороннего человека.
3. Создайте пробное уведомление на странице «Каналы уведомлений» штатной кнопкой. Запомните номер задания из ответа интерфейса.
4. Дождитесь штатного запуска фонового обработчика; не запускайте старые отдельные обработчики параллельно с единым циклом.
5. На сервере выполните команду только для чтения:

```sh
php bin/notifications_acceptance_report.php --job-id=НОМЕР --json
```

6. Сравните состояние очереди, историю попыток, диагностический код и время принятия внешним каналом. Затем **отдельно** проверьте наличие сообщения в почтовом ящике или на контролируемом устройстве.
7. Зафиксируйте дату испытания, используемый канал, номер задания, итоговый код, наличие сообщения у адресата и обнаруженные проблемы в защищённом журнале оператора. Не сохраняйте пароли, секреты, почтовые адреса и текст личных сообщений в общедоступных отчётах.

Поле `transport_accepted=true` означает, что внешний адаптер сообщил об успешной передаче. Поле `recipient_receipt_verified=false` остаётся ложным во всех автоматических отчётах, поскольку наличие сообщения на устройстве требует отдельной проверки. Ни эта команда, ни просмотр административной страницы не отправляют сообщений.

При `retry` требуется дождаться следующей попытки и повторить чтение. Если `processing` сохраняется после потери процесса, проверяйте истечение аренды и состояние следующего фонового прохода. Возможна физическая повторная отправка после потери подтверждения от провайдера.

**Текущее состояние приёмки:** автоматический код и контрольное испытание тестовой БД предусмотрены. Проверка реального SMTP/Push на целевом сервере и подтверждение получателем не выполнялись: для этого необходимы доступ к установленному экземпляру и контролируемый адресат.
