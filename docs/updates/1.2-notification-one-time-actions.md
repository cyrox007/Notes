# Notes 1.2 — одноразовое подтверждение внешних действий

## Реализованный фундамент

`NotificationActionTokenStore` выдаёт криптографически случайный токен для конкретного пользователя, уведомления и действия `complete_task`. Срок действия — 15 минут. В БД хранится только SHA-256, исходное значение возвращается выдающему серверному компоненту единственный раз. Погашение выполняется атомарно через `Core\DatabaseManager`: конкурирующие запросы не могут использовать один токен дважды.

Новый маршрут `POST /tasks/notification/{notificationId}/confirm` требует авторизованной сессии, права использования Tasks и действительного CSRF-токена, затем проверяет и погашает одноразовый токен из поля `action_token` и вызывает существующий `TaskNotificationActionService`. Открытие GET-ссылки ничего не меняет. При истечении или повторном предъявлении возвращается 409.

## Важно: ограничения

На этом этапе **ссылки с токенами ещё не включены во внешние отправления** SMTP, Push, Telegram, MAX, Webhook и SMS. Хранилище и защищённый маршрут готовы для следующей задачи: добавить отдельную страницу предпросмотра и подтверждения в авторизованной сессии, а затем безопасную выдачу ссылок в выбранных каналах, не раскрывая тексты задач и личные данные. Успешная отправка сообщения внешним сервисом не означает фактического получения.

Если операция завершения задачи не удалась после погашения, токен остаётся использованным (безопасное поведение против повторов). Пользователь может завершить задачу обычной кнопкой в Notes. Для установки новой таблицы обязательна миграция `20261021_notification_action_tokens.sql`, зарегистрированная в `database/migrations/manifest.json`.
