# Notes 1.2 — одноразовое подтверждение внешних действий

## Реализованный фундамент

`NotificationActionTokenStore` выдаёт криптографически случайный токен для конкретного пользователя, уведомления и действия `complete_task`. Срок действия — 15 минут. В БД хранится только SHA-256, исходное значение возвращается выдающему серверному компоненту единственный раз. Погашение выполняется атомарно через `Core\DatabaseManager`: конкурирующие запросы не могут использовать один токен дважды.

Новый маршрут `POST /tasks/notification/{notificationId}/confirm` требует авторизованной сессии, права использования Tasks и действительного CSRF-токена, затем проверяет и погашает одноразовый токен из поля `action_token` и вызывает существующий `TaskNotificationActionService`. Открытие GET-ссылки ничего не меняет. При истечении или повторном предъявлении возвращается 409.

## Важно: ограничения

На этом этапе **ссылки с токенами ещё не включены во внешние отправления** SMTP, Push, Telegram, MAX, Webhook и SMS. Хранилище и защищённый маршрут готовы для следующей задачи: добавить отдельную страницу предпросмотра и подтверждения в авторизованной сессии, а затем безопасную выдачу ссылок в выбранных каналах, не раскрывая тексты задач и личные данные. Успешная отправка сообщения внешним сервисом не означает фактического получения.

Если операция завершения задачи не удалась после погашения, токен остаётся использованным (безопасное поведение против повторов). Пользователь может завершить задачу обычной кнопкой в Notes. Для установки новой таблицы обязательна миграция `20261021_notification_action_tokens.sql`, зарегистрированная в `database/migrations/manifest.json`.

## Экран подтверждения

Добавлен маршрут `GET /tasks/notification/{notificationId}/preview` для авторизованного получателя. Ссылка должна формироваться как `/tasks/notification/123/preview#token=<одноразовый_секрет>`: фрагмент после символа `#` не отправляется серверу вместе с GET. Скрипт удаляет фрагмент из адресной строки через `history.replaceState`, проверяет разрешение через защищённый `POST /tasks/notification/123/inspect` и только после успешной проверки разрешает кнопку «Подтвердить выполнение».

Нажатие кнопки отправляет `POST /tasks/notification/123/confirm` с токеном и CSRF. Сторонний просмотрщик ссылок, сканер почты и открытие страницы пользователем не изменяют задачу. При отказе от подтверждения ссылка остаётся неизрасходованной до окончания срока действия. Вся страница работает через представление Tasks, без самостоятельных запросов к БД из интерфейса.

**Следующий этап:** выдача ссылки сервером в зависимости от канала доставки (SMTP, Web Push, Telegram, MAX, Webhook и SMS), тестирование реального получения. В текущем изменении внешняя публикация токенов ещё не включена.

## Выдача ссылок через внешние каналы

Обработчик выдаёт персональную ссылку подтверждения только в момент отправки уведомления Tasks с корректным идентификатором задачи. Токен хранится только в виде хеша; в общей очереди и журнале доставки его нет. Ссылка ведёт на защищённый экран предпросмотра; само открытие задачи не завершает.

SMTP получает ссылку в текстовом и HTML-письме, Telegram и MAX — в сообщении, SMS — в тексте для шлюза, Web Push — в зашифрованном пути открытия. Общий подписанный Webhook одноразовый токен не получает. Для выдачи внешней ссылки адрес SITEURL должен быть абсолютным HTTPS-адресом без учётных данных и параметров запроса.

Срок действия токена — 15 минут от выдачи. На каждую повторную попытку доставки может формироваться новый токен. Приём сообщения внешним сервисом не доказывает, что оно показано пользователю; для завершения задачи требуются авторизованная сессия, CSRF и явное подтверждение.

## Очистка и испытания повторных отправок

При каждом запуске `php bin/notifications_worker.php` отдельным ограниченным запросом удаляется не более 100 токенов, срок действия которых истёк. Очистка использует `Core\DatabaseManager`, не удаляет ещё действующие разрешения и не блокирует всю очередь. В текстовый и JSON-отчёт обработчика добавлен счётчик `expired_action_tokens_removed` без самих секретов. Для более быстрого удаления накопленных записей можно повторить запуск штатного обработчика; массовое удаление без ограничений не используется.

Профильный тест `php tests/integration/notification_action_tokens_mysql_12.php` проверяет реальную MySQL 8.4: независимые токены при повторных отправках, принадлежность учётной записи, единственность погашения, отклонение просроченных токенов и ограниченную очистку. Тест работает только на базе, в названии которой есть `test`, и не отправляет сообщения внешним провайдерам.

До закрытия задачи необходима приёмка фактического получения ссылок на реальном Android-устройстве и в настроенных почтовом ящике/мессенджерах; автоматические испытания проверяют сервер, но не факт вручения.
