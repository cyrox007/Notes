# Notes 1.2 — автономный модуль «Дефекты»

Статус: рабочая первая версия; до окончательной приёмки по полному ТЗ остаются отдельные задачи.

## Подключение

Пакет зарегистрирован как `modules/defects`. Ядро загружает его только при наличии лицензии с возможностью `workspace.defects` и включённого состояния модуля. По умолчанию новый модуль отключён: обновление не открывает доступ к непроверенной функциональности автоматически.

Установка и включение выполняются существующим управлением модулями в административной панели либо штатными командами `bin/control.php`. Для установки и обновления применяются каноническая схема `database/defects_schema.sql` и миграция `20261019_defects_foundation.sql`.

## Реализованные операции

- Справочники участков/РЭС, категорий объектов, объектов и ответственных служб.
- Регистрация дефектов с описанием, приоритетом, датой обнаружения, ФИО регистрирующего и несколькими ответственными службами.
- Плановый срок устранения по утверждённой политике 1/7/14/30 дней; дата сохраняется отдельно.
- Постраничный реестр, карточка со службами и закрытие с описанием выполненных работ.
- Версии карточек, защита от повторных команд и атомарность записи связей.
- Начальный экран «Дефекты» с действиями без перезагрузки страницы.

Все SQL-запросы выполняются через `Core\DatabaseManager`. Маршруты принадлежат `Core\Router`, входные данные — `Core\Request`, ответы — `Core\Controller`. Доступ управляется правами `defects.use` и `defects.manage`. Запись событий проходит через `Core\UserActionLog`.

## Проверки

```bash
php tests/integration/defects_priority_policy_12.php
php tests/integration/defects_reference_boundary_12.php
php tests/integration/defects_registration_12.php
php tests/integration/defects_module_runtime_12.php
```

Испытания SQLite проверяют предметные операции и откат. До окончательной приёмки необходимы проверка развёртывания и миграций на MySQL/MariaDB с `DBPREFIX`, браузерные сценарии и длительная нагрузка.

## Невыполненные пункты полного ТЗ

Остаются безопасный импорт справочников с предварительным просмотром и отчётом, расширенные фильтры и отчётность, полноценная история предметных изменений, уточнение правил закрытия просроченных дефектов и дополнительные эксплуатационные сценарии. Нельзя объявлять выпуск модуля полностью завершённым, пока эти части не прошли отдельную приёмку.
