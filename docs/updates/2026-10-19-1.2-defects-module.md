# Notes 1.2 — автономный модуль «Дефекты»

Статус: рабочая первая версия; до окончательной приёмки по полному ТЗ остаются отдельные задачи.

## Подключение

Пакет зарегистрирован как `modules/defects`. Ядро загружает его только при наличии лицензии с возможностью `workspace.defects` и включённого состояния модуля. По умолчанию новый модуль отключён: обновление не открывает доступ к непроверенной функциональности автоматически.

Установка и включение выполняются существующим управлением модулями в административной панели либо штатными командами `bin/control.php`. Для установки и обновления применяются каноническая схема `database/defects_schema.sql` и миграция `20261019_defects_foundation.sql`.

## Реализованные операции

- Справочники участков/РЭС, категорий объектов, объектов и ответственных служб.
- Импорт справочников из UTF-8 текста с предварительным просмотром, проверкой SHA-256 и атомарным применением в БД.
- Регистрация дефектов с описанием, приоритетом, датой обнаружения, ФИО регистрирующего и несколькими ответственными службами.
- Плановый срок устранения по утверждённой политике 1/7/14/30 дней; дата сохраняется отдельно.
- Постраничный реестр с фильтрами по статусу, приоритету, РЭС, объекту, службе и периоду; карточка со службами и закрытие с описанием выполненных работ.
- Сводный отчёт по состоянию, просрочке, приоритетам и участкам с ограниченной выдачей.
- Версии карточек, защита от повторных команд и атомарность записи связей.
- Предметная история регистрации и закрытия дефектов, создания справочников и импорта с автором, данными операции и просмотром с постраничной выдачей.
- Начальный экран «Дефекты» с действиями без перезагрузки страницы.

Все SQL-запросы выполняются через `Core\DatabaseManager`. Маршруты принадлежат `Core\Router`, входные данные — `Core\Request`, ответы — `Core\Controller`. Доступ управляется правами `defects.use` и `defects.manage`. Запись событий проходит через `Core\UserActionLog`.

## Проверки

```bash
php tests/integration/defects_priority_policy_12.php
php tests/integration/defects_reference_boundary_12.php
php tests/integration/defects_registration_12.php
php tests/integration/defects_module_runtime_12.php
```

Испытания SQLite проверяют предметные операции и откат. До окончательной приёмки необходимы проверка развёртывания и миграций на MySQL/MariaDB с `DBPREFIX`, браузерные сценарии и длительная нагрузка.

## Невыполненные пункты полного ТЗ

Остаются экспорт и печатные формы, история редактирования и архивирования (после добавления соответствующих операций), уточнение правил закрытия просроченных дефектов и дополнительные эксплуатационные сценарии. Нельзя объявлять выпуск модуля полностью завершённым, пока эти части не прошли отдельную приёмку.

## Формат импорта справочников

Файл UTF-8 содержит не более 200 записей, до 512 КиБ; разделитель `;`, комментарии начинаются с `#`. Форматы строк:

```text
area;Северный РЭС
category;Северный РЭС;Подстанции
object;Северный РЭС;Подстанции;ТП-17
service;Ремонтная служба
```

При предварительном просмотре проверяются формат, повторения и существование родительских записей. Применяется тот же неизменённый файл; импорт выполняется одной транзакцией. Совпавшие существующие записи повторно не создаются. Доступ разрешён только пользователям с правом `defects.manage`.

## История изменений

Новые события записываются в принадлежащую модулю таблицу `defect_history`, создаваемую миграцией `20261019_defects_history.sql`. Событие сохраняется **в одной транзакции** с регистрацией, закрытием или созданием записи справочника. Неудачная операция не оставляет историю, а повтор команды не дублирует событие.

В реестре кнопка «История» показывает события конкретного дефекта; пользователям с `defects.manage` доступна история записей справочников. Все запросы используют `Core\\DatabaseManager`, проверку прав выполняет платформа. Сведения о событиях до внедрения данной миграции задним числом не восстанавливаются.
