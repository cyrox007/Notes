# Workspace Organizer 1.0.1

Дата релиза: 20 сентября 2026

`1.0.1` — maintenance-релиз stable-линейки 1.0. Он сохраняет runtime/schema/update contracts 1.0.0 и добавляет module onboarding, подписанные лимиты пользователей, durable журнал действий и финальную зачистку неиспользуемого legacy template tail.

## Signed user limits

- License payload получил опциональное подписанное поле `max_users`.
- Лицензии без `max_users` остаются backward-compatible и считаются unlimited.
- Место занимает каждый активный аккаунт (`users.is_active=1`), включая blocked; deactivated-аккаунт освобождает место.
- Admin provisioning, open/invite self-registration и reactivation деактивированного пользователя используют единый `LicenseSeatPolicy`.
- Seat-changing операции сериализуются через licensing-row lock, поэтому параллельные регистрации не могут превысить лимит.
- Нельзя активировать ключ, чей `max_users` меньше текущего количества активных пользователей; старый действующий токен при отказе не заменяется.
- Admin/Core license screens показывают фактическое использование мест.
- Offline issuer поддерживает `--max-users=N`.

Пример Team-лицензии:

```powershell
& $PHP tools\vendor-license\issue.php `
  --private-key="$SECURE\prod-license-2026-01.license-secret" `
  --key-id=prod-license-2026-01 `
  --installation-id=$InstallationId `
  --license-id=lic-customer-001 `
  --edition=team `
  --max-users=20 `
  --features=workspace.notes,workspace.tasks,workspace.files,workspace.messenger,workspace.profile,workspace.admin
```

Private signing key остаётся только во внешнем vendor/offline storage.

## Module onboarding

- Добавлена `docs/MODULE_DEVELOPMENT.md` с практическим contract для независимого модуля: `module.json`, `runtime.php`, `ModuleRuntimeProvider`, routes, views/assets, capabilities, storage и DB ownership.
- Core control plane получил:
  ```bash
  php bin/control.php modules install <module-id>
  ```
- Для non-bundled module штатный lifecycle теперь:
  ```text
  discovered -> installed -> enabled
  ```
- CI проверяет реальный independently installed fixture-module.
- Database-backed external module в 1.x всё ещё использует canonical root `database/` и `database/migrations/`; это явно зафиксировано как текущая packaging boundary.

## User action audit

- Authenticated mutating HTTP actions are journaled centrally after authorization middleware; Messenger mutating WebSocket actions use the same durable journal.
- The journal stores actor snapshots, module/action, transport, outcome/status and bounded sanitized metadata only. Request bodies and user content are not persisted.
- Admins with `admin.audit.view` can filter the journal at `/admin/audit`.
- Retention is explicit: `php bin/audit_log.php --json` previews expired rows; deletion requires `--apply --yes`. Default retention is 180 days.
- Obsolete `.tpl` files left from the pre-native-view runtime are removed and guarded by CI.

## Maintenance fixes and Workspace integrations

- Исправлена авторизация/смена пароля со сложными паролями: credential boundaries используют byte-exact POST, не меняя обычную request sanitization.
- Исправлены acceptance-регрессии Notes editor, compact sidebar, Admin license layout и доступность раздела «Журнал действий».
- Messenger получил обновлённую responsive-компоновку, переработанный voice player, unread/global notifications и более устойчивый WebSocket bootstrap.
- Из Messenger можно создать задачу или заметку напрямую либо из конкретного сообщения; интеграция идёт через module capabilities и сохраняет RBAC/role limits.
- Файлы из личного хранилища можно отправить в Messenger как независимое chat-вложение или как отзывную публичную ссылку; публичные ссылки регулируются `files.can_share`.
- Для legacy File Manager rows добавлен UID backfill, необходимый для безопасных cross-module file references.
