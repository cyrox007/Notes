# Workspace Organizer 1.0.2

Статус: разработка / release candidate.

`1.0.2` — завершающий стабилизационный релиз линии 1.0 перед началом разработки `1.1.0`. Он не открывает новый цикл продуктовых функций: основная цель — довести подписанный updater и production-эксплуатацию до повторяемого пользовательского сценария.

## Запланированный объём

- единый операторский flow для подписанного обновления: remote staging → maintenance → проверенный backup кода+MySQL → внешний candidate → транзакционное применение;
- автоматический rollback/recovery остаётся единственным допустимым поведением после начала live mutation;
- production-доставка feed/manifest/signature и проверка реального обновления `1.0.1 -> 1.0.2`;
- read-only `update_doctor` для диагностики feed/trust/extensions/external paths/DB/operator prerequisites;
- Admin Updates показывает готовность оператора и точные CLI-команды install/recovery без destructive browser endpoint;
- сервис доставки update/license получает безопасный health endpoint и CLI status для production deployment/monitoring;
- старые проверенные rollback backups/release candidates очищаются отдельным fail-closed retention CLI; transaction journals и незавершённые recovery states сохраняются;
- дальнейшее улучшение UX Admin Updates без обхода существующей transaction boundary;
- CI drill exact `v1.0.1` (`0e6e4a3b352cfb7436db6b749fd869bbb07310c9`) → synthetic signed `1.0.2`, включая forced post-switch failure и автоматический rollback кода + БД;
- проверка Windows/OSPanel и обычного Linux hosting profile;
- актуализация release/operations документации после реального upgrade drill;
- явный runbook для штатного и отдельного WebSocket-узла; несколько WS instances одной installation остаются вне scope 1.0.2 до отдельной доработки pub/sub/fan-out.

## Совместимость

- Версия: `1.0.2`.
- Код версии: `10002`.
- Stable-история schema линии 1.0 не переписывается; новые изменения БД допускаются только через additive compatibility migrations.
- Существующие contracts installation/license/update trust версии `1.0.1` должны оставаться совместимыми.

## Граница перед 1.1.0

После выпуска и проверки `1.0.2` разработка функций переключается на `1.1.0` — отдельный isolated-модуль «Ежедневник + Calendar» согласно `docs/ROADMAP.md`.
