# Workspace Organizer 1.0.2

Статус: стабильный релиз.

Дата релиза: 24 сентября 2026.

`1.0.2` — завершающий релиз линии 1.0 перед началом разработки `1.1.0`. Он объединяет стабилизацию подписанного обновления и Messenger с завершённой двухфакторной аутентификацией TOTP.

## Состав релиза

- единый операторский поток подписанного обновления: удалённая подготовка → maintenance → проверенная резервная копия кода и MySQL → внешний release candidate → транзакционное применение;
- автоматический rollback/recovery остаётся единственным допустимым поведением после начала изменения live-системы;
- production feed/manifest/signature и проверка реального обновления `1.0.1 -> 1.0.2`;
- доступ к серверу обновлений в `1.0.2` настраивается автоматически после активации обычной лицензии: пользователь больше не работает с одноразовым activation code, временным файлом, `UPDATE_CREDENTIALS_FILE` или ручным `bin/update_activate.php`;
- installation credential автоматически хранится вне дерева приложения в `PRIVATE_STORAGE_PATH/update-access/update-access.json`; небезопасный путь старой установки внутри application tree игнорируется и самовосстанавливается;
- штатный stable-канал `https://jsinteractive.ru/api/notes/v1/stable/feed.json` задан по умолчанию, а `UPDATE_ACCESS_MODE=offline` остаётся явным способом отключить сетевой bootstrap;
- read-only readiness doctor для диагностики feed/trust/extensions/external paths/DB/operator prerequisites;
- Admin Updates показывает готовность и точные CLI-команды установки/восстановления без destructive browser endpoint;
- update/license delivery service предоставляет безопасный health endpoint и CLI status для production deployment/monitoring;
- старые проверенные rollback backups/release candidates очищаются отдельным fail-closed retention CLI; transaction journals и незавершённые recovery states сохраняются;
- exact CI drill опубликованного `v1.0.1` (`0e6e4a3b352cfb7436db6b749fd869bbb07310c9`) до synthetic signed `1.0.2`, включая принудительный отказ после переключения и автоматический rollback кода и БД;
- Windows compatibility CI для PHP 8.1/8.3 и ручная приёмка OSPanel 5.2.2 по `docs/WINDOWS_OSPANEL_ACCEPTANCE.md`;
- подробный WebSocket startup preflight: фактический CLI PHP, extensions, paths, listener/proxy/origins и bindability до запуска long-running process;
- diagnostics-only команда `php ws_server/server.php check` и подтверждение успешного bind;
- документированный single remote WebSocket node contract без заявления неподдерживаемого multi-instance/HA режима;
- WebSocket-first realtime transport с автоматическим HTTP long-poll fallback;
- при недоступном WebSocket Messenger продолжает durable-синхронизацию через HTTP, параллельно переподключается и возвращается на WebSocket после `Authorized`;
- Long Poll не пропускает изменение на границе timeout;
- неуспешный HTTP fallback не уничтожает неподтверждённый текст/контекст composer;
- mutation endpoint HTTP fallback явно защищён CSRF и использует тот же allow-list, RBAC, license/maintenance gates и socket handlers;
- shared DB realtime revision bridge сообщает WebSocket-клиентам о durable mutations, выполненных через HTTP fallback.

- добавлена двухфакторная аутентификация TOTP по RFC 6238;
- пользователь может включить 2FA только для собственного аккаунта через профиль;
- администратор может сделать 2FA обязательной для всех активных аккаунтов системы;
- аккаунт без TOTP при обязательной политике проходит настройку второго фактора до получения обычного доступа;
- обязательная политика запрещает пользователю самостоятельно отключить 2FA;
- резервные коды одноразовые и хранятся только в виде хешей;
- секреты TOTP шифруются в БД и участвуют в штатной возобновляемой ротации `UNIQUE_KEY` с rollback;
- отдельная матрица 2FA проверяет PHP 8.1/8.3, а Stable release gate запускает общий контракт TOTP.

## Совместимость

- версия: `1.0.2`;
- код версии: `10002`;
- stable 1.0 schema/history не переписываются; изменения БД допускаются только через совместимые additive migrations;
- существующие установки `1.0.1`, лицензии и update trust contracts должны сохранять совместимость;
- старый одноразовый activation code сохраняется только для совместимости `1.0.0/1.0.1`; обычный сценарий `1.0.2+` использует подписанную лицензию как bootstrap-доказательство.

## Граница перед 1.1.0

TOTP/2FA входит в 1.0.2. Перед публикацией требуется подтвердить персональный и обязательный режимы, резервные коды, ротацию `UNIQUE_KEY` и обновление с 1.0.1 на точном финальном кандидате.

После выпуска и проверки `1.0.2` функциональная разработка переключается на `1.1.0` — отдельный изолированный модуль «Ежедневник + Calendar» согласно `docs/ROADMAP.md`.
