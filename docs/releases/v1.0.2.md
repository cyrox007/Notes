# Workspace Organizer 1.0.2

Статус: development / release candidate.

`1.0.2` — завершающий stabilization-релиз линии 1.0 перед началом разработки `1.1.0`. Он не открывает новый feature cycle: основная цель — довести signed updater и production operations до повторяемого пользовательского сценария.

## Planned scope

- единый operator flow для signed update: remote staging → maintenance → verified code+MySQL backup → external candidate → transactional apply;
- автоматический rollback/recovery остаётся единственным допустимым поведением после начала live mutation;
- production feed/manifest/signature deployment и проверка реального обновления `1.0.1 -> 1.0.2`;
- read-only updater readiness doctor для диагностики feed/trust/extensions/external paths/DB/operator prerequisites;
- Admin Updates показывает operator readiness и точные CLI install/recovery команды без destructive browser endpoint;
- update/license delivery service получает безопасный health endpoint и CLI status для production deployment/monitoring;
- старые verified rollback backups/release candidates очищаются отдельным fail-closed retention CLI; transaction journals и незавершённые recovery states сохраняются;
- дальнейшее улучшение Admin Updates UX без обхода существующей transaction boundary;
- CI drill exact `v1.0.1` (`0e6e4a3b352cfb7436db6b749fd869bbb07310c9`) → synthetic signed `1.0.2`, включая forced post-switch failure и автоматический code + DB rollback;
- Windows compatibility CI (PHP 8.1/8.3) для updater/path/filesystem contracts;
- финальная ручная OSPanel 5.2.2 acceptance по `docs/WINDOWS_OSPANEL_ACCEPTANCE.md` на final production-signed artifacts;
- обычный Linux hosting profile;
- актуализация release/operations документации после реального upgrade drill.

## Compatibility

- Version: `1.0.2`.
- Version code: `10002`.
- Stable 1.0 schema/history не переписываются; новые изменения БД допускаются только additive compatibility migrations.
- Existing `1.0.1` installation/license/update trust contracts должны оставаться совместимыми.

## Boundary before 1.1.0

После выпуска и проверки `1.0.2` feature development переключается на `1.1.0` — отдельный isolated модуль «Ежедневник + Calendar» согласно `docs/ROADMAP.md`.
