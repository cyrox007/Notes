# Workspace Organizer 0.14.0-beta.2

Hotfix beta release for WebSocket deployment reliability, especially on Open Server 6+ and other Apache/Nginx deployments where Workerman is running but the public `wss://.../ws` endpoint is not proxied to it.

## Что исправлено в beta.2

- WebSocket endpoint contract централизован в `Core\WebSocketEndpoint`;
- Workerman по умолчанию остаётся внутренним listener на `127.0.0.1:27800`;
- браузер использует same-origin `ws(s)://<site>[/base]/ws`, а TLS/WSS завершается на фронтовом Apache/Nginx/Caddy;
- удалён нерабочий fallback на прямой `wss://host:27800` для plain Workerman listener;
- для Apache добавлен guarded `.htaccess` bridge `/ws -> 127.0.0.1:27800` при доступных proxy modules;
- добавлен `php bin/ws_doctor.php`, который различает состояние внутреннего listener и публичного reverse-proxy endpoint;
- production healthcheck теперь показывает канонический WebSocket proxy contract;
- добавлена документация Open Server 6+ с Apache/Nginx `.osp` fallback-конфигурациями;
- regression contract проверяется на PHP 8.1 и PHP 8.3, PHP warnings считаются hard failure;
- полный regression matrix, включая настоящий HTTPS/WSS browser E2E, installer, security и production gates, прошёл перед включением hotfix в `master`.

## Deployment model

Рекомендуемая схема одинакова для локальной разработки и production:

```text
Browser -> wss://domain[/base]/ws
        -> Apache/Nginx/Caddy (TLS + WebSocket Upgrade)
        -> ws://127.0.0.1:27800
        -> Workerman
```

Workerman не требуется публиковать на `0.0.0.0`, если reverse proxy находится на том же хосте.

## Дальше

`0.14.0-beta.2` остаётся beta-линейкой. Следующая основная цель проекта — **`1.0.0` stable**: module-owned runtime isolation, updater/recovery, licensing, observability, load/soak evidence, key re-encryption и CSP hardening.
