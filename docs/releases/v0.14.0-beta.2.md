# Workspace Organizer 0.14.0-beta.2

Hotfix beta-релиз для надёжности WebSocket-развёртывания, особенно в Open Server 6+ и других Apache/Nginx-конфигурациях, где внутренний WebSocket process работает, но публичный endpoint `wss://.../ws` не проксируется к нему.

> Историческая заметка: в момент выпуска beta.2 проект ещё использовал Workerman. Начиная с линии 1.0 runtime заменён собственным native PHP WebSocket server. Для текущей настройки используйте `docs/MESSENGER_SERVER.md`.

## Что исправлено в beta.2

- WebSocket endpoint contract централизован в `Core\WebSocketEndpoint`;
- внутренний listener по умолчанию остаётся на `127.0.0.1:27800`;
- browser использует same-origin `ws(s)://<site>[/base]/ws`, а TLS/WSS завершается на фронтовом Apache/Nginx/Caddy;
- удалён нерабочий fallback на прямой `wss://host:27800` для plain внутреннего listener;
- для Apache добавлен guarded `.htaccess` bridge `/ws -> 127.0.0.1:27800` при доступных proxy modules;
- добавлен `php bin/ws_doctor.php`, который различает состояние внутреннего listener и публичного reverse-proxy endpoint;
- production healthcheck показывает канонический WebSocket proxy contract;
- добавлена документация Open Server 6+ с Apache/Nginx `.osp` fallback-конфигурациями;
- regression contract проверяется на PHP 8.1 и PHP 8.3, PHP warnings считаются hard failure;
- полный regression matrix, включая настоящий HTTPS/WSS browser E2E, installer, security и production gates, прошёл перед включением hotfix в `master`.

## Модель развёртывания

Рекомендуемая схема для того исторического релиза:

```text
Browser -> wss://domain[/base]/ws
        -> Apache/Nginx/Caddy (TLS + WebSocket Upgrade)
        -> ws://127.0.0.1:27800
        -> WebSocket process
```

Внутренний listener не требуется публиковать на `0.0.0.0`, если reverse proxy находится на том же host.
