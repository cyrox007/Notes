# Проверка перехода 1.0.16 → 1.1

Сначала используйте отдельную копию каталога приложения, базы данных и внешнего PRIVATE_STORAGE_PATH. Сохраните исходные .env, доверенные ключи, лицензию и SHA-256 файлов. Рабочую установку нельзя использовать как тестовую базу.

1. До обновления переключите копию на PHP 8.2 или новее. Убедитесь в доступности mysqli/pdo_mysql, mbstring, sodium, openssl, fileinfo, zlib и gd. Выполните healthcheck исходной версии.
2. Сделайте полный снимок базы и приватных файлов. Не запускайте web-установщик поверх существующей базы.
3. Распакуйте основной ZIP 1.1.0 в отдельный каталог. Затем распакуйте `workspace-organizer-v1.1.0-updater-bridge.zip` из того же GitHub Release в корень этого каталога: рядом должны находиться `core/` и `tools/`. До перехода с 1.0.16 установите мост из этого доверенного распакованного пакета: `php tools/release/bootstrap-1.0.16-updater.php --yes --root=/путь/к/копии/1.0.16`. Он требует PHP 8.2+, проверяет точные версии источника и назначения, сохраняет исходные updater-файлы, не меняет Version.php, .env, доверенные ключи, миграции или БД. Старый web-обновлятор 1.0.16 без этого моста не знает платформенные миграции 1.1. Повторный запуск допустим, активную транзакцию мост не меняет.
4. Для подписанного выпуска используйте обычный обновлятор с проверкой подписи. Локальный ZIP кандидата без подписи предназначен для изолированного стенда и не должен добавляться в стабильный feed. При ручной проверке копии сохраните её .env, приватные файлы и доверенные ключи, затем примените `php bin/migrate.php` новым кодом.
5. Проверьте healthcheck, вход, старые заметки/задачи/файлы/переписку и права доступа. Проверьте Calendar, уведомления, подписки и отправку через тестовый SMTP. Повторный запуск миграций не должен применять их заново.
6. Добавьте в планировщик `php bin/calendar_reminders.php` и `php bin/notifications_worker.php`. Запускайте `php bin/healthcheck.php --json` для диагностики; его ошибки и нехватка места помещаются в устойчивую очередь. Порог STORAGE_LOW_THRESHOLD_BYTES по умолчанию 100 МиБ. Получатели — активные пользователи с admin.settings.manage или ролью superadmin. HTTP-проверка центра уведомлений служит резервным ограниченным обработчиком.

Системные уведомления появляются только для событий, зафиксированных новым кодом; старый обновлятор 1.0.16 не создаёт их задним числом. Ошибка доставки сохраняет событие для следующего прохода. Отключение внешних каналов не мешает встроенной доставке.

## Возврат

Автоматический updater восстанавливает снимок при ошибке миграции или проверки новой версии. Для ручного стенда восстанавливайте вместе исходный код, базу, .env и приватное хранилище из одного снимка. Простая замена кода на 1.0.16 поверх уже изменённой БД не является проверенным откатом. Сохраняйте новые пользовательские изменения отдельно перед полным восстановлением снимка.

CI проверяет успешное обновление с журналом миграций и без него, отказ после фактического изменения БД и прерывание браузера после переключения кода/миграций. Контрольные пользовательские данные проверяются до и после операций. Производственная установка не участвует в этих сценариях.
