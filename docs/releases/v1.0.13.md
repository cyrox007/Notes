# Workspace Organizer 1.0.13

Дата выпуска: 30 сентября 2026  
Статус: опубликован  
Код версии: `10013`

## Назначение релиза

`1.0.13` завершает пользовательский контур модульной платформы перед добавлением новых прикладных модулей. Выпуск связывает три независимых уровня доступа:

`лицензия → состояние модуля в установке → права пользователя`.

Модуль доступен пользователю только когда все три уровня его разрешают.

## Явные разрешения лицензии

Каждый встроенный модуль объявляет `license.feature`:

- Admin — `workspace.admin`;
- Notes — `workspace.notes`;
- Tasks — `workspace.tasks`;
- File Manager — `workspace.files`;
- Messenger — `workspace.messenger`;
- Profile — `workspace.profile`.

Начиная с этого выпуска разрешение должно **явно** присутствовать в подписанном поле `features`. Отсутствующее поле, пустой список и отсутствие конкретного feature не трактуются как полный доступ.

Нелицензированный модуль:

- не входит в активную runtime-композицию;
- не регистрирует provider, capability и маршруты;
- не показывается в Admin → Модули;
- не появляется в общей навигации и на главной;
- не предоставляет соседним модулям свои действия и содержимое;
- сохраняет данные и операторский `configured_state`.

Для этого добавлено фактическое состояние `unlicensed`.

## Admin → Модули

Суперадминистратор получает отдельный раздел **Admin → Модули**.

В нём отображаются только модули, разрешённые текущей лицензией. Для каждого показываются версия, лицензионный feature, заданное и фактическое состояние.

Обычные прикладные модули можно включать и отключать. Отключение не удаляет:

- таблицы и записи;
- private storage;
- настройки;
- разрешения ролей;
- ролевые политики.

После повторного включения прежнее состояние снова используется.

Admin объявлен обязательным системным модулем и не имеет операторского действия отключения. Если сама лицензия не содержит `workspace.admin`, Admin не загружается, но независимый core-маршрут `/license` остаётся доступным суперадминистратору для установки подходящей лицензии.

## Исчезновение межмодульных возможностей

Отключение — это не скрытие пункта меню.

### Notes и Tasks

При отключении Notes или Tasks:

- их карточки и пункты общей навигации исчезают;
- собственные маршруты перестают регистрироваться;
- Messenger не показывает создание заметки или задачи;
- соответствующие Messenger-маршруты создания объекта не регистрируются;
- Profile не показывает показатели и настройки видимости этого типа.

### File Manager

При отключении File Manager:

- его навигация и маршруты недоступны;
- Messenger не показывает выбор файла из личного хранилища;
- файловые маршруты интеграции Messenger не регистрируются;
- Profile не показывает файлы, объём хранилища и файловые настройки видимости;
- Admin не показывает квоты и лимит загрузки File Manager;
- сохранённые квоты и ролевые политики не удаляются.

### Messenger

При отключении Messenger:

- его маршруты и provider отсутствуют;
- глобальные клиентские ресурсы Messenger не загружаются;
- постоянно работающий WebSocket не должен оставаться параллельным runtime отключённого Messenger.

### Profile

При отключении Profile:

- профиль и каталог пользователей исчезают из активной композиции;
- Messenger не формирует профильные URL аватаров и не предлагает переход в профиль собеседника.

## Обновлятор и WebSocket

До 1.0.13 updater исходил из того, что WebSocket, работавший до обновления, обязательно должен снова запуститься после переключения кода.

С появлением лицензионного состава это неверно: новая лицензия или новый контракт может сделать Messenger недоступным. Теперь post-update проверка различает два случая:

- Messenger доступен — WebSocket перезапускается и проверяется как раньше;
- Messenger недоступен — прежний WebSocket штатно останавливается, а отсутствие его повторного запуска не вызывает rollback всего релиза.

Если последующая проверка всё же требует rollback, восстановленная старая версия получает прежний WebSocket обратно.

## Проверки релиза

Обязательная матрица включает:

- lifecycle с разрешённым и запрещённым лицензией модулем;
- невозможность ручного включения нелицензированного модуля;
- невозможность операторского отключения обязательного Admin;
- статические контракты Admin/Profile/Messenger/shared shell;
- браузерный цикл отключения Notes, проверки отсутствия его точек входа и повторного включения;
- обновление и rollback с учётом WebSocket;
- обычные release-gate, browser lifecycle и совместимость PHP/БД.

PR #322 завершил exact-head CI с результатом **68/68 успешно** и слит в `master`.

## Проверяемый путь обновления

## Совместимость

- PHP: 8.1+.
- БД: MySQL 8.0+ или MariaDB 10.5+.
- Windows / OSPanel 5.2.2 остаётся поддерживаемой целью.
- WebSocket остаётся необязательным ускорителем Messenger; Long Poll обеспечивает рабочий транспорт при отсутствии отдельного WebSocket-процесса.
- Распаковка ZIP поверх рабочей установки не является поддерживаемым способом обновления.

## Эксплуатационный ввод

Публикация GitHub Release предшествует размещению версии во внешнем реестре обновлений.

После добавления 1.0.13 в реестр оператор:

1. публикует или обновляет stable-feed;
2. проверяет, что установка 1.0.12 видит 1.0.13 штатным updater;
3. выполняет контрольное обновление обычной лицензированной установки;
4. фиксирует найденные эксплуатационные дефекты отдельным следующим patch-релизом линии 1.0.x.

До регистрации выпуска во внешнем реестре отсутствие 1.0.13 в пользовательском канале обновлений является ожидаемым состоянием.
