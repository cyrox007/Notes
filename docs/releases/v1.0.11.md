# Workspace Organizer 1.0.11

Дата релиза: 29 сентября 2026  
Статус: stable  
Код версии: `10011`

## Назначение релиза

`1.0.11` заменяет отозванный `1.0.10` и закрывает найденные при реальном обновлении с `1.0.9` регрессии. Номер `1.0.10` повторно не используется.

Главная цель релиза — восстановить надёжный путь обновления с опубликованной `1.0.9` и не допустить ситуацию, когда после ошибки обновления требуется ручное восстановление установки.

## Updater и recovery

- Для exact `1.0.9` сохраняется одноразовый `bootstrap-1.0.9-updater.php`, потому что уже опубликованный updater 1.0.9 создаёт неполный recovery-runtime.
- Bootstrap не устанавливает новый пакет и не обходит подпись. Он только добавляет отсутствующую зависимость `core/HostingCompatibility.php` в состав автономного runtime 1.0.9.
- Новый `UpdateExternalRuntime` проверяет замкнутость локальных `require/require_once` до destructive-фазы. Если runtime неполон, обновление завершается безопасным отказом до изменения рабочих файлов.
- Сквозной drill начинается с неизменяемого тега `v1.0.9`, проходит через подписанный feed и штатный web-updater.
- В drill обязательны два принудительных отказа: ошибка миграции и ошибка post-health. В обоих случаях требуется `rollback_verified`, снятый maintenance и рабочий healthcheck.
- После rollback и после успешной установки проверяются контрольные заметка, задача, файл, реальные байты private storage, диалог и сообщение Messenger.
- Отдельно проверяется раннее boot recovery после имитации обрыва процесса и повторный HTTP-запрос без ручного recovery CLI.

## Profile

- Исправлена регрессия 1.0.9, из-за которой TOTP-ресурсы перезаписывали `module_styles/module_scripts`.
- Изолированный модуль Profile снова сам объявляет `style.css`, `hub.css`, `metrics.css` и `profile.js`.
- Compatibility bridge больше не владеет ресурсами Profile.
- Браузерный тест проверяет, что форма редактирования скрыта до действия пользователя и что аватар получает модульную геометрию вместо исходного размера изображения.

## Messenger

- WebSocket остаётся необязательным ускорителем, Long Poll — полноценным рабочим transport.
- Исправлена гонка общей realtime-ревизии: локальная WebSocket-мутация больше не может замаскировать внешнее изменение, пришедшее через HTTP fallback.
- При активном WebSocket транспортный маркер зелёный.
- При активном Long Poll транспортный маркер ярко-синий: `#1687ff` в светлой теме и `#49a7ff` в тёмной.
- Восстановление соединения отображается жёлтым, отсутствие связи — красным.
- Long Poll остаётся состоянием `online`, а не пользовательской ошибкой.

## Файловый менеджер

- Разрешена загрузка VSD, VSDX, DJVU и ZIP с серверной проверкой MIME.
- VSD/VSDX отображаются как документы Visio, DJVU — как документ, а ZIP использует архивную иконку.
- Просмотр файла больше не требует отдельной кнопки с глазком: одиночный клик по самому объекту открывает встроенный предпросмотр для изображений, аудио, видео и текста; остальные файлы открываются через защищённый маршрут выдачи.
- Кнопки действий не запускают просмотр, а Enter по объекту сохраняет клавиатурный сценарий открытия.

## Отозванный 1.0.10

`1.0.10` не должен присутствовать в stable-feed и не должен предлагаться существующим установкам.

Причины отзыва:

- опубликованная `1.0.9` могла создать recovery-runtime без `HostingCompatibility.php`;
- реальное падение обновления приводило к невозможности выполнить автоматический recovery;
- в Profile была обнаружена отдельная регрессия подключения модульных ресурсов.

Исправленный пакет публикуется только как `1.0.11`.

## Проверяемый путь обновления

Основной релизный путь:

`v1.0.9 → bootstrap совместимости 1.0.9 → подписанный updater → 1.0.11`.

Перед публикацией обязательны:

1. успешный preflight exact 1.0.9;
2. автоматический rollback после намеренной ошибки миграции;
3. автоматический rollback после намеренной ошибки post-health;
4. сохранность пользовательских данных после каждого rollback;
5. успешное обновление до 1.0.11;
6. сохранность пользовательских данных и private storage после обновления;
7. boot recovery после имитации аварийного обрыва;
8. Windows/OSPanel compatibility;
9. браузерные Profile и Messenger сценарии;
10. режим Messenger без WebSocket через Long Poll;
11. отсутствие PHP fatal/error в логах после всех сценариев.

## Совместимость

- PHP: 8.1+.
- БД: MySQL 8.0+ или MariaDB 10.5+.
- Windows / OSPanel 5.2.2 остаётся обязательной целью релизной приёмки.
- WebSocket не является обязательной зависимостью Messenger.
- Распаковка релизного ZIP поверх рабочей установки не является поддерживаемым способом обновления.
