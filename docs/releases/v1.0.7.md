# Workspace Organizer 1.0.7

Дата релиза: 28 сентября 2026  
Статус: stable  
Код версии: `10007`

## Назначение релиза

`1.0.7` — стабилизационный релиз линии 1.0 после публикации и реальной эксплуатации `1.0.6`.
Он закрывает дефекты, обнаруженные уже на установленной системе, и доводит Messenger до режима,
в котором WebSocket является ускоряющим каналом, но не обязательным условием работы realtime.

Основной проверяемый путь обновления для этого релиза — `1.0.6 → 1.0.7`.

## Что изменено

### Установка и recovery

- исправлено ошибочное наследование старого `workspace-maintenance.json` и updater journal при повторной установке в тот же физический каталог;
- maintenance предыдущей установки определяется по `INSTALL_DATE` и снимается только при валидном подтверждённом marker;
- журнал старой транзакции не удаляется и остаётся доступным для диагностики;
- текущие, повреждённые и неоднозначные recovery-состояния по-прежнему обрабатываются fail-closed;
- установка из Admin больше не требует `proc_open` и отдельного PHP CLI: при их недоступности автоматически используется совместимый web-режим;
- совместимый режим выполняет долговечные этапы отдельными HTTP-запросами: backup → candidate → preflight → переключение кода → миграции → post-health → commit;
- продолжение транзакции во время maintenance разрешено только точному updater-маршруту по короткоживущему capability-токену; на диске хранится только SHA-256 токена;
- `proc_open` и PHP CLI остаются необязательным ускоренным режимом там, где hosting их разрешает;
- аварийное восстановление использует отдельный проверенный runtime и не зависит от live-кода, который мог быть частично заменён.

### Messenger

- authenticated HTTP Long Poll стал полноценным durable-транспортом;
- Messenger может штатно работать в окружении, где WebSocket server или WebSocket reverse proxy отсутствуют;
- временные 5xx, зависшие poll-запросы, смена сети и восстановление после сна не оставляют transport остановленным;
- добавлены watchdog, ограниченный backoff и автоматический restart Long Poll;
- WebSocket продолжает переподключаться в фоне и после `Authorized` бесшовно возвращается как быстрый канал;
- глобальный badge непрочитанных и системные сообщения Messenger работают без WebSocket;
- короткоживущая activity-синхронизация доступна обоим transport;
- видимые вкладки координируют владение глобальным realtime transport, уменьшая лишнее удержание PHP workers;
- перед запуском встроенного updater текущая вкладка заранее останавливает WebSocket и Long Poll, чтобы не создавать фоновые запросы после включения maintenance.

## Интерфейс

- исправлено ложное уведомление «Доступно обновление», которое могло отображать скрытый шаблон при фактическом отсутствии новой версии;
- рядом с `Installation ID` добавлена кнопка копирования с понятным подтверждением результата;
- «Профиль» больше не дублирует «Настройки»: личная страница пользователя и системные настройки Admin разведены в боковой навигации и Ctrl+K.

## Совместимость

- минимальный PHP: 8.1;
- CI compatibility matrix: PHP 8.1, 8.2, 8.3, 8.4 и 8.5;
- основной production baseline БД: MySQL 8.x;
- Long Poll не требует отдельного CLI/WebSocket process, но hosting должен разрешать длительные authenticated HTTP requests и достаточную параллельность PHP workers;
- WebSocket остаётся рекомендуемым быстрым каналом для меньшей задержки и нагрузки;
- automatic updater требует `openssl`, `zlib`, `mysqli`, доступный на запись внешний private storage и возможность выполнять обычные PHP HTTP-запросы;
- `proc_open` и отдельный PHP CLI для установки из Admin не обязательны: при их отсутствии автоматически выбирается совместимый web-режим;
- private storage должен располагаться вне document root и быть доступен PHP на запись.

## Проверка обновления

Release CI поднимает текущую архитектуру как `1.0.6` и устанавливает подписанный `1.0.7`.
Проверяются:

1. успешная установка одной кнопкой;
2. автоматический rollback после намеренно сломанной миграции;
3. автоматический rollback после ошибки post-update healthcheck;
4. раннее boot recovery на следующем HTTP-запросе;
5. отсутствие фоновых Messenger 5xx на границе updater maintenance/rollback;
6. штатный HTTPS/WSS path и автоматическое переключение на Long Poll;
7. работа Long Poll после временного HTTP 503 и зависшего запроса;
8. activity и глобальные уведомления без обязательного WebSocket;
9. shared-hosting режим updater без обязательных `proc_open` и PHP CLI;
10. наличие web-updater/recovery runtime в финальном hosting bundle.

## Ручная приёмка перед публикацией

Перед финальной публикацией `v1.0.7` exact release-candidate должен быть проверен на реальной установке `1.0.6`:

- обновление `1.0.6 → 1.0.7` одной кнопкой;
- сохранность пользователя, роли, лицензии, `installation_id`, private storage и прикладных данных;
- отсутствие наследованного maintenance после новой установки;
- штатная работа Messenger только через Long Poll при отключённом WebSocket;
- автоматический возврат к WebSocket после его восстановления;
- отсутствие ложного системного уведомления об обновлении;
- корректные переходы «Профиль» и «Настройки»;
- копирование `Installation ID`;
- отдельная установка с отключённым `proc_open`: Admin должен показать «Совместимый с хостингом» и завершить обновление одной кнопкой без команд PHP CLI.

OSPanel 5.2.2 остаётся обязательным целевым окружением этой ручной приёмки; OSPanel 6+ можно использовать как дополнительную современную Windows-проверку.

## Граница поддержки

`1.0.7` сохраняет compatibility contract линии 1.0 и не требует нового ручного bootstrap для перехода с `1.0.6`.
Публикация релиза не должна перемещать или переписывать уже существующие теги `v1.0.6` и более ранних версий.
