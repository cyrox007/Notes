# Workspace Organizer 1.0.12

Дата релиза-кандидата: 30 сентября 2026  
Статус: **stable, опубликован**  
Код версии: `10012`

## Назначение релиза

`1.0.12` — исправительный выпуск после `1.0.11`, собранный по реальной пользовательской обратной связи. Основные цели: закончить жизненный цикл общего доступа в File Manager, сделать чужие профили обнаруживаемыми, устранить регрессии компактного Messenger и превратить ограничение размера загрузки в понятную административную настройку.

Новых крупных прикладных модулей релиз не добавляет.

## Messenger

- Объединены изменения прежних веток #314 и #315 в единую релизную линию.
- Общий сайдбар корректно работает на промежуточной ширине до 900 px.
- Действия шапки чата, сообщений и редактора не прячутся в горизонтально обрезанной области.
- WebSocket отображается зелёным, рабочий Long Poll — синим, восстановление — отдельным состоянием.
- Long Poll остаётся полноценным рабочим транспортом и запускается независимо от успешности WebSocket.
- Реальные аватары используются в диалогах, шапке личного чата и выборе контактов.
- По имени или аватару собеседника можно перейти в его профиль.
- Исправлен тип данных, передаваемый в публичное представление Profile.
- Проверка самовосстановления Long Poll согласована с намеренно видимым названием активного транспорта.

## File Manager: общий доступ

### Центр управления

В File Manager добавлен раздел **«Общий доступ»**. Он показывает созданные ссылки независимо от того, где находится исходный объект.

Для каждой записи отображаются:

- файл или папка;
- дата создания;
- срок действия;
- состояние: активна, истекла, отозвана либо исходный объект удалён;
- действия копирования и открытия;
- изменение срока;
- отзыв доступа.

Отзыв ссылки не удаляет файл или папку.

### Срок действия

При создании ссылки доступны варианты:

- без срока;
- 1 день;
- 7 дней;
- 30 дней;
- произвольная дата и время.

Ссылка после истечения срока перестаёт выдавать содержимое. Истёкшую активную запись можно увидеть в центре общего доступа.

### Публикация папок

Поддерживается публикация папок одной ссылкой. Получатель видит содержимое опубликованного дерева и может переходить по вложенным папкам.

Сервер на каждом переходе проверяет, что объект:

- принадлежит тому же владельцу;
- остаётся внутри опубликованного корня;
- не удалён;
- запрошен через действующую ссылку.

Ссылка на папку не раскрывает соседние папки и файлы владельца.

### Открытие папок

Отдельная кнопка «Открыть папку» убрана. Папка открывается кликом по всей карточке или строке. Кнопки действий остаются отдельными и переход не запускают. Клавиатурное открытие по Enter сохранено.

## Ограничение размера загрузки

Максимальный размер одного файла настраивается в **Admin → Системные настройки**.

Workspace показывает:

- заданный лимит приложения;
- `upload_max_filesize`;
- `post_max_size`;
- фактически загруженный `php.ini`;
- обнаруженный тип веб-сервера;
- известный предел тела HTTP-запроса, если его удалось определить;
- известный фактический потолок размера файла.

Если администратор задаёт лимит выше возможностей PHP или известного ограничения веб-сервера, настройка сохраняется, но интерфейс показывает явный конфликт и руководство по его устранению.

Для PHP выводятся требуемые значения `upload_max_filesize` и `post_max_size`. Для Apache, Nginx и IIS показываются соответствующие директивы. Если внешний reverse proxy не раскрывает предел приложению, его можно указать для диагностики через `WEB_SERVER_MAX_UPLOAD_SIZE`; эта переменная не изменяет конфигурацию сервера.

Существующая ролевая политика `files.max_file_bytes` остаётся дополнительным более строгим ограничением для отдельных ролей.

## Profile

Добавлен раздел **«Пользователи»**:

- поиск по имени, фамилии и логину;
- только активные доступные учётные записи;
- постраничный вывод;
- переход в профиль пользователя.

Терминология собственного профиля изменена:

- **«Видимость профиля»** определяет, какие заметки, задачи и файлы видят другие авторизованные пользователи Workspace;
- **«Общий доступ»** в File Manager создаёт специальную ссылку, доступную её получателю.

Эти режимы независимы и не должны автоматически раскрывать друг друга.

## Автоматическая проверка общего доступа

Browser E2E проверяет полный сценарий:

1. создание корневой папки;
2. создание вложенной папки;
3. загрузку файла внутрь неё;
4. публикацию корневой папки;
5. анонимное открытие ссылки;
6. переход во вложенную папку;
7. получение вложенного файла;
8. отзыв ссылки;
9. недоступность старого URL после отзыва;
10. создание отдельной ссылки на файл с заданным сроком;
11. истечение срока;
12. недоступность URL после истечения;
13. сохранность исходных объектов после отзыва и истечения.

## Проверяемый путь обновления

Основной путь релиза:

`1.0.11 → встроенный подписанный updater → 1.0.12`.

Для этого перехода не требуется bootstrap предыдущих старых версий. Перед изменением рабочих файлов updater обязан пройти обычный preflight, применить новую миграцию системного лимита загрузки, выполнить post-update healthcheck и при ошибке использовать штатный rollback/recovery.

Контрольные пользовательские данные должны сохраняться после успешного обновления и после проверяемого отказа/отката.

## Совместимость

- PHP: `8.1+`.
- БД: MySQL `8.0+` или MariaDB `10.5+`.
- Windows / OSPanel 5.2.2 остаётся поддерживаемой целью.
- WebSocket остаётся необязательным ускорителем Messenger; Long Poll сохраняет полный рабочий контур.
- Распаковка ZIP поверх рабочей установки не является поддерживаемым способом обновления.
