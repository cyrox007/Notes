# Workspace Organizer v0.14.0-beta.3

`0.14.0-beta.3` закрывает пробел в управлении регистрацией и созданием пользователей, не открывая новый цикл разработки функций перед `1.0.0`.

## Регистрация и пользователи

- Добавлены три управляемых режима публичной регистрации: **закрыта**, **свободная** и **только по инвайтам**.
- Без явно сохранённой политики регистрация по умолчанию закрыта.
- Администратор может создавать обычных пользователей непосредственно из админ-панели независимо от режима публичной регистрации.
- Саморегистрация и админское создание назначают каноническую RBAC-роль `user`; повышение до admin/superadmin остаётся отдельной операцией управления доступом.

## Управляемые инвайты

- Инвайты создаются из админ-панели с названием, сроком действия и лимитом использований.
- Код приглашения генерируется криптографически случайно и показывается только при создании.
- В `system_settings` сохраняется SHA-256 hash кода и служебные метаданные, а не сам plaintext-код.
- Поддержаны revoke, expiry и usage limit.
- Создание пользователя и расход инвайта выполняются в одной транзакции; состояние списка инвайтов блокируется через `SELECT ... FOR UPDATE`.
- Старый `REGISTRATION_INVITE_CODE` сохранён только как compatibility fallback до первого явного сохранения новой политики регистрации в БД.

## Безопасность

- Публичный POST регистрации защищён `AuthRateLimit` и CSRF.
- Создание пользователя и изменение registration/invite settings в админке требуют соответствующих RBAC permission checks и CSRF.
- Авторизация повторно проверяется внутри service-layer, а не полагается только на HTTP middleware.

## Развёртывание и совместимость

- Добавлена отдельная матрица `docs/DEPLOYMENT_COMPATIBILITY.md` для Open Server 6+, Open Server 5.4.x с PHP 8.1+, Linux VPS/VDS и shared hosting.
- Для shared hosting явно зафиксировано ограничение realtime Messenger: требуется long-running PHP process и WebSocket reverse proxy; cron не является заменой process manager.

## Проверки релиза

Перед merge функционального PR успешно прошли все 38 PR workflows, включая PHP 8.1/MySQL 8.4 registration contract, Chromium registration lifecycle, installer/upgrade, Hosting installer, Security baseline, browser lifecycles, HTTPS/WSS E2E, Product Quality и Master release gate.

После merge в `master` повторно успешно прошли push-gates: installer schema contract, Master release gate, Module platform contract и core router/session security.

Это предварительный релиз beta-линейки. Основная цель после beta patch releases остаётся `1.0.0` stable и закрытие оставшихся platform/stability blockers.
