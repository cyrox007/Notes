# Workspace Organizer 1.0.3

Дата релиза: 24 сентября 2026  
Статус: stable  
Код версии: `10003`

## Состав релиза

`1.0.3` закрывает критичный пробел линии 1.0: обновление из Admin теперь действительно выполняет подписанную транзакционную установку, а не только проверку и staging.

Основные изменения:

- реальная установка обновления из Admin → Updates только для суперадминистратора;
- CSRF-защита и привязка подтверждения к проверенным `version_code` и SHA-256 пакета;
- использование существующего `bin/update_run.php`, а не отдельного браузерного механизма замены файлов;
- определение PHP CLI для web-runtime, включая Windows и OSPanel;
- настоящий сквозной E2E реального пути: exact `v1.0.2` штатно обновляется CLI до текущего `1.0.3`, затем уже `1.0.3` устанавливает следующее подписанное тестовое обновление из Admin UI;
- исправление локализованного WebSocket `status` и снятия maintenance при отказе до изменения live-файлов;
- ранняя проверка готовности схемы БД с диагностическим HTTP 503 вместо поздних SQL 500;
- устойчивое поведение страницы ролей Admin при ошибках чтения данных;
- стабилизация интерфейса регистрации и Messenger при переключении WebSocket ↔ HTTP long-poll fallback.

## Совместимость

- PHP: 8.1+; для публичного production рекомендуется поддерживаемая ветка PHP, сейчас 8.3+.
- MySQL: 8.x.
- Сохраняется совместимость данных и migration history линии 1.0.
- Fresh install использует текущие canonical schemas.
- Existing install обновляется через compatibility migration/updater path; распаковка поверх рабочей установки не считается штатным способом обновления.

### Важно для установок 1.0.2

Опубликованная `1.0.2` умеет проверять и подготавливать обновления, но ещё не содержит destructive apply из Admin UI. Поэтому переход на `1.0.3` выполняется один раз через существующий CLI updater:

```bash
php bin/update_run.php --yes --json
```

После успешного перехода на `1.0.3` следующие подписанные обновления можно устанавливать из Admin → Updates, если readiness-проверка разрешает установку.

## Проверка обновления

Обязательный `admin-update-e2e` поднимает отдельную установку из exact тега `v1.0.2`, создаёт реальную MySQL-схему и суперадминистратора и повторяет реальный путь без подмены возможностей старой версии. Сначала подписанный пакет текущего exact HEAD устанавливается штатным `bin/update_run.php`, потому что в `1.0.2` кнопки установки ещё нет. Затем канал переключается на следующее подписанное тестовое обновление, и уже работающая `1.0.3` через Chromium выполняет `Проверить обновления → Установить обновление`.

После этого тест проверяет две успешные committed-транзакции, `live_mutation_started=true`, отсутствие оставшегося maintenance, сохранность пользователя, роли и `installation_id`, а также успешный post-update healthcheck.

## Граница перед 1.1.0

`1.0.3` остаётся исправляющим релизом стабильной линии 1.0. Новые продуктовые возможности, не необходимые для исправления совместимости, обновления или эксплуатационной надёжности, должны уходить в следующий feature-cycle, а не расширять этот patch-релиз.
