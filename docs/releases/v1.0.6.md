# Workspace Organizer 1.0.6

Дата релиза: 27 сентября 2026  
Статус: stable  
Код версии: `10006`

## Назначение релиза

`1.0.6` — опорный релиз новой архитектуры обновлений Workspace Organizer.
Он устраняет проблемы, обнаруженные при реальной Windows/OSPanel-приёмке предыдущего механизма,
и становится исходной версией для обязательной проверки перехода `1.0.6 → 1.0.7`.

Публикация `1.0.6` предшествует этой ручной проверке намеренно: новый updater находится
в самой `1.0.6`, поэтому проверить его на реальном обновлении до следующей версии
до существования устанавливаемой `1.0.6` технически невозможно.

## Что изменено

- критическая фаза updater исполняется из проверенного внешнего runtime вне live-tree;
- рабочие файлы применяются и откатываются пофайлово без переименования целиком исполняемых каталогов;
- устаревший update credential автоматически восстанавливается по действующей лицензии;
- единый private storage определяется и при необходимости создаётся автоматически без обязательной ручной правки `.env`;
- rollback backup/restore различает числовые, NULL, JSON, BLOB/BINARY и текстовые значения;
- сохранено восстановление legacy dump, где JSON исторически записывался как binary hex;
- незавершённая транзакция автоматически восстанавливается первым следующим HTTP-запросом до обычной загрузки приложения;
- maintenance снимается только после подтверждённого `committed` или `rollback_verified`;
- Admin показывает реальные этапы операции, а CLI остаётся аварийным техническим путём, не пользовательским сценарием.

## Безопасность обновления

Перед изменением live-tree клиент повторно проверяет подписанный manifest, SHA-256 пакета,
совместимость версии, rollback backup и внешний release candidate. После переключения
выполняются миграции, проверка точной версии и healthcheck. Ошибка после начала изменения
рабочих файлов запускает автоматический rollback кода и БД.

При ответе update API `401` локальный credential считается устаревшим и один раз
перевыпускается через действующую лицензию. `403` не маскируется автоматическим повтором
и остаётся явным ограничением лицензии или права на обновление.

## Совместимость

- PHP: 8.1+; для production рекомендуется 8.3+;
- основной production baseline БД: MySQL 8.x;
- rollback-контракт дополнительно проверен на MariaDB 10.11;
- автоматическое обновление требует `openssl`, `zlib`, `proc_open` и доступный PHP CLI;
- private storage должен находиться вне live-tree и document root и быть доступен PHP на запись;
- подпись обновлений — Ed25519 с production trust root.

## Следующая обязательная приёмка

После установки опубликованной `1.0.6` выполняется реальная Windows/OSPanel 5.2.2
проверка на подписанном тестовом `1.0.7`:

1. успешное обновление одной кнопкой;
2. автоматический rollback при ошибке миграции;
3. автоматический rollback при ошибке post-update healthcheck;
4. восстановление после принудительного завершения PHP-процесса первым следующим HTTP-запросом;
5. сохранность пользователя, роли, лицензии, `installation_id` и прикладных данных;
6. отсутствие оставшегося maintenance после подтверждённого успешного обновления или rollback.

До успешного завершения этой проверки новая архитектура считается автоматически
проверенной CI и опубликованной как опорная версия, но ещё не принятой владельцем
на реальной Windows/OSPanel среде.

## Граница поддержки

`1.0.6` является новой опорной точкой updater. Обязательная работоспособность старой
багованной архитектуры обновления `1.0.5` и более ранних версий не используется как
критерий приёмки нового updater. Следующий эталон — `1.0.6 → 1.0.7`.
