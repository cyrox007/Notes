# Workspace Organizer 1.0.5

Дата релиза: 24 сентября 2026  
Статус: stable  
Код версии: `10005`

## Назначение релиза

`1.0.5` — переходный стабильный релиз, который становится базовой версией
постоянного механизма обновлений Workspace Organizer.

Начиная с этой версии штатный пользовательский сценарий выглядит так:

```text
оператор публикует и подписывает stable-релиз на jsinteractive.ru
  -> активная лицензированная установка сама обнаруживает его
  -> в центре уведомлений появляется новая версия
  -> суперадминистратор нажимает одну кнопку «Обновить до …»
  -> клиент повторно проверяет подписанный feed
  -> фиксирует version_code и SHA-256 пакета
  -> выполняет staging и резервное копирование
  -> включает maintenance
  -> переключает код и применяет миграции
  -> выполняет post-update healthcheck
  -> фиксирует committed и снимает maintenance
```

Пользователь не должен запускать PowerShell/SSH/PHP CLI, скачивать bootstrap,
редактировать `.env`, вручную применять SQL или распаковывать ZIP поверх
рабочей установки.

## Что изменено

- добавлена автоматическая проверка обновлений после входа и каждые пять минут;
- добавлен центр системных уведомлений с новой версией;
- добавлена одношаговая установка последнего совместимого подписанного релиза;
- перед destructive-частью релиз повторно связывается с exact `version_code`
  и SHA-256 пакета;
- существующие транзакционные staging/backup/migrations/rollback не дублируются
  в браузерном коде;
- durable transaction journal создаётся до включения maintenance, поэтому даже
  аварийный обрыв до backup имеет однозначное безопасное состояние recovery;
- после ошибки за destructive boundary откат выполняется автоматически; при
  прерванном или незавершённом восстановлении обёртка сама возобновляет recovery
  по журналу до трёх раз, не предлагая пользователю команды CLI;
- если погиб и сам HTTP/PHP-процесс, следующий запрос до запуска БД и модулей
  автоматически продолжает recovery; живое обновление защищено operation lock;
- клиент сообщает серверу фактические `X-Notes-Version` и
  `X-Notes-Version-Code`, чтобы control plane мог выдавать совместимый
  следующий релиз;
- fresh install заранее проверяет `openssl`, `zlib`, `proc_open` и PHP CLI;
- release gate запрещает stable-релиз без одношагового контура обновлений.

## Переход с 1.0.4

Опубликованная `1.0.4` уже содержит исправленный поиск PHP CLI для Windows и
OSPanel, но ещё не содержит нового центра автоматических уведомлений.

Поэтому `1.0.4 → 1.0.5` — последний переходный шаг:

1. суперадминистратор открывает Admin → Updates;
2. запускает проверку обновлений;
3. устанавливает подписанный `1.0.5`.

Никакие bootstrap-файлы для `1.0.4` не должны требоваться. После перехода на
`1.0.5` следующий stable-релиз должен обнаруживаться автоматически.

## Обязательная проверка 1.0.6

`1.0.6` нельзя считать готовым к публикации, пока exact опубликованная
`v1.0.5` не докажет следующий сценарий:

1. чистая лицензированная установка `1.0.5 (10005)`;
2. обычный вход в Workspace без открытия Admin → Updates;
3. автоматическое появление уведомления о `1.0.6`;
4. одно нажатие «Обновить до 1.0.6»;
5. получение manifest/signature/ZIP только через действующую лицензию;
6. успешные staging, backup, code switch, migrations и healthcheck;
7. транзакция `committed`;
8. maintenance marker отсутствует;
9. пользователь, роль, installation_id и прикладные данные сохранены;
10. перед успешной установкой намеренно сломанный, но корректно подписанный
    пакет `1.0.6` должен упасть на миграции после начала изменения рабочих
    файлов, автоматически вернуть `1.0.5`, получить `rollback_verified`,
    снять maintenance и сохранить пользователя, роль и `installation_id`;
11. второй корректно подписанный пакет `1.0.6` должен пройти миграции, но
    намеренно упасть на post-update healthcheck; система обязана снова
    автоматически вернуть код и БД на `1.0.5`, получить второй
    `rollback_verified`, снять maintenance и сохранить данные установки;
12. после переключения feed на исправный подписанный `1.0.6` та же установка
    должна снова показать уведомление и успешно завершить обновление одной кнопкой;
13. после успешного `1.0.6` тест имитирует оставшийся после аварийного
    завершения валидный `rollback_verified` + maintenance-marker; первый
    следующий HTTP-запрос обязан сам завершить recovery до bootstrap БД;
14. повторный запуск приложения показывает `1.0.6`.

## Совместимость

- минимальная штатная исходная версия релиза: `1.0.4 (10004)`;
- PHP: 8.1+;
- MySQL: 8.x;
- автоматическая установка требует `openssl`, `zlib`, `proc_open` и
  доступный PHP CLI;
- схема БД меняется только через compatibility migrations;
- подпись обновлений — Ed25519 с production trust root;
- право на скачивание обновлений определяется активной лицензией,
  `updates_until` и `max_version`.

## Граница поддержки

Опубликованные версии до `1.0.5` сохраняют свои исторические ограничения.
Постоянный контракт «автоматическое уведомление → одна кнопка» начинается с
`1.0.5` и должен сохраняться во всех следующих patch/feature-релизах.
