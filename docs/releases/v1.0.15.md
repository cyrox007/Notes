# Workspace Organizer 1.0.15

Дата выпуска: 2 октября 2026  
Статус: стабильный исправляющий релиз  
Код версии: `10015`

## Назначение релиза

`1.0.15` — исправляющий выпуск после эксплуатационной проверки 1.0.14. Он не меняет прикладную модель данных и не добавляет новый модуль. Цель выпуска — устранить пользовательские регрессии 1.0.14 и отдельно доказать штатное обновление существующей установки без переустановки с нуля.

Переработка палитры тёмной темы в этот релиз намеренно не входит: решение по ней принимается отдельно после дополнительной визуальной оценки.

## Messenger и переключение вкладок

При возврате во вкладку успешное обновление realtime-ticket больше не оставляет Long Poll в паузе.

WebSocket теперь считается восстановленным только после фактической авторизации. Если браузер сохранил старое соединение в состоянии OPEN/CONNECTING, но оно ещё не авторизовано, оно не блокирует новое подключение.

Long Poll остаётся полноценным резервным транспортом и должен автоматически продолжать работу, пока WebSocket не авторизован.

## Файловый менеджер без ручного F5

После создания папки, загрузки, переименования и удаления файла текущий список синхронизируется без полной перезагрузки страницы.

После частичного обновления дополнительно пересчитываются:

- поиск и сортировка;
- состояние пустого списка;
- квота персонального хранилища.

Если частичное обновление по сети невозможно, используется безопасный переход на текущий URL как запасной путь.

## Регистрация и приглашения

На странице регистрации используется настоящий SVG-знак Workspace Organizer вместо текстовой заглушки.

Подсказка номера телефона исправлена с `+49` на `+7`.

Одноразовый код приглашения получил отдельную кнопку «Копировать» и понятное состояние результата. Если Clipboard API браузера недоступен, используется совместимый запасной путь с выделением значения.

## Мобильные действия Messenger

На компактных экранах панель действий больше не занимает ширину рядом с сообщением.

Под сообщением показывается одна компактная кнопка. По нажатию действия раскрываются под сообщением и могут переноситься на несколько строк, не сжимая текст сообщения.

## Проверяемый путь обновления

Основной релизный путь:

```text
exact v1.0.14
  -> Admin → Updates
  -> подписанный stable-feed
  -> проверка manifest/signature
  -> загрузка exact ZIP
  -> backup
  -> apply
  -> migrations
  -> healthcheck
  -> commit
  -> 1.0.15 (10015)
```

Для `1.0.14 → 1.0.15` **не требуется** повторный `bootstrap-1.0.12-updater.php`, ручной ZIP, ручной SQL или переустановка приложения.

Сквозная проверка начинается с неизменяемого тега `v1.0.14`, работает в web-only режиме на PHP 8.1 с отключёнными process API и должна доказать сохранность:

- пользователя и его роли;
- лицензии и installation identity;
- заметки;
- задачи;
- файла и его байтов в private storage;
- диалога и сообщения Messenger.

Переустановка с нуля не считается проверкой upgrade-path.

Исторические 1.0.12/1.0.13 по-прежнему сначала переходят на 1.0.14 через ранее опубликованный совместимый handoff, а затем обновляются обычным последовательным путём до 1.0.15.

## Совместимость и восстановление

Минимальные требования линии 1.0 не меняются:

- PHP 8.1+;
- MySQL 8.0+ или MariaDB 10.5+;
- Windows / OSPanel и Linux/shared hosting остаются поддерживаемыми средами.

Обновление 1.0.14 → 1.0.15 использует уже исправленный updater-контур 1.0.14. При ошибке после destructive-фазы действует обычный rollback/recovery; пользовательские данные и private storage не должны требовать повторной установки.

## Что не меняется

- формат лицензии и production trust roots;
- маршруты модулей и RBAC;
- минимальная версия PHP;
- модель private storage;
- исторические теги и артефакты 1.0.12–1.0.14;
- тёмная палитра 1.0.14 до отдельного решения по её переработке.
