# Workspace Organizer v0.14.0-beta.4

`0.14.0-beta.4` добавляет управляемый доступ по ролям и совместные задачи перед вечерним beta-тестированием, сохраняя upgrade compatibility с предыдущими 0.14 prerelease.

## Роли и ограничения модулей

- Добавлен полноценный Role Manager в `/admin/roles` поверх persisted RBAC.
- Superadmin может создавать прикладные роли, назначать несколько ролей пользователям и управлять permission assignment.
- Системные роли защищены от удаления, текущий superadmin — от самоснятия ролей.
- Boolean permissions отделены от `role_module_policies`: разрешение отвечает за доступ к операции, policy — за количество, размер, частоту, типы ресурсов и feature flags.
- Shared sidebar отражает effective RBAC, поэтому недоступные роли пользователя модули не показываются в основной навигации; server-side middleware/services остаются реальной authorization boundary.

### Policy coverage

- **Files:** общая ёмкость роли, максимальный размер одного файла, разрешённые расширения, создание папок.
- **Messenger:** частота сообщений, размер/типы вложений, создание групп, число участников и voice messages.
- **Notes:** число заметок, размер/типы и количество вложений, sharing.
- **Tasks:** число личных задач, создание shared boards, число собственных досок, размер команды и task assignment.

## Общие доски задач

- Личные Tasks остались совместимыми с прежней ownership-моделью.
- Добавлены отдельные shared boards для выбранных участников или динамической аудитории `all_active`.
- Доступ к конкретной доске определяется board ACL (`owner`, `manager`, `member`, `viewer`) поверх глобального `tasks.use`.
- Добавлены shared task items, несколько исполнителей, priority/due date/status и отдельный Kanban.
- Drag-and-drop обновления защищены CSRF и выполняются через ownership/board-ACL checked service path.

## Админка / UX

- Исправлена сетка формы создания пользователя: отдельная responsive layout вместо пятиколоночной сетки редактора custom fields.
- Role Manager получил собственную адаптивную раскладку для permissions и module policies.
- Persisted значения permission/policy теперь корректно отображаются как выбранные после повторного открытия страницы.

## Database / upgrade

- Canonical fresh contract расширен до **32 обязательных таблиц**.
- `database/tasks_schema.sql` теперь содержит canonical shared-board tables: `task_boards`, `task_board_members`, `task_board_items`, `task_board_assignees`.
- `database/access_control_schema.sql` содержит `role_module_policies`.
- Existing installations обновляются additive migrations `20260915_role_module_policies.sql` и `20260915_shared_task_boards.sql` через `php bin/migrate.php`.
- Production healthcheck проверяет весь 32-table contract.

## Перед обновлением

Как и для предыдущих beta, перед upgrade существующей установки сделайте backup MySQL, `PRIVATE_STORAGE_PATH` и действующих crypto keys. Затем выполните:

```bash
php bin/migrate.php --status
php bin/migrate.php
php bin/healthcheck.php
```

Для fresh install вручную импортировать SQL не требуется — web-installer использует canonical schemas.

## Release direction

Это prerelease beta-линейки. Для `1.0.0` остаются отдельными задачами полный отказ от сторонних runtime-библиотек, installation-wide signed licensing, signed staged updater/recovery, module isolation и дополнительные production hardening/evidence.
