# Проверенный кандидат обновления

Этот слой подготавливает уже проверенный подписанный пакет к последующему переключению live-кода **без изменения рабочей установки и БД**.

## Предусловия

До создания кандидата должны быть выполнены:

- manifest/signature/package проверены;
- ZIP прошёл аудит;
- staging находится вне application tree;
- текущая транзакция владеет maintenance;
- проверенный rollback backup создан;
- журнал находится в ожидаемом состоянии;
- destructive boundary ещё не пересечена.

При нарушении любого условия операция завершается закрыто.

## Хранилище

Рекомендуется внешний путь:

```dotenv
UPDATE_RELEASE_PATH=/var/lib/notes/update-releases
```

Если он не задан, используется безопасный каталог под `PRIVATE_STORAGE_PATH`.

Web-сервер не должен раздавать этот каталог.

## Создание

```bash
php bin/update_candidate.php --transaction=<id>
```

Кандидат извлекается в отдельный каталог, после чего строится проверяемый manifest дерева. Симлинки, path traversal и неожиданные структуры запрещены.

## Назначение

Release candidate нужен только как проверенный источник нового release-owned кода для controlled switch. Он не является recovery artifact.

После destructive boundary авторитетным источником rollback остаётся pre-update backup.

## Retention

После terminal-state старые кандидаты могут удаляться отдельной retention-процедурой. Удаление не должно затрагивать активную транзакцию или необходимый rollback backup.
