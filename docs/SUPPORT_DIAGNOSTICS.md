# Сервисная диагностика Notes

## Назначение

Notes формирует диагностический ZIP по явному действию суперадминистратора. Пакет предназначен для разбора проблем обновления, recovery, PHP-runtime, файловой системы и БД на ограниченном виртуальном хостинге.

Постоянного удалённого доступа к установке нет. Каждый пакет является отдельным неизменяемым снимком.

## Состав ZIP

Текущая схема пакета: `2`.

Архив содержит:

- `manifest.json` — версия схемы, идентификатор пакета, версия Notes, SHA-256 и размеры остальных файлов;
- `hosting-profile.json` — безопасный профиль PHP, OPcache, process API, файловых возможностей, режима updater и объявленных MySQL-привилегий;
- `health.json` — результат штатной web-проверки состояния;
- `maintenance.json` — состояние режима обслуживания;
- `service-events.json` — последние сервисные события updater/recovery/runtime/БД;
- `updater-transactions.json` — последние очищенные журналы updater;
- `security-summary.json` — агрегированная security-сводка;
- `privacy.json` — явный контракт того, какие данные не включаются;
- `README.txt` — краткое описание архива.

ZIP создаётся собственным writer в режиме STORE и не требует PHP-расширения `zip`.

## Профиль хостинга

Вместо полного `phpinfo()` сохраняется только allowlist параметров, полезных для диагностики:

- версия PHP, SAPI и семейство ОС;
- `memory_limit`, `max_execution_time`, `max_input_time`;
- лимиты загрузки;
- наличие `open_basedir` без раскрытия физических путей;
- список `disable_functions`;
- доступность process API;
- параметры OPcache, влияющие на переключение кода;
- наличие обязательных расширений;
- фактическая возможность создать файл, взять `flock`, переименовать, заменить и удалить файл во внешнем private storage;
- версия MySQL/MariaDB;
- безопасная карта привилегий текущего пользователя БД, включая `CREATE ROUTINE` и `ALTER ROUTINE`, без логина, host и исходного текста `SHOW GRANTS`;
- выбранный режим updater: обычный или web-only.

Полный вывод `phpinfo()` в пакет не включается.

## Конфиденциальность

Пакет не содержит:

- `.env`;
- дамп БД;
- заметки, сообщения, файлы и другой пользовательский контент;
- пароли;
- cookies и сессии;
- CSRF-значения;
- лицензионные токены;
- ключи шифрования;
- приватные ключи подписи.

Из строк ошибок удаляются известные секреты, абсолютные пути приложения/private storage и MySQL identity в сообщениях вида `command denied to user`.

## Одноразовый доступ

Суперадминистратор создаёт пакет в **Admin → Обновления → Диагностика поддержки**.

Разрешение:

- действует 15 минут по умолчанию;
- не может действовать дольше 30 минут;
- хранит только SHA-256 токена;
- прекращает действие после первого успешного скачивания;
- после выдачи удаляет grant и сам ZIP;
- не даёт shell, live-tail логов или доступа к произвольным файлам.

Для браузера поддерживается одноразовая ссылка:

`GET /support-diagnostics?token=<одноразовый-токен>`

Для будущей интеграции jsint предпочтителен вариант без токена в URL:

`GET /support-diagnostics`

с заголовком:

`Authorization: Bearer <одноразовый-токен>`

Ответ:

- `Content-Type: application/zip`;
- `X-Notes-Diagnostics-Schema: 2`;
- `X-Notes-Diagnostics-Bundle-Id: <id>`;
- `X-Notes-Diagnostics-SHA256: <sha256>`.

Получатель обязан проверить HTTP-статус, SHA-256 архива, затем `manifest.json` и SHA-256 каждого JSON-файла перед разбором.

## Будущая интеграция с jsint

Рекомендуемый поток:

1. пользователь в Notes явно создаёт диагностический пакет;
2. Notes передаёт пользователю или доверенному jsint одноразовый токен;
3. jsint выполняет HTTPS GET с Bearer-токеном;
4. jsint проверяет `X-Notes-Diagnostics-Schema`, SHA-256 ответа и manifest;
5. архив сохраняется как неизменяемое вложение обращения поддержки;
6. повторное скачивание тем же токеном невозможно.

Notes не должен самостоятельно открывать постоянный исходящий канал к jsint, а jsint не должен иметь постоянный credential на чтение установки.
