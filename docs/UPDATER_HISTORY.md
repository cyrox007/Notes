# История развития updater

> **Архив.** Этот документ нужен для понимания совместимости старых установок и не описывает обычный пользовательский путь 1.0.13.

## Beta4 → ранняя 1.0

Опубликованная Beta4 была выпущена до появления полного подписанного updater runtime, поэтому первый переход требовал отдельного trusted bootstrap runner из нового релизного bundle.

Подробная историческая процедура сохранена в [UPDATER_BETA4_BOOTSTRAP.md](UPDATER_BETA4_BOOTSTRAP.md).

## 1.0.1 → 1.0.2

1.0.1 уже содержала основные transaction/apply boundaries, но до появления более удобной wrapper/readiness/retention обвязки. Exact upgrade/rollback drill этой пары сохранён в CI как регрессионное доказательство раннего updater.

## 1.0.4/1.0.5 → 1.0.6

Реальная OSPanel-проверка выявила Windows file-lock, rollback JSON dump, stale credential и maintenance/recovery проблемы. Причины и переработка зафиксированы в [UPDATER_1.0.6_REWORK.md](UPDATER_1.0.6_REWORK.md).

## Современный путь

Для текущей линии используется единый пользовательский процесс из [UPDATES.md](UPDATES.md). Старые bootstrap-сценарии не должны попадать в обычную инструкцию пользователя, кроме аварийной совместимости с действительно старой установкой.
