# Совместимость с виртуальным хостингом

Документ фиксирует минимальный контракт Workspace Organizer для обычного виртуального PHP-хостинга и отделяет обязательные возможности от серверных ускорений.

Цель линии 1.0: установка, обновление, основные модули и Messenger должны работать без root-доступа, systemd, Supervisor, Composer, входящего WebSocket и запуска дочерних процессов из PHP.

## Базовый профиль

Минимально поддерживаемый профиль:

- PHP 8.1+;
- MySQL/MariaDB с доступом пользователя приложения к своей базе;
- расширения PHP, которые проверяет web-installer;
- обычные HTTPS/HTTP-запросы;
- запись в каталог приложения на этапе установки и обновления;
- отдельный writable private storage вне document root;
- исходящие TLS-соединения PHP для встроенного updater;
- возможность удерживать один HTTP-запрос Long Poll несколько секунд;
- достаточное число PHP workers для числа одновременно активных пользователей.

PHP CLI, Cron, WebSocket, process manager и process API не входят в обязательный минимум.

## Что считается обязательным

| Возможность | Статус | Причина |
| --- | --- | --- |
| PHP 8.1+ | обязательно | минимальная версия runtime |
| mysqli + pdo_mysql | обязательно | рабочая БД и web-installer |
| mbstring | обязательно | строки и пользовательские данные |
| sodium | обязательно | шифрование данных и подписи updater |
| openssl | обязательно | TLS stream для защищённого доступа к серверу обновлений |
| zlib | обязательно | работа с пакетами обновлений |
| fileinfo | обязательно | безопасная проверка загружаемых файлов |
| gd | пока обязательно | обработка аватаров |
| Argon2id | обязательно | хранение паролей |
| random_bytes | обязательно | секреты, nonce и токены |
| writable private storage вне web-root | обязательно | пользовательские файлы, логи и updater state не должны быть публичными |
| session_write_close + usleep | обязательно для Messenger | безопасный Long Poll без блокировки остальных запросов сессии |

## Что не должно блокировать установку

| Возможность | Роль |
| --- | --- |
| proc_open | только ускоренный изолированный режим updater |
| exec / shell_exec / system / passthru / popen | не требуются штатному web-runtime |
| PHP CLI | нужен только серверным операциям и WebSocket-ускорителю |
| pcntl | только необязательный Unix daemon mode WebSocket |
| stream_socket_server / stream_select | только native WebSocket-ускоритель |
| systemd / Supervisor | только автоматический перезапуск WebSocket process |
| WebSocket reverse proxy | только низколатентный fast path |
| Cron | полезен для эксплуатационных задач, но не является условием запуска приложения |
| Composer/vendor | production bundle самодостаточен |

Web-installer показывает эти возможности отдельным разделом и не превращает их отсутствие в ошибку установки.

## Messenger

### Основной transport

HTTP Long Poll является основным обязательным realtime transport.

Клиент:

1. запускает Long Poll сразу;
2. параллельно пробует WebSocket, если он включён;
3. после успешной WebSocket-авторизации временно останавливает Long Poll;
4. при любом разрыве WebSocket немедленно продолжает через Long Poll;
5. восстанавливает зависший poll через watchdog;
6. не требует reload страницы для смены transport.

Через Long Poll должны работать те же функции, что через WebSocket:

- список диалогов;
- текстовые сообщения;
- редактирование и удаление;
- медиа, файлы и голосовые сообщения;
- группы;
- пересылка;
- реакции;
- доставка и прочтение;
- typing/activity;
- архив, закрепление и mute;
- глобальный счётчик непрочитанных;
- уведомления внутри открытого Workspace.

WebSocket не должен открывать отдельные функции. Он только уменьшает задержку и расход PHP workers.

### Несколько вкладок

Глобальный transport координируется между вкладками одного browser-origin. Один владелец lease держит Long Poll/WebSocket, остальные вкладки получают общее состояние через межвкладочный канал.

Скрытие вкладки само по себе не должно отключать transport. Lease освобождается при закрытии/уходе страницы либо после аварийного истечения.

Это критично для shared hosting: один пользователь с пятью открытыми вкладками не должен занимать пять PHP workers.

### Ограничение по workers

Long Poll держит PHP worker на время ожидания. На небольших тарифах число workers/entry processes может быть низким.

Практическая граница:

- маленькая команда и обычный shared hosting — Long Poll является штатным режимом;
- рост числа одновременно активных пользователей — повод включить WebSocket или перейти на тариф с большим числом workers;
- WebSocket в этом случае является оптимизацией масштаба, а не требованием функциональности.

По умолчанию Long Poll ждёт до 15 секунд. Installer уменьшает timeout под ограниченный max_execution_time, но не ниже безопасного минимума 5 секунд. При max_execution_time меньше 7 секунд installer показывает предупреждение.

## Встроенный updater

Updater не должен требовать:

- proc_open;
- exec/shell_exec/system;
- PHP CLI;
- cURL;
- allow_url_fopen.

Для применения обновления без process API используется пошаговый web-режим с тем же transaction journal, staging, backup, rollback и recovery.

Для загрузки подписанного релиза используется собственный HTTPS transport через PHP streams. Для него нужны:

- openssl;
- stream_socket_client;
- stream_context_create;
- DNS через dns_get_record или gethostbynamel;
- исходящий TCP/443 к серверу обновлений.

Отсутствие proc_open не является ошибкой readiness. Отсутствие исходящего TLS transport означает, что автоматическое получение релизов недоступно, хотя сама установка приложения может работать.

## Private storage и open_basedir

Workspace Organizer намеренно требует private storage вне document root.

Это может стать единственным жёстким ограничением на особенно закрытом shared hosting:

- если аккаунт даёт writable каталог выше public_html/httpdocs — профиль поддерживается;
- если open_basedir разрешает только document root и нельзя выделить непубличный каталог — такой тариф не соответствует security contract.

Не следует обходить это размещением пользовательских файлов внутри web-root только ради совместимости.

## База данных

Installer умеет работать с заранее созданной базой.

CREATE DATABASE не является обязательным правом, если пользователь хостинга заранее создаёт пустую БД в панели и передаёт её параметры мастеру установки.

Нужны права на таблицы, индексы, INSERT/UPDATE/DELETE и миграции внутри собственной базы.

## Лимиты загрузок

PHP upload_max_filesize и post_max_size могут быть ниже лимитов приложения.

Это не мешает запуску Workspace Organizer, но фактический максимальный размер файлов определяется меньшим из:

- лимита PHP;
- лимита web-server;
- лимита Workspace Organizer.

Для дешёвых тарифов installer должен как минимум предупреждать, если PHP-лимит ниже продуктового лимита вложений. Автоматическое согласование этих лимитов остаётся отдельным улучшением.

## Ограничения, которые не решаются приложением

Workspace Organizer не может программно обойти:

- запрет исходящих HTTPS-соединений;
- отсутствие writable private storage вне web-root;
- слишком малое число PHP workers для фактической одновременной нагрузки;
- принудительный timeout PHP меньше минимального Long Poll;
- отсутствие обязательных PHP extensions;
- ограничения MySQL-пользователя на собственные таблицы;
- лимиты диска, inode, памяти и I/O самого тарифа.

## Работа после закрытия браузера

Long Poll и WebSocket работают, пока открыта хотя бы одна вкладка Workspace.

Получение пользовательских уведомлений после полного закрытия всех вкладок требует отдельного слоя Service Worker + Web Push. Это не часть transport parity Messenger 1.0.9 и должно реализовываться отдельно.

## Проверки CI

Shared-hosting контракт должен включать:

- web-install без vendor/Composer;
- web-install с отключёнными proc_open, exec, shell_exec, system, passthru и popen;
- web-install с отключёнными stream_socket_server/stream_select и pcntl;
- WS_ENABLED=0 по умолчанию на hosting-профиле;
- работа Messenger через Long Poll при WebSocket, зависшем навсегда без open/error/close;
- глобальные unread/уведомления через Long Poll вне страницы Messenger;
- один transport на набор вкладок;
- updater без обязательного proc_open/PHP CLI.

## Внешние наблюдения по shared hosting

Аудит 29 сентября 2026 подтверждает, что ограничения различаются между провайдерами:

- некоторые web-hosting тарифы разрешают только исходящие WebSocket и требуют VPS для входящего WebSocket;
- process-функции PHP нередко отключены по умолчанию;
- Cron/PHP CLI на части хостингов доступны, но это не означает возможность держать постоянный daemon;
- CloudLinux-подобные тарифы ограничивают entry processes/PHP workers, поэтому длительные HTTP requests имеют реальную стоимость;
- лимиты max_execution_time, memory_limit, upload/post size задаются тарифом и могут быть изменяемы только в пределах максимума провайдера.

Поэтому compatibility contract проекта строится от обычного HTTP/PHP, а не от серверных возможностей конкретной панели.
