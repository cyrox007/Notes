- версия: `1.0.14`;
- код версии: `10014`;
- статус приложения: `stable`;
- кодовый релизный PR: #328, `hotfix/1.0-web-updater-recovery → master`;
- основной путь обновления: `1.0.12/1.0.13 → одноразовый совместимый updater-handoff → штатный подписанный web-updater → 1.0.14`;
- handoff меняет только updater-контур и не меняет версию приложения или БД;
- `min_source_version_code` во внешнем реестре: `10012`;

Exact-head матрица подтверждает обновление, rollback и recovery с опубликованных 1.0.12 и 1.0.13 на PHP 8.1, включая web-only режим после handoff и MySQL-пользователя без повышенных административных привилегий. Windows/PHP, браузерные lifecycle, HTTPS/WSS, Long Poll, installation/license, release evidence и release gate также завершены успешно.

### Диагностика поддержки

Начиная с 1.0.14 суперадминистратор может сформировать обезличенный ZIP или отправить его напрямую в активированный JSInteractive control plane. Пакет содержит безопасный профиль хостинга, health/maintenance, сервисные события и журналы updater/recovery, но не содержит пользовательские документы, `.env`, пароли, лицензионные токены или приватные ключи.

### Эксплуатационный ввод

После публикации GitHub Release оператор JSInteractive:

1. регистрирует `v1.0.14` и её неизменяемые артефакты в реестре релизов;
2. задаёт `min_source_version_code = 10012`;
3. публикует stable-feed;
4. проверяет, что лицензированная установка видит 1.0.14;
5. выполняет контрольный переход с опубликованной 1.0.12 или 1.0.13 через handoff и штатный web-updater.

## Что вошло в 1.0.13

### Лицензионный состав модулей

Каждый встроенный прикладной модуль имеет собственное `license.feature`:

- `workspace.admin`;
- `workspace.notes`;
- `workspace.tasks`;
- `workspace.files`;
- `workspace.messenger`;
- `workspace.profile`.

Модуль запускается только если действующая подписанная лицензия явно содержит его feature. Пустой или отсутствующий список `features` не даёт неявного полного доступа.

Если разрешения нет:

- операторский `configured_state` сохраняется;
- фактическое состояние становится `unlicensed`;
- provider, capability и маршруты не загружаются;
- соседние модули не получают точки интеграции;
- данные модуля не удаляются.

### Управление модулями

Суперадминистратор управляет разрешёнными лицензией модулями через **Admin → Модули**.

- отключение модуля не удаляет данные;
- разрешения ролей и ролевые политики сохраняются;
- нелицензированные модули не показываются в панели управления;
- Admin является обязательным системным модулем и не может быть отключён операторским переключателем;
- при отсутствии `workspace.admin` остаётся независимая core-страница восстановления лицензии.

### Межмодульная изоляция

Отключённый или нелицензированный модуль:

- не входит в `enabledComposition()`;
- не отображается в общей навигации и на главной;
- не оставляет пользовательские действия в Messenger и Profile;
- не регистрирует свои HTTP-маршруты и runtime-provider;
- не оставляет фоновой WebSocket-службы Messenger после отзыва соответствующего разрешения.

### Обновление

Проверяемый переход релизной матрицы:

`1.0.12 → встроенный подписанный updater → 1.0.13`.

Миграция `20260930_module_entitlements.sql` добавляет состояние `unlicensed`. Обновлятор учитывает короткое окно до применения миграции, сохраняет возможность rollback и корректно останавливает WebSocket, если Messenger после обновления больше недоступен.
