## Состав релизного кандидата

### Messenger

- объединены исправления компактной ширины из #314/#315;
- восстановлены реальные аватары;
- имя и аватар личного собеседника ведут в его профиль;
- исправлен публичный профиль;
- Long Poll остаётся полноценным рабочим транспортом;
- проверка самовосстановления согласована с отображением активного транспорта.

### File Manager

- центр «Общий доступ» показывает созданные ссылки и их состояние;
- активную ссылку можно скопировать, открыть, ограничить сроком или отозвать;
- отзыв не удаляет исходный объект;
- поддержана публикация папки одним URL с безопасной навигацией только внутри опубликованного дерева;
- папка открывается кликом по всей карточке;
- максимальный размер одного файла настраивается через Admin;
- Admin диагностирует конфликт лимита Workspace с PHP и известным пределом веб-сервера и показывает руководство по исправлению.

### Profile

- добавлен каталог пользователей с поиском и постраничным выводом;
- каталог и Messenger ведут в профиль пользователя;
- настройки собственного профиля используют термин «Видимость профиля»;
- видимость профиля отделена от ссылок общего доступа File Manager.

### Проверки

- browser E2E покрывает создание общей ссылки, папку, вложенный файл, отзыв и истечение;
- релизный переход должен подтверждать штатное обновление `1.0.11 → 1.0.12`;
- любые изменения после принятого SHA требуют повторного exact-head CI.

## Что осталось до публикации

Релизный код и автоматические проверки завершены:

- PR #318 принят в `master`;
- exact HEAD перед merge прошёл **65/65** проверок;
- штатный updater `1.0.11 → 1.0.12` подтверждён на PHP 8.1 и 8.3;
- проверены отказ миграции, отказ post-health после успешной миграции, rollback/recovery и восстановление после прерывания;
- browser lifecycle Files/Profile/Messenger и затронутые Windows/OSPanel-контракты прошли в той же матрице;
- merge-коммит имеет то же дерево исходников, что и проверенный exact HEAD. Отдельный push-набор workflow для merge-коммита в репозитории не запускается.

До фактической публикации остаются операторские действия:

1. Создать неизменяемый тег `v1.0.12` на принятом релизном `master`.
2. Собрать hosting package и опубликовать GitHub Release.
3. Сформировать и подписать stable-feed для `1.0.12`.
4. Выполнить контрольное обновление обычной лицензированной установки через опубликованный stable-feed.
