# Статус релизной линии Workspace Organizer 1.0.x

> **Обновлено 30 сентября 2026.** Последний опубликованный стабильный выпуск — `v1.0.11`. Текущий релиз-кандидат — `1.0.12 (10012)` в ветке `release/1.0.12`.

## Текущее состояние 1.0.12

- версия: `1.0.12`;
- код версии: `10012`;
- статус приложения: `stable`;
- исходная опубликованная версия для штатного обновления: `v1.0.11`;
- релизная ветка: `release/1.0.12`;
- публикация тега `v1.0.12`: **ещё не выполнена**;
- `master` до принятия релизного кандидата остаётся опубликованной 1.0.11.

## Состав релизного кандидата

### Messenger

- объединены исправления компактной ширины из #314/#315;
- восстановлены реальные аватары;
- имя и аватар личного собеседника ведут в его профиль;
- исправлен публичный профиль;
- Long Poll остаётся полноценным рабочим транспортом;
- проверка самовосстановления согласована с отображением активного транспорта.

### File Manager

- центр «Общий доступ» показывает созданные ссылки и их состояние;
- активную ссылку можно скопировать, открыть, ограничить сроком или отозвать;
- отзыв не удаляет исходный объект;
- поддержана публикация папки одним URL с безопасной навигацией только внутри опубликованного дерева;
- папка открывается кликом по всей карточке;
- максимальный размер одного файла настраивается через Admin;
- Admin диагностирует конфликт лимита Workspace с PHP и известным пределом веб-сервера и показывает руководство по исправлению.

### Profile

- добавлен каталог пользователей с поиском и постраничным выводом;
- каталог и Messenger ведут в профиль пользователя;
- настройки собственного профиля используют термин «Видимость профиля»;
- видимость профиля отделена от ссылок общего доступа File Manager.

### Проверки

- browser E2E покрывает создание общей ссылки, папку, вложенный файл, отзыв и истечение;
- релизный переход должен подтверждать штатное обновление `1.0.11 → 1.0.12`;
- любые изменения после принятого SHA требуют повторного exact-head CI.

## Что осталось до публикации

1. Завершить полный CI на точном HEAD `release/1.0.12`.
2. Исправить все красные обязательные проверки без отключения защитных сценариев.
3. Подтвердить штатный updater-переход `1.0.11 → 1.0.12`, миграцию и rollback/recovery.
4. Выполнить затронутые Windows / OSPanel проверки.
5. Открыть и принять единый релизный PR `release/1.0.12 → master`.
6. Дождаться зелёного Stable release gate уже на итоговом `master`.
7. Создать неизменяемый тег `v1.0.12`, hosting package и подписанный stable-feed.
8. Проверить установку обновления на обычной лицензированной установке.

## Ветки и старые PR

Релизный источник 1.0.12 — только `release/1.0.12`. Ветки #314, #315, #316 и #317 являются источниками отдельных изменений, которые сводятся в релизную ветку; после подтверждения эквивалентности и зелёного релизного PR они не должны использоваться как альтернативные источники выпуска.
