# Локальные установки разного состава на общей БД

Если новая и старая копии сайта намеренно используют одни таблицы, новая копия может зарегистрировать модуль, которого нет в старом пакете. По умолчанию отсутствие зарегистрированного модуля остаётся ошибкой запуска.

Только для такого намеренного сосуществования в `.env` старой копии можно указать точные идентификаторы модулей другой установки:

```dotenv
MODULE_SHARED_DB_EXTERNAL_MODULES=defects,work-permits
```

Эти строки реестра сохраняются без отключения и удаления. Их код не загружается и маршруты в старой установке не добавляются. Остальные отсутствующие зарегистрированные модули по-прежнему останавливают запуск. После выравнивания состава установок настройку можно убрать.

Это не изоляция установок: пользовательские данные, миграции и состояние общих модулей остаются общими. Для независимых установок следует использовать разные префиксы таблиц.
