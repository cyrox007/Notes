# Проверка доступа Tasks двумя браузерными пользователями

## Назначение

Испытание проверяет реальный маршрут **Tasks API** без подмены HTTP-ответов. Два независимых контекста Chromium имеют разные действующие ключи доступа и обращаются к двум независимым PHP-процессам, подключённым к одной временной MySQL/MariaDB. Благодаря этому одновременно проверяются серверные роли, транзакции, версии задач и журнал команд.

Последовательность проверки:

1. Владелец и руководитель одновременно читают закрытую доску.
2. Руководитель изменяет задачу, а владелец со старой версией получает HTTP 409. Повтор команды с тем же идентификатором не создаёт второе изменение.
3. Оба пользователя параллельно сохраняют разные изменения с одной и той же версией. Только одно применяется, другое получает 409.
4. Владелец понижает руководителя до наблюдателя: чтение остаётся доступным, запись получает 403.
5. Пока браузер наблюдателя остаётся открытым, владелец удаляет его из участников. Чтение закрытой доски и изменение задачи возвращают 404, **несмотря на действующий ключ API**.
6. Повтор старой успешной команды после отзыва доступа тоже возвращает 404. Сохранённая квитанция не становится обходом прав.
7. После повторного приглашения прежняя версия конфликтует, а новая корректная команда проходит.
8. Итоговые версия, состояние задачи, роли и HTTP-коды дополнительно подтверждаются непосредственным чтением тестовой БД.

## Запуск

В GitHub Actions запускается матрица MySQL 8.4 / MariaDB 11.4. Локально нужны PHP 8.3, Node.js, установленный Chromium Playwright и **изолированная БД с `test` в имени**. Пример вызова после установки Playwright:

```bash
DBNAME=workspace_two_users_test DBHOST=127.0.0.1 DBUSER=workspace DBPASS=workspace \
    python3 tests/integration/tasks_board_live_two_users_12.py
```

Тест создаёт и очищает собственные таблицы; ни при каких обстоятельствах не направляйте его на рабочую базу.

## Точные границы приёмки

Это **настоящие браузерные HTTP-запросы к штатным контроллерам Tasks API**, а не имитация результата серверных команд. Авторизация выполняется двумя разными ключами Bearer Tasks API. Важное ограничение: такое испытание **не проверяет вход двух пользователей через форму сайта, сеансовые куки, защиту CSRF или отображение страниц `/tasks/boards` после отзыва доступа**. Для полной приёмки веб-интерфейса эти сценарии требуется добавить отдельно на развёрнутом приложении с реальной сессионной авторизацией.

Секреты тестовых ключей не печатаются в отчёте. Скрипт очищает тестовую БД даже при ошибке проверки. Комментарии и сообщения об ошибках сохраняются на русском языке.
