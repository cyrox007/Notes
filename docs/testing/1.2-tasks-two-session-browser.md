# Приёмка общей доски двумя браузерными сеансами

## Цель

Это дополнение к [проверке двух браузерных пользователей через API](../testing/1.2-tasks-two-users-live-http.md). Здесь используется **настоящая форма авторизации сайта**, куки двух независимых сеансов, штатная HTML-страница общих досок и CSRF-проверка изменяющих форм.

Временный стенд создаёт настоящую MySQL 8.4, канонические таблицы Notes, временную CI-лицензию, двух пользователей и закрытую командную доску. Два Chromium-сеанса обращаются к одному запущенному приложению в подкаталоге `/workspace`; один пользователь работает на обычной ширине экрана, второй — на мобильной ширине 390 пикселей.

Проверяется:

1. Независимый вход двух пользователей через форму `/auth/login/`.
2. Отображение одной общей задачи и версии 1 в обеих сессиях.
3. Изменение статуса вторым пользователем без перезагрузки страницы, запись новой версии в БД.
4. Конфликт HTTP 409 при сохранении устаревшей версии владельцем.
5. Удаление участника через настоящую форму владельца, включая CSRF.
6. Попытка изменения со старой уже открытой страницы участника после отзыва доступа: сервер обязан вернуть 403/404.
7. При последующей навигации отозванный пользователь не должен получить прежнюю карточку.
8. Повторное приглашение через форму владельца возвращает доступ к карточке с актуальной версией.
9. Отдельная проверка итоговых версии и статуса задачи непосредственно в БД.

При ошибке CI сохраняет журнал PHP-сервера и приложения. Конфиденциальные временные пароли маскируются средствами GitHub Actions.

## Границы

Это полноценная проверка сеансового входа и HTTP-проверок доступа на временном браузерном стенде, но не ручная приёмка на устройстве пользователя и не стресс-тест. Права проверяются сервером, поэтому уже открытая страница не становится разрешением на изменение задачи после отзыва участия.

Никакой доступ к настоящему рабочему серверу для теста не требуется. Временные пароли, ключи и данные создаются только на машине GitHub Actions.

## Запуск

Ветка `1.2` проверяется сценарием `.github/workflows/tasks-board-two-sessions-live-12.yml` с PHP 8.3 и Chromium. При локальном воспроизведении используйте отдельную тестовую базу данных и временную лицензию: сценарий создаёт и изменяет содержимое БД.
