# Notes 1.2 — местные рабочие сутки в нарядах

## Правило

Все зарегистрированные моменты времени в базе остаются в UTC.
**Календарные сутки для перерыва, окончания дня и нового допуска**
вычисляются по часовому поясу IANA, который указан для организации
при выдаче документа. Например, `Europe/Amsterdam`, `Europe/Moscow`,
`Asia/Yekaterinburg` или `America/New_York`.

Это устраняет ошибку при переходе через местную полночь до или после
полуночи UTC. Изменения зимнего и летнего времени учитываются с помощью
системной базы часовых поясов PHP, без фиксированных смещений.

В управлении справочниками администратор может указать и изменить
`time_zone` организации. Сервер допускает только настоящие идентификаторы
IANA и использует контроль версии; смена записывается в историю
`work_permit_reference_history`. Для другой записи справочника эту
операцию выполнить нельзя.

**На момент выдачи** часовой пояс копируется в
`work_permit_issuances.time_zone`. Позднейшая правка организации
не меняет правило уже выданного наряда, не переписывает его историю
и не влияет на идемпотентный повтор старой команды. Часовой пояс
показывается в PDF-копии рядом со сроками.

Распоряжения также проверяются по местной дате начала и окончания:
пересечь полночь UTC разрешено, если в месте работы ещё не наступили
следующие календарные сутки.

## Совместимость

Миграция `20261024_work_permits_local_day.sql` добавляет два поля
с `DEFAULT 'UTC'`: организации и снимок выдачи. Все существующие
организации и документы продолжают использовать UTC, пока управляющий
явно не установит другой часовой пояс для будущих документов.
Существующие команды, номера, периоды и PDF не пересчитываются.

**Важно:** поле браузера `datetime-local` показывает время
устройства пользователя; клиент переводит его в UTC перед передачей.
Сутки сервера рассчитываются по поясу документа, а не устройства.
Если пользователь находится в другом часовом поясе, он должен
вводить фактический момент с учётом этого различия. Отдельный
режим ввода «время объекта» и полномасштабная приёмка временных
зон интерфейса требуют дополнительной работы.

## Проверка

```bash
php tests/integration/work_permits_local_day_mysql_12.php
```

Сценарий сначала выполняет все предыдущие тесты полного жизненного
цикла, затем проверяет новую границу местных суток: первичный допуск
до местной полуночи, запрет остановки уже после полуночи при той же
UTC-дате, дневной допуск после полуночи при ещё той же UTC-дате,
безопасный повтор команды, изменение пояса организации, сохранение
снимка и открытие следующего дня. Проверяются весенний и осенний
переходы часов, неизвестные идентификаторы и распоряжение через
UTC-полночь, которое не пересекает местную.

Дальнейшие обязательные работы: формальная сверка PDF с нормативными
образцами, многопользовательская нагрузочная приёмка нарядов и
полный пользовательский режим отображения времени объекта.
