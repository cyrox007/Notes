# Notes 1.2 — совместимость способов SMTP-авторизации

## Исправление

Ранее собственный почтовый транспорт Notes всегда отправлял команду
`AUTH LOGIN`, даже если почтовый сервер не объявлял этот механизм.
Серверы, поддерживающие только `AUTH PLAIN`, не могли принять пробное письмо.

Теперь SMTP-транспорт читает расширения из многострочного ответа `EHLO`.
После установки `STARTTLS` возможности считываются **повторно**:
до и после шифрования сервер может объявлять разный набор команд.

- Если объявлен `LOGIN`, применяется прежний сценарий с двумя ответами.
- Если `LOGIN` отсутствует, но объявлен `PLAIN`, используется
  стандартное сообщение `AUTH PLAIN` с обязательным кодированием полей.
- Если сервер не объявил ни одного поддерживаемого способа, пароль
  **не отправляется**: возвращается безопасный код `smtp_auth_unavailable`.
- Любой способ авторизации с логином допускается только с TLS/SSL.
- При отказе в авторизации программа не перебирает другие механизмы,
  чтобы не увеличивать число неудачных входов.
- Серверные строки `EHLO` не сохраняются в очереди или журналах.

Изменение применяется к обычным заданиям очереди, пробной кнопке
в административном интерфейсе и явной команде
`bin/notifications_smtp_probe.php --config-id=N --user-id=N --send`.

## Проверки

```bash
php -l app/services/notifications/SocketSmtpTransport.php
php tests/integration/notification_smtp_auth_methods_12.php
php tests/integration/smtp_socket_transport_contract.php
php tests/integration/notification_smtp_guidance_12.php
```

Проверяются ответы `EHLO`, выбор `PLAIN` или `LOGIN`,
кодирование данных авторизации и отсутствие отправки секрета,
если сервер не предложил подходящий способ.

## Проверка на установленном сайте

1. Проверьте у почтового провайдера хост, порт и режим TLS/SSL.
2. Убедитесь, что переменная окружения с SMTP-паролем доступна
   тому процессу PHP, который фактически отправляет уведомления.
3. Выполните пробную отправку в админке или штатную консольную
   проверку. Не выводите пароли, адреса и полный ответ сервера в журнал.
4. Если получен `smtp_auth_unavailable`, сопоставьте порт, TLS и
   поддерживаемые сервером способы авторизации.
5. Если сервер принял письмо, проверьте его появление в контролируемом
   почтовом ящике и папке спама.

**Ограничение:** проверка в CI не доказывает реальное получение письма
и не устанавливает автоматически причину неисправности установленного сайта.
Задача #429 остаётся открытой до реальной сквозной проверки.
