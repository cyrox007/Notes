# Проверка исторических миграций и восстановления 1.1 → 1.2

Испытательный стенд сравнивает все миграции, опубликованные в неизменяемом Git-теге v1.1.0, с миграциями проверяемой ветки 1.2. Проверяется точный список, порядок и SHA-256 исходных байтов каждого SQL-файла. Повторная компиляция или нормализация переводов строк не скрывают изменения исторического SQL.

В отдельном задании MySQL 8.4 создаётся тестовая база и две записи, снимается согласованная резервная копия, моделируются потеря записей и изменение структуры, затем база восстанавливается из копии. Проверяется наличие исходных данных и отсутствие повреждающего столбца.

Команды запуска: php tests/integration/upgrade_11000_historical_integrity.php /путь/к/v1.1.0. Для испытания восстановления используется сценарий GitHub Actions в .github/workflows/upgrade-11000-backup-restore.yml.

**Ограничение:** проверка восстановления использует небольшую искусственную таблицу, а не фактические Notes/Tasks/Files/Messenger. Она не выполняет реальный установщик, переход кода, все миграции или транзакционное восстановление обновлятора. Полная приёмка задачи #425 требует точного кандидата релиза 1.2.0, опубликованной установки 1.1.0, Windows/OSPanel, MySQL/MariaDB, DBPREFIX, проверки пользовательских данных и аварийного восстановления штатного обновлятора.

## Уточнение испытательного стенда

Восстановление теперь проверяется на реальной таблице `users` из опубликованного тега `v1.1.0` и реальной миграции `20261017_mutation_commands.sql` ветки `1.2`. После создания пользователей снимается резервная копия, выполняется миграция, данные намеренно изменяются, затем копия восстанавливается. Стенд проверяет исходные фамилии пользователей, количество записей и отсутствие новой таблицы после отката. Он не затрагивает рабочую БД.

Это по-прежнему **испытание восстановления отдельных таблиц, а не полноценное обновление всех модулей штатным обновлятором**. Задача #425 остаётся открытой.
