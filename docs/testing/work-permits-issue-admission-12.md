# Notes 1.2 — выдача документа и первичный допуск

## Что работает

После регистрации, заполнения бригады и редактирования черновика пользователь
с разрешением `work_permits.manage` видит управленческий журнал документов
всех авторов. Он может открыть черновик и записать выдачу наряда-допуска
или распоряжения. Для этого указываются начало и окончание работ,
отдельные меры безопасности и при необходимости особые указания.

Для наряда обязательны выдавший сотрудник, производитель работ, как минимум
один член бригады, организация, объект и задание. Работники проверяются
по действующему справочнику своей организации. Для распоряжения начало и
окончание должны приходиться на одну календарную дату в UTC.

При выдаче создаётся отдельная неизменяемая запись с датами, ФИО
выдающего и производителя, текстом указаний, автором действия.
Меры безопасности хранятся отдельными строками (от одной до 20).
Состояние документа меняется `draft` → `issued`, версия увеличивается.
После этого редактор черновика недоступен.

Для **наряда-допуска** после выдачи можно отдельно оформить **только первый
допуск**. Требуются фактическое начало в пределах срока наряда,
допускающий, проводивший инструктаж, производитель работ, а также явные
подтверждения подготовки места и состоявшегося инструктажа. Все
работники проверяются по организации; получателем инструктажа должен
быть производитель работ из выданного наряда. Если ранее указан
допускающий, нельзя подменить его другим сотрудником.

Первый допуск хранится отдельной записью, не меняет состояние
`issued` на `closed` и не подменяет ежедневные допуски в будущем.
Для распоряжения отдельный допуск не предусмотрен.

## Аудит и защита

- Изменяющие запросы требуют входа, права `work_permits.manage` и CSRF.
- Для обеих команд обязателен `version` и уникальный `command_id`.
- В транзакции блокируется строка документа. Сроки, состояние, версии и
  участники проверяются до изменения.
- Повтор уже применённой команды возвращает прежний результат;
  повтор с иными данными отклоняется ответом 409.
- Выдача, меры безопасности, первый допуск, версия и история
  записываются атомарно, без частично выданных документов.
- Время хранится в UTC, интерфейс преобразует локальное время в UTC.
- При чтении чужих документов обычным пользователем продолжает действовать
  ограничение авторства; расширенный список и просмотр доступны только
  пользователю с административным разрешением.

**Важно:** учётное действие в Notes не является цифровой подписью
выдающего наряд, допускающего или получателя инструктажа. Запись должна
соответствовать реально выполненным действиям и не заменяет оформление
документа по действующим нормативам.

## Испытания

```bash
php tests/integration/work_permits_issue_admission_mysql_12.php
node --check modules/work-permits/assets/work-permits-lifecycle.js
```

Тест на MySQL 8.4 наследует проверки предыдущих этапов, создаёт выданный
наряд, два мероприятия, первый допуск и распоряжение на одну смену.
Проверяются дубли, конфликт версий, отсутствие инструктажа, сроки,
чужой работник и запрет исправления выданного документа.
