# Notes 1.2 — восстановление после обрывов с DBPREFIX

## Проверяемый сценарий

Обновлятор создаёт резервную копию кода и БД на отдельном испытательном стенде. Далее дочерний PHP-процесс намеренно изменяет код, повреждает существующую запись и создаёт новую таблицу миграции. Следующий дочерний процесс восстанавливает файлы; отдельный третий — базу. Каждый шаг возвращает заранее ожидаемый код завершения.

Проверка `.github/workflows/updater-real-recovery-12.yml` запускается на MySQL 8.4 и MariaDB 11.4, в каждом случае без префикса и с `DBPREFIX=nt12_`. Итого — четыре независимых прогона.

В режиме общей базы дополнительно создаются **посторонние** непрефиксированные таблицы `users` и `mutation_commands`, имеющие контрольные данные. Испытание проверяет, что:

- снимок содержит только таблицу установки Notes и сохраняет её префикс;
- штатные службы восстановили пользовательский файл, старую версию кода и исходную запись БД;
- повреждённая таблица этой установки удалена, а не замаскирована префиксом в запросе проверки;
- чужие таблицы и их контрольные строки сохранились после восстановления.

Стенд запрещает имена БД без слова `test`; рабочую БД использовать нельзя.

## Границы результата

Проверяется настоящее резервное копирование и восстановление кодовых файлов и SQL-снимка после **раздельных принудительных завершений процессов**. Это не означает автоматического отключения питания реального компьютера или завершения всей транзакции Admin → Updates на Windows. Для закрытия #425 по-прежнему нужны штатный подписанный пакет 1.2.0, реальный переход с опубликованной 1.1.0, защита состояния обновлятора, проверка OSPanel 5.2.2, окончательный релизный SHA и ручные доказательства сохранности лицензий, модулей и прав.
