# 1.2 — наблюдение за отдельным обработчиком уведомлений

## Назначение

Команда `php bin/notifications_worker.php` обрабатывает ограниченный пакет внешних уведомлений.
До этого изменения успешный проход без заданий не оставлял понятной отметки для администратора.
Теперь после успешного прохода сохраняется время UTC в существующей таблице
`notification_runtime_state` с ключом `delivery_cli_worker`.

**Это наблюдение за процессом, а не проверка системного расписания или доставки адресату.**
Отметка не создаётся при ошибке до завершения обработки. Ошибки отправки отдельных
сообщений отражаются отдельно в журнале попыток; они не отменяют успех самого прохода.

## Установка и проверка

1. Настройте регулярный вызов `php bin/notifications_worker.php --json` в cron или планировщике Windows.
   Для наблюдения с порогом 45 минут рекомендуем запуск не реже одного раза в 15 минут.
2. В административном разделе «Каналы уведомлений» проверьте блок
   «Состояние отдельного обработчика уведомлений»: дата последнего завершённого прохода
   и его давность показываются отдельно от планировщика напоминаний Tasks.
3. Выполните `php bin/notifications_diagnose.php --json` и проверьте поля
   `cli_worker_last_success_utc`, `cli_worker_state`.
4. Если результат «Нет свежих запусков», проверьте существование системного задания,
   пользователя, путь к исполняемому PHP, права и записи журнала сервера.
   Не делайте вывод о состоянии SMTP только по этой отметке.
5. Для SMTP выполните пробную отправку через администратора, изучите
   `notification_delivery_attempts` и вручную подтвердите получение
   на контролируемом почтовом ящике.

При запуске одной только составной команды `tasks_reminder_cycle.php` отдельный
`notifications_worker.php` может не выполняться; этот индикатор тогда останется пустым.
Статус составного цикла Tasks показывается в другом блоке административного интерфейса.
Резервная обработка через HTTP также не обновляет отметку отдельного обработчика.

## Ограничения

- При отсутствии новой миграции не создаются ни таблицы, ни новые столбцы:
  используется историческое поле `last_http_run_at`, разделяемое по `state_key`.
- Запись отметки выполняется после завершения очереди, без адресов, сообщений,
  паролей, идентификаторов пользователей и параметров SMTP.
- Время берётся из MySQL/MariaDB в UTC, поэтому часовой пояс PHP не влияет на запись.
- Сбой записи диагностической отметки не должен ломать отправку уведомлений.
- Нельзя считать получение письма доказанным по зелёному состоянию обработчика.

## Автоматическая проверка

```bash
php tests/integration/notification_cli_worker_health_12.php
php tests/integration/notification_worker_cli_contract.php
php -l app/services/notifications/NotificationWorkerScheduleHealth.php
```

Для закрытия задачи #429 необходима отдельная проверка установленного сайта,
расписания на хостинге и фактического получения письма.
