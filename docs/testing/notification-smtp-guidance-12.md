# Notes 1.2 — диагностика ошибок пробной SMTP-отправки

## Исправленный сценарий

В административной странице «Каналы уведомлений» результат пробного письма
раньше отображался как успешная операция при HTTP 200 даже тогда, когда
задание завершалось в состоянии `failed` или `retry`.
HTTP 200 говорит лишь о выполнении запроса на создание пробного события,
но не об успешной передаче письма.

Теперь состояния отображаются раздельно:

- **Принято SMTP:** сервер завершил операцию и принял письмо в очередь.
  Это не доказательство получения адресатом.
- **Ожидание или повтор:** письмо пока не передано; необходимо проверить
  обработчик и дождаться следующей попытки.
- **Ошибка:** внешняя передача завершилась отказом; показывается причина
  по безопасному коду результата.

Для SMTP предусмотрены подсказки при ошибках соединения, времени ожидания,
TLS, авторизации, секрета окружения, адреса получателя и отклонения письма.
Они показываются рядом с результатом теста, в административной истории
и после явной консольной проверки `bin/notifications_smtp_probe.php --send`.
Тексты ответа SMTP и содержимое `error_summary` не выводятся: они могут
содержать чувствительные сведения.

## Приёмка установленного сайта

1. Убедитесь, что SMTP-конфигурация включена, у администратора имеется
   действующий электронный адрес, а переменная `env:` доступна процессу PHP.
2. В админке отправьте пробное письмо; проверьте, что сообщение интерфейса
   соответствует состоянию задания, а не только статусу HTTP.
3. Если ошибка `smtp_connect_failed`, проверьте исходящие TCP-соединения
   хостинга, порт, адрес и DNS.
4. Если `smtp_auth_rejected`, проверьте учётную запись и пароль приложения
   без копирования секретов в журнал.
5. Если `smtp_tls_failed`, проверьте режим подключения, сертификат и порт.
6. Сравните результат с состоянием очереди, журналом попыток, отметкой
   фонового обработчика и фактическим получением в контролируемом ящике.
7. Проверьте одну временную ошибку и повтор без дубликатов.

## Автоматические проверки

```bash
php tests/integration/notification_smtp_guidance_12.php
node tests/integration/notification_smtp_feedback_12.mjs
node --check modules/admin/assets/notification-settings.js
php tests/integration/notification_admin_smtp_12.php
php tests/integration/notification_smtp_contract.php
```

Сценарии без внешней сети не доказывают, что установленный SMTP
действительно передал письмо. Задача #429 остаётся открытой до проверки
на сервере и подтверждения получения.
