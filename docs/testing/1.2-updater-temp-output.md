# Проверка бюджета временного вывода обновлятора Notes 1.2

В Windows UpdateProcessRunner направляет stdout и stderr в отдельные временные файлы. Ограничение памяти не равно ограничению физического размера файлов.

Обработчик проверяет по 8 МиБ на каждый поток, 16 МиБ суммарно, запас свободного места 128 МиБ и прекращает команду с кодом 125 при превышении. При нормальном завершении, тайм-ауте и превышении бюджета файлы удаляются. На новом запуске удаляются файлы обновлятора старше суток.

## Автоматическая проверка

Команда: php tests/integration/update_process_temporary_output_12.php

Тест принудительно вызывает файловую реализацию на Linux и Windows. Он проверяет оба потока, превышение 64 МиБ на поток, код отказа, ограничение собранного вывода, тайм-аут и уборку оставшегося файла. GitHub Actions выполняет проверку на Windows Server 2022 и Ubuntu 24.04 с PHP 8.3.

## Отдельный том с квотой ОС

Для Windows-установки можно задать `NOTES_UPDATER_TEMP_DIRECTORY` — абсолютный путь к существующему, доступному на запись каталогу на **локальном** диске. Рекомендуется размещать его на отдельном томе, для которого системный администратор установил настоящую квоту свободного места. При недоступном, подменённом символической ссылкой или несуществующем каталоге обновлятор отказывает в запуске, **не переключаясь скрытно на системный TEMP**.

Пример локальной настройки перед запуском веб-сервера Windows: `NOTES_UPDATER_TEMP_DIRECTORY=D:\\NotesUpdaterTemp`. Каталог следует создавать заранее с правами исключительно учётной записи службы. Отдельный каталог на том же общем разделе **не обеспечивает квоту**. Квота дискового тома и аварийный перезапуск Windows/OSPanel требуют проверки администратором на целевом сервере.

Автоматические проверки дополнительно создают временный отдельный каталог, проверяют запуск, удаление обоих файлов и безопасный отказ при ошибке пути.

## Остающееся ограничение

Опрос раз в 10 мс не является жёсткой квотой ОС: дочерняя команда может записать дополнительные данные между проверками. После аварийного отключения компьютера файлы удаляются лишь при следующем запуске. Для окончательного устранения риска #427 требуется квота или ограничение на самой записи; испытание на Windows/OSPanel 5.2.2 остаётся обязательным.

Windows-испытание выявило, что системная функция tempnam может сокращать префикс имени. Создание временного файла переведено на эксклюзивный режим с полным префиксом notes-up-out-/notes-up-err- и случайным суффиксом: теперь очистка по маске видит файлы этого процесса после аварийного завершения.
