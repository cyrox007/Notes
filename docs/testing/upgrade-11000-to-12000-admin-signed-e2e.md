# Notes 1.2 — подписанное обновление из опубликованной 1.1.0 через админку

## Назначение

Процесс `.github/workflows/upgrade-11000-to-12000-admin-e2e.yml` использует **реальный тег `v1.1.0`** как исходную установленную версию, а не заново собранный макет старой системы. Устанавливает кандидат на базе текущего SHA ветки `1.2` через штатный интерфейс Admin → Updates, а не прямой вызов мигратора.

Перед запуском обновления стенд отдельной привилегированной командой `php tools/release/prepare-1.1-updater-12.php --yes --root=<установленная-1.1.0>` переносит только замкнутый набор файлов исполнителя из проверенного дерева 1.2, сохраняя исходную `1.1.0`, `.env`, доверенные ключи и прикладные данные. Этот этап не является частью подписанного ZIP и требует отдельного доверия к исходному дереву. Он исключён из автоматической установки на рабочем сервере до независимой проверки исходного SHA и безопасности подготовки.

Стенд собирает ZIP, создаёт одноразовый ключ Ed25519, подписывает манифест с SHA-256 пакета и полным SHA исходного коммита, размещает пакет на испытательном HTTPS-сервере. Запущенная версия 1.1.0 получает и применяет обновление через административный интерфейс, при этом в веб-процессе отключён `proc_open` и используется внешний механизм продолжения.

Запускаются два независимых испытания MySQL 8.4: **с историческим журналом миграций** и **без него**. Проверяется вход администратора, установка, код целевой версии, отсутствие режима обслуживания, здоровье приложения и сохранение контрольных пользователя, заметки, задачи, файла и сообщения Messenger. Файлы среды и лицензий защищены штатным обновлятором.

## Отличие от настоящего релизного пакета

В ветке `1.2` пока указан `Core\Version::VERSION = '1.1.0'` и код 11000. Для испытания только во **временной копии будущего ZIP** изменяются эти две константы на `1.2.0` и `12000`. Исходный коммит, опубликованный тег и рабочее дерево не редактируются; закрытый ключ используется лишь на стенде и удаляется до запуска обновления.

Таким образом, это доказательство работы **подписанного сквозного пути с испытательным пакетом**, но **не** доказательство тождественности настоящего опубликованного ZIP точному SHA `1.2.0`. Публикация запрещена до подготовки и испытания неизменённого пакета конечного SHA, независимой проверки подписи, защищённых правил ветки, прерываний, восстановления на настоящей системе и целевых платформ.

## Безопасность

Стенд использует отдельную БД и случайные секреты. После проверки возвращает конфигурацию DNS и удаляет испытательный ключ. В артефакты не должны попадать пароли БД, SMTP, приватные ключи и реальные пользовательские данные. Задание №425 остаётся открытым до полного релизного испытания.

## Итог сквозных испытаний от 26 октября 2026 года

После первоначальных отказов обнаружены и устранены три причины:
- Старый исполнитель `v1.1.0` не знал базовую отметку миграций `11000`. При обновлении без журнала он повторно применял историческую миграцию Messenger и выполнял безопасный откат.
- После обновления с журналом старая реализация могла зафиксировать транзакцию при пяти ожидающих миграциях. PR №525 требует `0 ожидает` и подтверждённый контракт схемы до фиксации. PR №526 включает эту проверку в автономный исполнитель.
- Для подготовки кода 1.1 к переходу на 1.2 контракт таблиц должен опираться на фактический состав установленного пакета. Таблица push-подписок не должна требоваться от старой 1.1 без соответствующей миграции.

В PR №527 выполнен повторный прогон `1.2 — подписанное обновление v1.1.0 через админку (испытательный пакет)` (GitHub Actions, запуск **40273779624**). Результаты:

| Исходная установка | Результат |
| --- | --- |
| Опубликованная `v1.1.0`, с историческим журналом миграций | **Успех:** установка через Admin → Updates, интерфейс подтверждает `1.2.0`, контрольные пользовательские данные и private storage сохранены |
| Опубликованная `v1.1.0`, без журнала миграций | **Успех:** установка через Admin → Updates, интерфейс подтверждает `1.2.0`, контрольные пользовательские данные и private storage сохранены |

Все восемь проверок PR №527 завершились успешно; изменения объединены с веткой `1.2` (коммит `6529ace1`).

**Область доказательства ограничена:** перед установкой выполняется отдельная подготовка исполнителя 1.1; пакет `1.2.0` изготовлен только для испытания с временной заменой констант версии. Это не подтверждает ни автоматическое обновление неподготовленной 1.1, ни идентичность публичного релизного архива точному SHA, ни Windows/OSPanel.

Следующие критерии завершения №425: подписанный подготовительный дистрибутив с установленным доверием к источнику, испытание неизменённого официального пакета exact-SHA, проверка безопасного восстановления после прерывания и приёмка на Windows/OSPanel.

## Подготовка исходного исполнителя

В опубликованном `v1.1.0` зафиксирован устаревший список миграций и отсутствует исходная отметка `11000`. Предварительная подготовка копирует обновлённый, замкнутый набор файлов updater, используя проверку размеров и SHA-256, атомарную замену, отдельную резервную копию и обратное копирование при ошибке. До переключения приложение остаётся `1.1.0`. Подготовка не изменяет БД. Доступна только оператору с правами записи в установленный каталог и доверием к подготовленному исходному дереву 1.2; запрещено запускать её с непроверенной загрузкой. Для рабочего сайта нужен отдельный подписанный дистрибутив подготовки и приёмка прав доступа.
