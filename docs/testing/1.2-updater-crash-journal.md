# Прерывания процесса и контрольные точки отката Notes 1.2

Тест `tests/integration/updater_crash_resume_journal_12.php` использует настоящий `UpdateTransactionJournal` и `UpdateTransactionStateMachine`. Внешние каталоги журнала, кандидата и резервной точки создаются только во временном каталоге испытания.

Первый отдельный PHP-процесс фиксирует начало изменения и переключение кода, затем намеренно завершается с кодом 73. Следующий процесс читает журнал с диска, отвергает преждевременный переход в `committed`. Второй дочерний PHP-процесс начинает откат, фиксирует восстановление кода и завершается с кодом 74. Последний процесс возобновляет журнал, отмечает восстановление базы и проверяет последовательность состояний.

Проверка запускается в GitHub Actions на Ubuntu 24.04 и Windows Server 2022 с PHP 8.3. Это регрессия долговечности **журнала и графа состояний**, а не испытание фактического копирования файлов, работы мигратора и восстановления реальной БД. Проверки `markCodeRestored` и `markDatabaseRestored` здесь передают тестовые метаданные без реального восстановления. Нельзя использовать успех этой проверки как доказательство готовности полного обновлятора.

Для закрытия #425 необходимо отдельное испытание `UpdateApplyCommand` на установленной 1.1.0, с настоящей резервной копией кода и БД, предсказуемым прерыванием дочернего процесса, вызовом `--recover`, сверкой данных и повторным успешным обновлением.
