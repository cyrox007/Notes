# Notes 1.2 — исторические рабочие места в допусках

## Выполнено

Каждый новый первичный или повторный допуск может сохранять собственное фактическое место работы (не более 500 символов). Формы требуют заполнить место при создании. Сервер сохраняет значение в строке конкретного периода, возвращает его с историей и печатает в обоих вариантах PDF.

Поле `workplace` добавлено миграцией `20261025_work_permits_period_workplace.sql` как допускающее отсутствие значения. Старые строки не заполняются искусственно. Команды старых клиентов без этого поля сохраняют прежний отпечаток, а при наличии поля оно участвует в защите от повторной команды с изменёнными данными.

## Проверка

```bash
php tests/integration/work_permits_print_layout_mysql_12.php
node --check modules/work-permits/assets/work-permits-daily.js
node --check modules/work-permits/assets/work-permits-lifecycle.js
```

Браузерные проверки дополнены вводом рабочего места на первичном допуске и после перерыва. Проверка MySQL контролирует два разных места, старые записи, отсутствие вымышленных значений, безопасный повтор и отказ от подмены, а Poppler — отображение в PDF.

## Что ещё не принято

Печатная форма остаётся **учётным макетом**, без юридически значимых электронных подписей. Нужны сравнение распечаток с утверждённым организацией бланком, решение ответственного за охрану труда, проверка на физическом Android/iOS и отдельная массовая нагрузка. Этот этап не закрывает задачу #421 и не разрешает выпуск 1.2.0.
