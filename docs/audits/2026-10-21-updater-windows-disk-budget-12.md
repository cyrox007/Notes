# Notes 1.2 — безопасный бюджет временного вывода обновлятора Windows

Дата: 21 октября 2026 года.

## Почему нужна дополнительная защита

После ограничения потребления памяти обновлятором (#407) Windows по-прежнему направляла `stdout` и `stderr` во временные файлы, потому что штатные каналы `proc_open` на Windows не гарантируют надёжное неблокирующее чтение. Очень многословная дочерняя команда могла заполнить свободный диск задолго до штатного тайм-аута.

## Что изменено

- `Core\UpdateProcessRunner` продолжает направлять два канала в разные временные файлы на Windows и сохранять в результате только первые **1 МиБ** каждого.
- При запуске проверяется свободное место во временном каталоге. Необходим запас как минимум **128 МиБ сверх суммарного бюджета временного вывода в 16 МиБ**.
- Пока процесс работает, не реже чем с интервалом **10 мс** проверяются размеры обоих файлов и остаток диска. Если любой файл превысил **8 МиБ**, оба — **16 МиБ** суммарно, либо оставшийся запас ниже **128 МиБ**, выполнение прерывается.
- При превышении бюджета возвращается **код 125** и понятная диагностика; тайм-аут остаётся **124**, настоящий код завершения сохраняется при обычной работе. Если процесс закончил запись до следующего опроса, размер перепроверяется после его завершения и ошибка всё равно фиксируется.
- При срабатывании защиты применяется экстренная остановка без обычной задержки перед завершением. После остановки файловые дескрипторы закрываются и оба временных файла удаляются в `finally`.
- При следующем запуске безопасно удаляются только совпадающие с собственными именами `notes-up-out-*` / `notes-up-err-*` обычные файлы, созданные более суток назад. Свежий вывод параллельно работающих команд не трогается.

### Граница гарантии

**Проверка размеров с интервалом 10 мс — не жёсткая файловая квота операционной системы.** Между двумя опросами очень быстрый процесс может успеть записать больше 8/16 МиБ, а аварийное завершение самого PHP или Windows может оставить временные файлы до следующего запуска. Для площадок, где допустим исключительно гарантированный максимум, нужен отдельный ограниченный по объёму каталог/том с квотой ОС и проверенный способ завершения порождаемых процессов. Без него нельзя заявлять абсолютное физическое ограничение временного файла.

Для реальных Windows/OSPanel 5.2.2 требуется ручная проверка прав временного каталога, наличия места, поведения `proc_terminate`, перезапуска после принудительного завершения PHP и совместимости с антивирусом. Положительный GitHub Windows CI не заменяет эту проверку.

## Автоматическая приёмка

`tests/integration/updater_windows_disk_budget_12.php` выполняется в двух заданиях `.github/workflows/php83-foundation.yml` на PHP 8.3:

1. Два канала по 6 МиБ не блокируют завершение, возвращается исходный код, в памяти не более 1 МиБ из каждого канала.
2. Вывод существенно выше бюджета приводит к коду 125 и ограниченной диагностике, не ждёт общего тайм-аута.
3. Истечение времени без превышения бюджета возвращает 124, а не 125.
4. После успешного выполнения, превышения и тайм-аута не остаются новые временные файлы.
5. После повторного запуска обычные команды снова работают, устаревшие временные файлы удаляются.

Тест использует метод файлового перенаправления и на Linux, чтобы проверить его независимо от платформенного выбора ветки.

## Статус задачи #427

Автоматическая защита, диагностика, уборка и регрессии реализованы. Полное закрытие эксплуатационного риска возможно после проверки на реальной установке Windows/OSPanel и, если требуется строгая файловая квота, после выделения отдельного ограниченного временного тома. **Не объявлять защиту абсолютной системной квотой.**
