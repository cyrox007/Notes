# Двухфакторная аутентификация TOTP

Workspace Organizer поддерживает стандартную двухфакторную аутентификацию TOTP по RFC 6238, совместимую с Google Authenticator, Microsoft Authenticator, Aegis и другими приложениями-аутентификаторами.

## Режимы работы

2FA имеет два независимых уровня управления.

### Персональный режим

Если общесистемная обязательность выключена, пользователь самостоятельно включает или отключает TOTP в своём профиле. Настройка действует только на его учётную запись и не влияет на остальных пользователей.

Для включения пользователь:

1. подтверждает текущий пароль;
2. получает индивидуальный TOTP-секрет;
3. добавляет его в приложение-аутентификатор;
4. подтверждает настройку текущим шестизначным кодом;
5. сохраняет резервные коды, которые показываются один раз.

Отключение требует текущий пароль и действующий TOTP-код либо неиспользованный резервный код.

### Обязательный режим для всей системы

Администратор может открыть **Admin → Системные настройки → Двухфакторная аутентификация** и переключить политику в режим **«Обязательно для всех пользователей»**.

Изменение политики требует текущий пароль администратора.

После включения обязательного режима:

- пользователи с уже настроенной 2FA продолжают вход через пароль и TOTP;
- пользователь без 2FA после правильного пароля не получает обычную авторизованную сессию;
- вместо этого ему предлагается настроить собственный TOTP;
- доступ к Workspace появляется только после успешного подтверждения настройки;
- пользователь не может самостоятельно отключить 2FA, пока действует общесистемная политика;
- выключение обязательной политики не удаляет уже настроенные персональные TOTP-секреты.

## Модель безопасности

- для каждого пользователя создаётся отдельный случайный 160-битный Base32-секрет;
- секрет шифруется перед записью в БД через штатный механизм шифрования приложения и пользовательский AAD;
- TOTP использует 30-секундный интервал и допускает отклонение времени не более чем на один интервал;
- счётчик успешно принятого TOTP сохраняется, поэтому один и тот же код нельзя использовать повторно;
- успешная проверка пароля не создаёт авторизованную сессию, если аккаунту требуется второй фактор;
- для проверки второго фактора действует отдельное ограничение частоты попыток;
- при включении выдаются 10 случайных одноразовых резервных кодов;
- в БД резервные коды хранятся только как SHA-256-хеши;
- использованный резервный код немедленно удаляется из набора;
- включение, отключение, перевыпуск резервных кодов, успешные и неуспешные проверки записываются как события безопасности;
- страницы настройки и однократного показа резервных кодов запрещают кэширование;
- секрет не передаётся внешнему сервису генерации QR-кода.

## Вход

После правильной пары логин/пароль:

- при включённой TOTP пользователь переводится в короткоживущее состояние ожидания второго фактора;
- действующий TOTP или неиспользованный резервный код завершает вход;
- после успешной проверки идентификатор сессии обновляется;
- если глобальная политика обязательна, а TOTP ещё не настроен, вместо входа запускается обязательная настройка 2FA.

## Восстановление

Резервный код может заменить TOTP при входе и после использования становится недействительным.

Авторизованный пользователь может перевыпустить набор резервных кодов после подтверждения пароля и существующего второго фактора.

Административный сброс чужой 2FA не является скрытым обходом аутентификации и в текущий контракт не входит. Если такой сценарий понадобится, он должен быть отдельной журналируемой процедурой подтверждения личности.

## Ротация UNIQUE_KEY

TOTP-секреты шифруются тем же доменом данных, который использует `UNIQUE_KEY`. Поэтому штатная ротация ключа обязана включать TOTP.

`bin/rotate_data_keys.php` при области `all` или `notes`:

- проверяет, что каждый активный TOTP-секрет читается ровно одним из старого/нового поколений ключа;
- пакетно перешифровывает TOTP-секреты;
- сохраняет контрольную точку для безопасного продолжения после прерывания;
- повторный проход распознаёт уже перешифрованные записи;
- финально проверяет чтение новым ключом;
- поддерживает симметричный rollback обратно на исходный `UNIQUE_KEY`.

Область `notes` исторически означает весь домен данных `UNIQUE_KEY`; после появления 2FA в неё входят заметки, история заметок и TOTP-секреты.

## Ограничение попыток

Параметры по умолчанию:

- `MAX_2FA_ATTEMPTS=8`;
- `TWO_FACTOR_RATE_LIMIT_WINDOW_SECONDS=300`.

Их можно переопределить в `.env`.

## Критерий приёмки

Функция считается принятой, когда подтверждены:

- персональное включение и отключение;
- вход с TOTP;
- вход с резервным кодом и невозможность использовать его повторно;
- обязательная системная политика;
- принудительная настройка аккаунта без TOTP;
- запрет отключения при обязательной политике;
- возврат к персональному режиму без удаления существующих секретов;
- прямая ротация `UNIQUE_KEY`, продолжение после прерывания и rollback;
- clean install и upgrade с опубликованной 1.0.1;
- полный набор релизных проверок на точном объединённом SHA.
