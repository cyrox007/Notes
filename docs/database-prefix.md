# Две установки в одной базе данных

Накопительный патч r2 для 1.1.0 добавляет параметр `.env` **DBPREFIX**. Каждая установка сохраняет собственные файлы, `.env`, ключи и приватное хранилище. Совместно используется только база MySQL/MariaDB.

Для новой установки укажите на шаге настройки БД уникальный префикс, например `test_`. Разрешены 2–16 символов: строчные латинские буквы, цифры и `_`, первая — буква, последняя — `_`. Таблицы, внешние ключи, триггеры, служебные процедуры и журнал миграций получают этот префикс. Вторая установка может использовать `prod_`; похожие префиксы вроде `prod_` и `prod_test_` также разделены.

Существующая рабочая установка с таблицами без префикса может оставаться на месте. После установки r2 **явно добавьте в её `.env` строку `DBPREFIX=`**, оставив значение пустым. Это включает ограничение резервного копирования и отката таблицами приложения без переименования данных. Тестовой установке задайте `DBPREFIX=test_` в отдельном `.env` либо через установщик. Перед использованием общей БД обе установки должны работать на r2 или более новом коде с поддержкой префиксов. Старый обновлятор может затронуть всю базу.

Пример рабочей установки:

```dotenv
DBNAME=workspace
DBPREFIX=
```

Пример тестовой установки:

```dotenv
DBNAME=workspace
DBPREFIX=test_
```

Не меняйте пустой префикс уже заполненной установки на `prod_`: параметр выбирает другой набор таблиц, а не переносит существующие данные. Для действующих таблиц без префикса используйте пустое значение. Патч сам не переименовывает и не переносит таблицы.

Миграции применяются через обычный обновлятор или `php bin/migrate.php`; контрольные суммы исходных SQL сохраняются. Резервная копия включает только таблицы и триггеры текущего пространства имён. Обычный и пошаговый откат не удаляют соседние установки. Восстановление снимка с другим префиксом отклоняется до изменения БД.

Проверено на MySQL 8.4: три установки в одной БД, полный набор схем и миграций, триггеры заметок и ролей, PDO/mysqli, отдельные журналы миграций, обычное и пошаговое восстановление, сохранность чужой таблицы. Браузерные действия всех модулей проверяются в CI с пустым префиксом и `test_`.
