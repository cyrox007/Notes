# Банк идей и отложенных направлений

Этот документ хранит идеи, которые **не являются обещанием конкретного релиза**. После принятия решения направление переносится в `ROADMAP.md` и получает отдельную спецификацию.

## Модуль «Авто» / бортовой журнал

Кандидат без назначенной версии:

- несколько автомобилей;
- карточка автомобиля и текущий пробег;
- одометр;
- журнал заправок;
- расчёт расхода топлива, включая циклы «до полного»;
- обслуживание по пробегу и календарю;
- ремонты, запчасти и расходы;
- статистика расхода, стоимости километра и пробега;
- позднее — напоминания через общий механизм уведомлений.

До планирования нужно определить правила неполных заправок, исправления пробега, единицы измерения, вложения, шины, страховки и сезонные работы. OBD и телеметрия в исходный объём не входят.

## Общий импорт справочников

Поддерживающая возможность для модулей со справочниками:

- UTF-8, одна запись на строку;
- CRLF/LF/BOM;
- предварительный просмотр;
- транзакционный импорт;
- идемпотентность и отсутствие молчаливой перезаписи;
- типовая нормализация и уникальность;
- журнал результата;
- отдельные права;
- нагрузочная проверка больших списков.

CSV/Excel, автоматическое сопоставление столбцов и синхронизация с внешними системами — отдельный последующий этап.

## Перенесено из backlog в запланированные версии

Системный центр уведомлений из issue #233 больше не является инициативой без версии.

Для **1.1.0** принят общий платформенный механизм:

- семантические события;
- хранение в БД;
- встроенный центр уведомлений и непрочитанные;
- подписки, категории и важность;
- дедупликация;
- очередь и повторная доставка;
- пользовательские и административные получатели;
- подключаемые каналы E-mail, Browser/PWA Push, Telegram, подписанный Webhook и локальный SMS-шлюз.

Полный контракт: [plans/1.1-notifications.md](plans/1.1-notifications.md).

После решения объединить прежние объёмы 1.2 и 1.3 в один расширенный цикл следующие направления больше не относятся к backlog и выполняются в **1.2**:

- модуль «Дефекты»;
- модуль «Наряды и допуски»;
- команды/рабочие группы, исполнители и ответственность в Tasks;
- персональная и командная рабочая очередь;
- «Сегодня», «Завтра», «Просрочено»;
- ежедневные живые сводки и повторные напоминания;
- действия прямо из уведомлений;
- Browser/PWA Push и устанавливаемая PWA-оболочка;
- версионированный API Tasks;
- курсорная пагинация и идемпотентные команды;
- адаптеры мессенджеров/ботов как клиенты общего API, без собственной бизнес-логики;
- расширенный metadata-only аудит и серверные политики;
- активные сеансы, удалённое завершение сеанса, основа доверенных устройств и ограниченный режим;
- обязательная нагрузочная приёмка на 1000 одновременно активных пользователей.

Полный контракт: [plans/1.2-unified-cycle.md](plans/1.2-unified-cycle.md).

Развитие Tasks: [plans/tasks-evolution.md](plans/tasks-evolution.md).

## Другие кандидаты

Следующие направления остаются без самостоятельного общеплатформенного релизного обязательства. Их узкие части могут появляться внутри уже запланированных модулей:

- универсальный межмодульный поиск и индекс;
- общий workspace/team layer за пределами потребностей Tasks и уже утверждённых модулей 1.2;
- универсальная автоматизация между событиями модулей за пределами сценариев, назначенных в дорожной карте;
- полноценное двустороннее PWA/offline-редактирование всех поддерживаемых сущностей после определения общей конфликтной модели, локальной очереди команд и восстановления;
- общий публичный API всей платформы помимо API конкретных модулей и ограниченного подписанного webhook-канала уведомлений;
- отдельный полноэкранный медиаплеер поверх общего медиаслоя;
- административный мобильный companion;
- интеллектуальные AI-сводки Tasks и другие AI-функции, пока не утверждён общий контур управления AI.

## Старый UX-backlog

Из `PRODUCT_UX_0.13.md` не переносится автоматически ни один пункт. При необходимости он повторно проверяется на текущей версии и только подтверждённая проблема становится новой задачей.

Отдельно зафиксировано правило 1.2: **новый визуальный редизайн не выполняется**. Текущий стиль интерфейса сохраняется; удобство улучшается за счёт AJAX-сценариев внутри открытых страниц, состояний загрузки/ошибки, мобильной пригодности и сокращения лишних переходов.
