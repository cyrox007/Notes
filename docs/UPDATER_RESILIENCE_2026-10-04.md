## Внесённые изменения

- Восстановление БД разбирает дамп потоком, без загрузки всей базы и массива SQL
  в память. Сохранены SHA-256, размер, переносимость триггеров и совместимость
  старого формата JSON.
- Формат дампа проверяется при подтверждении резервной точки, до изменения
  рабочего кода, и повторно перед удалением таблиц. Пустой, оборванный дамп,
  неверный UTF-8 и незавершённый разделитель отвергаются заранее.
- Одно SQL-выражение ограничено 8 МиБ. Это предел выражения, а не базы.
  Установка с более крупным выражением должна получить отказ при подготовке
  резервной точки. Проверка формата не является проверкой всей семантики SQL
  сервером БД.
- Ошибки миграции в браузерном и консольном исполнителях содержат имя файла,
  номер выражения, SQLSTATE, код MySQL и SHA-256 SQL. Данные INSERT и текст
  внешней ошибки с потенциальными пользовательскими значениями не включаются
  в новое сообщение. Сервисное событие применения содержит исходную и целевую
  версии.
- Доставка фиксирует начало и исход попытки до появления транзакции. Этапы:
  предварительная проверка, список релизов, описание релиза, загрузка и проверка
  подписи, загрузка и проверка пакета, подготовка пакета. Сохраняются ID,
  безопасное имя сервера, HTTP-код, длительность и тип ошибки. URL-параметры,
  заголовки и текст внешней ошибки не сохраняются. Недоступность сервисного
  журнала не скрывает первичный отказ; при ненастроенном хранилище запись
  попытки не гарантируется.
- Браузер прекращает повторы при `retryable=false`, включая HTTP 403 от WAF.
  Для временных ошибок сохраняются восемь повторов; ожидание HTTP ограничено
  90 секундами. Потеря ответа на начало операции не вызывает автоматический
  повтор запуска. Серверные блокировки и журнал остаются источником истины.
- Подготовленный удалённый пакет сохраняется в привязке формы и используется
  при установке с повторной штатной проверкой подписи и хэша.
- Уведомление показывает код диагностики отката. Сквозной тест больше не
  утверждает, что commit состоялся, когда целевая версия не подтверждена.

## Выполненные проверки

Локально использован PHP 8.3.6. Прошли:

- потоковый разбор дампа около 137 МБ при `memory_limit=32M`, включая триггер;
- отказ для оборванного SQL, неверного UTF-8, пустого дампа, слишком большого
  выражения и незавершённого переключения разделителя;
- поведение браузера при постоянных HTTP 400/403/409/422/500,
  HTML-странице WAF, временном HTTP 409/503 и разрыве сети;
- сохранение раннего отказа HTTP 403 с общим ID и без тестового секрета;
- подписанная удалённая доставка, независимый внешний исполнитель,
  работа без запуска процессов, раннее восстановление до резервной точки,
  готовность конфигурации, инварианты восстановления и контракты интерфейса;
- синтаксис изменённых PHP/JS и проверка пробелов в изменениях.

Полный локальный прогон БД не состоялся: сервер MariaDB подготовлен,
но среда запрещает соединение с ним. Этот результат не является проверкой
реального восстановления MySQL. PHP 8.1 и MySQL целевого хостинга локально
не проверены.

## Подготовленные проверки GitHub

Только для этой ветки добавлен запуск трёх профильных процессов:

1. Точный переход опубликованной 1.0.14 → кандидата 1.0.15: отдельно без
   журнала миграций и с журналом. Права исключают CREATE VIEW / SHOW VIEW;
   процессы и `opcache_reset` запрещены; PHP ограничен 256 МБ / 80 секундами.
   При отказе выводится сервисный журнал с первичной причиной.
2. Существующая матрица резервного копирования и восстановления MySQL/MariaDB.
   Добавлен сценарий: корректный хэш оборванного дампа не разрешает удалить
   рабочие таблицы.
3. Проверки памяти, HTTP-повторов, ранней диагностики и независимого
   восстановления на PHP 8.1.

Отправка ветки отклонена автоматической проверкой разрешений. Эти процессы
ещё не запускались на новых изменениях. Общие матрицы модулей не запускались.

   восстановления БД. Потоковый SQL устраняет рост памяти с размером дампа,
