# Резервное копирование и восстановление из админки Notes

## Для чего

Раздел **Админка → Резервные копии** предназначен для восстановления данных после ошибочных действий или сбоя, без удаления существующей установки. Доступен только суперпользователю с правом управления настройками. Номер версии при этом не меняется.

Копия содержит:

- снимок таблиц MySQL, созданный штатным проверенным механизмом обновлятора;
- приватные пользовательские файлы и вложения из `PRIVATE_STORAGE_PATH`;
- старые вложения и аватары из `uploads/`, если каталог присутствует;
- технический снимок файлов приложения, необходимый для диагностики и аварийного восстановления через сервер.

**Не включаются** временные состояния обновлятора, сеансы, кэш, журналы безопасности и содержимое предыдущих резервных копий. `.env` и секреты приложения не публикуются через браузер. Технический снимок кода не подменяет безопасное обновление версии: действие «Восстановить» возвращает **данные и пользовательские файлы**, но не меняет код приложения.

## Создание

1. Откройте админку под суперпользователем и перейдите в «Резервные копии».
2. Убедитесь, что на диске хватает места для кода, SQL и пользовательских файлов. Для больших архивов операция может потребовать увеличенного времени выполнения PHP и отдельного расписания обслуживания.
3. Введите текущий пароль и нажмите «Создать и проверить копию».
4. Система временно ограничит запись и сохранит копию **вне веб-корня**. Проверьте, что копия появилась в списке, затем нажмите «Проверить».
5. Для защиты от поломки диска сохраните копию на **другом физическом носителе** средствами администрирования сервера. В интерфейсе отсутствует публичная ссылка на архив с личными данными.

В каталоге приватного хранилища создаётся `admin-backups/<идентификатор>`. Каждый снимок имеет реестр `operator.json` и контрольные суммы SHA-256. Не меняйте файлы внутри этого каталога.

## Восстановление

1. Убедитесь, что есть актуальная внешняя копия и что версия приложения соответствует версии сохранённых данных.
2. Выберите нужную запись и нажмите «Проверить». Повреждённые или неполные записи не принимаются.
3. Откройте «Восстановить из этой копии», повторно введите пароль и точное слово **ВОССТАНОВИТЬ**.
4. Перед изменением данных система создаёт **дополнительную защитную копию текущего состояния** и включает режим обслуживания. После успешного восстановления сравнивает данные и файлы с исходным реестром.
5. Войдите заново, проверьте пользователей, документы, вложения, роли и административные настройки.

При ошибке после начала восстановления система пытается вернуться к защитному снимку. Если откат тоже не завершён, режим обслуживания сохраняется; дальнейшие попытки через веб-интерфейс запрещены до разбирательства. Не удаляйте установленный сайт и не запускайте установщик поверх данных.

## Безопасность и ограничения

- Сервер проверяет роль суперпользователя, право управления настройками, CSRF и текущий пароль.
- Из браузера нельзя загрузить произвольный SQL или выбрать абсолютный путь резервной копии. Копии принадлежат этой установке и проверяются по контрольным суммам, текущей версии и набору таблиц.
- При несовпадении префикса БД или наличии сторонних триггеров восстановление запрещается. В базах с `DBPREFIX` чужие таблицы сохраняются; это проверяется реальным испытанием.
- Права файлового хранилища: каталоги 0700, пользовательские файлы копий 0600. Нельзя размещать каталог резервирования внутри публичного веб-корня.
- Хранение на том же сервере **не защищает** от отказа всего сервера, компрометации администратора или потери диска. Необходима внешняя копия и периодическая проба восстановления.
- Снимок SQL и файлов выполняется в режиме обслуживания, но сторонние процессы, которые игнорируют этот режим, могут продолжать писать. Для критичной установки предварительно остановите фоновые процессы.
- Для крупных данных и на Windows обязательно проведите испытание на отдельной копии установленного сайта; не считайте прохождение Linux CI достаточным основанием для включения в стабильный выпуск.

## Что проверяется автоматически
