# Предварительная установка исправленного updater 1.0.14 → 1.0.15

## Зачем нужен мост

Опубликованная 1.0.14 начинает обновление своим собственным исполнителем. Поэтому исправления резервирования, потокового восстановления, диагностики доставки и повторов HTTP из 1.0.15 не могут повлиять на самый первый запрос, пока новый исполнитель ещё не установлен.

Для exact-перехода 1.0.14 (10014) → 1.0.15 (10015) добавлен одноразовый мост `tools/release/bootstrap-1.0.14-updater.php`. Он предварительно переносит только файлы updater-контура из доверенного exact-пакета 1.0.15 в live-установку 1.0.14.

Мост **не меняет** `core/Version.php`, миграции, прикладной код и базу данных. После него установка по-прежнему остаётся 1.0.14; само обновление выполняется штатной кнопкой в административном интерфейсе.

## Запуск

Распакуйте доверенный exact-пакет 1.0.15 отдельно от рабочей установки. Из каталога этого пакета выполните:

```bash
php tools/release/bootstrap-1.0.14-updater.php --yes --root=/полный/путь/к/рабочей/установке
```

После сообщения `[OK]` откройте административный интерфейс Workspace Organizer и установите 1.0.15 обычным способом.

Скрипт откажется работать, если источник не является exact 1.0.15 или рабочая установка не является exact 1.0.14. Исходный и рабочий каталоги не могут совпадать или быть вложены друг в друга.

## Что переносится

Переносится замкнутый контур updater: браузерный исполнитель, web-транзакция, резервирование, переключение кода, мигратор, восстановление базы, проверка кандидата, блокировки, журнал транзакции и удалённая доставка. `Version.php`, SQL-миграции и прикладные модули в мост не входят.

Каждый существующий файл сначала сохраняется во временную резервную копию. Новая копия записывается через временный файл, проверяется по размеру и SHA-256 и затем заменяет рабочий файл. Если любой следующий файл или итоговая проверка не проходят, уже заменённые файлы возвращаются из резервной копии, а созданные мостом файлы удаляются.

После переноса дополнительно проверяются признаки исправленного исполнителя: предварительная проверка дампа, потоковый восстановитель, ранний журнал попытки доставки, 90-секундный предел браузерного запроса и новый пошаговый web-контур.

## Что это закрывает

Мост закрывает конкретный разрыв exact 1.0.14 → 1.0.15 на хостингах, где доступен PHP CLI: первый большой резервный снимок и последующие этапы может выполнять уже исправленный updater 1.0.15, хотя версия приложения ещё остаётся 1.0.14.

Профильная проверка CI применяет мост к дереву опубликованного тега `v1.0.14`, убеждается, что версия и manifest миграций не изменились, а перенесённые файлы совпадают с текущим исполнителем. Отдельный контракт принудительно ломает второй файл переноса и проверяет возврат первого файла.

## Что остаётся нерешённым

Это не делает обновление полностью независимым от ограничений виртуального хостинга. Остаются две отдельные задачи:

1. Хостинг без доступа к PHP CLI пока не имеет безопасного способа предварительно поставить новый исполнитель в уже опубликованную 1.0.14.
2. Полное копирование дерева, резервирование и восстановление большой БД всё ещё могут занять больше одного разрешённого HTTP-запроса. Потоковая обработка ограничивает память, но сама по себе не ограничивает время операции.

Поэтому наличие моста не является основанием объявлять updater окончательно отказоустойчивым. Следующий архитектурный этап — штатный подписанный handoff исполнителя и возобновляемые ограниченные шаги для длительных операций.
