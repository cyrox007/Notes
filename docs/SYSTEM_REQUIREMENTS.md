# Системные требования Workspace Organizer

Актуально для стабильных линий **1.0.x / 1.1.x** и разрабатываемой линии **1.2**.

## PHP

Технический минимум стабильной линии 1.0.x: **PHP 8.1+**.

Технический минимум выпущенной линии 1.1.x: **PHP 8.2+**. Накопительные патчи 1.1.0 не повышают этот порог.

Технический минимум разрабатываемой линии 1.2: **PHP 8.3.x**. Ветка `1.2` может использовать синтаксис и возможности PHP 8.3 и не обязана запускаться на PHP 8.2.

Порог 1.2 применяется не только в Composer и CI. Web-установщик и healthcheck проверяют PHP 8.3+, общий CLI bootstrap останавливает cron/worker/служебные команды на более старом PHP, а внешний updater отдельно проверяет фактическую версию выбранного `UPDATE_PHP_BINARY`. Подписанный пакет дополнительно проходит проверку `requires_php` до резервного копирования и destructive-фазы обновления.

Обязательные расширения:

- `mysqli`;
- `pdo_mysql`;
- `mbstring`;
- `ctype`;
- `fileinfo`;
- `sodium`;
- `openssl`;
- `zlib`;
- `gd`.

Также требуются рабочие PHP-сессии, upload temp, `flock`, атомарное переименование файлов, `getenv`/`putenv` и Argon2id в `password_hash()`.

## База данных

Поддерживаются:

- MySQL 8.0+;
- MariaDB 10.5+.

CI проверяет основной MySQL-контур; совместимость с MariaDB остаётся частью эксплуатационной приёмки.

## Web-сервер и хранилище

Нужны:

- Apache с `mod_rewrite` либо Nginx/эквивалентный reverse proxy;
- доступный для записи `PRIVATE_STORAGE_PATH` вне document root;
- HTTPS для production;
- возможность записывать в каталог приложения во время установки и обновления.

## Composer и vendor

Runtime не зависит от Composer и каталога `vendor/`. Готовый GitHub Release и исходный tree запускаются встроенным autoload/runtime.

Composer используется как инструмент разработки и фиксирует минимальную версию PHP. Для ветки 1.2 в `composer.json` и `composer.lock` установлен минимум `>=8.3`.

## Messenger

Полный функционал Messenger работает через аутентифицированный HTTP Long Poll.

WebSocket — необязательный ускоритель. Для него нужны:

- PHP CLI той же поддерживаемой версии;
- возможность держать долгоживущий PHP-процесс;
- WebSocket endpoint или reverse proxy;
- на Unix для режима управления процессом рекомендуется `pcntl`.

Отсутствие WebSocket не должно блокировать остальные модули или основные функции Messenger.

## Windows / OSPanel

Windows/Open Server поддерживается как локальная и тестовая среда. Для Internet-facing production рекомендуемый baseline — Linux.

Для линии 1.1 выбранный PHP-профиль OSPanel должен быть **8.2 или новее**. Для разработки и будущего выпуска 1.2 требуется **PHP 8.3 или новее**. Если web-PHP уже переключён на 8.3, но `UPDATE_PHP_BINARY` указывает на старый CLI 8.2, ускоренный процессный режим обновлятора не используется до исправления пути. Обновление между минорными линиями не должно терять конфигурацию сайта, `.env`, private storage и параметры базы данных.

## Правило минорных линий

Patch-релизы внутри одной минорной линии не повышают системный минимум.

- 1.0.x остаётся на минимуме PHP 8.1;
- 1.1.x остаётся на минимуме PHP 8.2;
- 1.2.x вводит минимум PHP 8.3.

Повышение минимума выполняется только новой минорной линией и сопровождается CI на новом минимуме, аудитом несовместимостей, проверкой зависимостей, fresh install, update/rollback/recovery, cron/worker/CLI и обновлением эксплуатационной документации.
