# Workspace Organizer — инструкция пользователя

Версия документа: 13.09.2026. Документ описывает функции текущей корпоративной alpha-версии и hardening Notes, входящий в этот пакет изменений.

## 1. Вход и учётная запись

### Вход
1. Откройте страницу входа.
2. Введите логин/e-mail и пароль.
3. После успешной авторизации система создаст рабочую сессию и откроет Workspace.

Не передавайте пароль другим пользователям. Если вы работаете на общем компьютере, используйте кнопку выхода из профиля/меню, а не просто закрывайте вкладку.

### Регистрация

Регистрация выполняется по invite-коду. Ссылка вида `/auth/registration/<invite_code>` открывает форму регистрации. Если invite недействителен или отключён, регистрация не должна предоставлять доступ.

## 2. Заметки

Раздел `/notes/` предназначен для личных рабочих заметок.

### Создать заметку
1. Откройте «Заметки».
2. Создайте новую запись и задайте название.
3. На странице редактирования введите текст.
4. Нажмите «Сохранить текст».

Текст заметки сохраняется в БД в зашифрованном виде. Название заметки отдельным полем не является частью encrypted text payload.

### Прикрепить файл
1. Откройте редактирование заметки.
2. В блоке «Вложения» выберите файл.
3. Нажмите «Загрузить файл».
4. После успешной загрузки страница обновится, а вложение появится в списке.

Поддерживаются изображения, распространённые документы, аудио и видео из серверного allowlist. Сервер не доверяет MIME, присланному браузером: содержимое файла проверяется отдельно.

Вложения находятся в приватном хранилище. Копировать прямой путь на диске невозможно; browser получает файл через `/notes/attachment/<file_uid>` после проверки владельца.

### Голосовая заметка
1. Нажмите «Записать голосовое».
2. Разрешите браузеру доступ к микрофону.
3. Нажмите «Начать запись».
4. Нажмите «Остановить» и прослушайте preview.
5. Нажмите «Загрузить запись».

Если browser не поддерживает `MediaRecorder/getUserMedia`, кнопка записи скрывается. Можно загрузить поддерживаемый audio-файл обычным способом.

### Удалить вложение
Нажмите «Удалить» рядом с вложением и подтвердите действие. В текущем storage lifecycle запись помечается удалённой; политика физической очистки задаётся отдельно.

### Поделиться заметкой
1. Откройте заметку.
2. В блоке «Поделиться заметкой» задайте срок действия ссылки в часах. `0` означает бессрочно до ручного отключения.
3. Нажмите «Создать ссылку для просмотра».
4. Передайте полученный URL нужному человеку.

Публичная ссылка в текущей версии работает **только на просмотр**. Получатель может читать текст и открывать вложения, но вложения всё равно выдаются через token-bound endpoint. Если владелец отключит ссылку или срок истечёт, текст и файлы перестанут открываться по этому token.

### Отключить sharing
На странице заметки нажмите «Деактивировать ссылку». Старый URL перестаёт быть действующим.

## 3. Задачи и ежедневник

Раздел `/tasks/` содержит персональные задачи.

Для задачи доступны:
- название и описание;
- статус `pending / in_progress / completed / cancelled`;
- priority;
- срок исполнения (`due_date`);
- подзадачи;
- категории.

### Основной сценарий
1. Создайте задачу, задав название, приоритет и при необходимости срок.
2. Меняйте статус по ходу работы.
3. Для крупных задач добавляйте подзадачи.
4. Используйте категории для группировки.
5. Фильтры позволяют показать задачи на сегодня, неделю, просроченные и по статусу.

Модуль Tasks является следующим после Notes техническим этапом аудита: его schema/model/UI contracts дополнительно проверяются на согласованность. Поэтому при обнаружении нестабильного edge-case его следует фиксировать как дефект, а не обходить изменением БД вручную.

## 4. Личные файлы

Раздел `/files/` — личный файловый менеджер пользователя.

### Папки
- создавайте папки для структуры;
- переходите в папку из списка;
- breadcrumb помогает вернуться на уровень выше.

### Файлы
- загрузка выполняется через «Загрузить»;
- имя можно переименовать;
- файл можно удалить;
- чтение/скачивание выполняется через защищённый `/files/get/<id>/`, а не через прямой filesystem URL.

File Manager хранит новые файлы под `PRIVATE_STORAGE_PATH/file_manager`. Доступ другого пользователя к вашему file ID не должен выдавать содержимое.

## 5. Messenger

Раздел `/messenger/` предназначен для корпоративных real-time сообщений.

### Личный чат
1. Нажмите создание нового чата.
2. Выберите одного пользователя.
3. Отправляйте сообщения через composer.

### Групповой чат
При выборе нескольких пользователей создаётся группа. В группе используются роли:
- **owner** — владелец группы;
- **admin** — управляет обычными участниками и частью настроек;
- **member** — обычный участник.

Owner может назначать admin и передавать владение. Owner должен передать владение перед выходом, если в группе остаются участники.

### Ответ, изменение и удаление
У сообщения доступны действия:
- «Ответить» — создаёт reply-to;
- «Изменить» — для собственных сообщений;
- «Удалить у меня» — скрывает только для вас;
- «Удалить у всех» — доступно отправителю согласно server policy.

### Вложения
Скрепка позволяет выбрать image/audio/video/document. Вложения хранятся приватно и выдаются только участникам диалога. Для media поддерживается streaming/byte range там, где это нужно browser player.

### Голосовые сообщения
Кнопка микрофона запускает запись. Во время записи доступны таймер, отмена и отправка. Player поддерживает seek и скорости 1x/1.5x/2x.

Доступ к микрофону запрашивает browser. Если разрешение запрещено, запись не начнётся.

### Реакции
Сообщения поддерживают ограниченный корпоративный набор реакций: 👍 ❤️ 😂 😮 😢 🔥. Нажатие на reaction chip переключает вашу реакцию; число рядом показывает aggregate count.

### Доставка и прочтение
Messenger различает состояния sent/delivered/read. Read acknowledgement не ставится только от факта загрузки истории: клиент отправляет его явно, когда соответствующий чат активен.

### Несколько вкладок и устройств
События синхронизируются по всем активным WebSocket connections пользователя: сообщение или изменение, выполненное в одной вкладке, должно появляться и в других активных вкладках.

### Pin, mute, archive
Состояния применяются персонально:
- pin поднимает важный чат;
- mute временно отключает уведомления по состоянию пользователя;
- archive переносит чат в архивную папку.

### Поиск
Поиск сообщений не создаёт plaintext-копию текста в БД. Сервер выполняет ограниченный decrypt-scan доступной истории. Поэтому поиск в очень больших историях намеренно ограничен и не предназначен для полного сканирования миллионов сообщений.

### Forwarding и «Сохранённые сообщения»
Функциональность реализована в отдельном PR #50 и считается частью ближайшего обновления только после его merge в `master`. До слияния #50 пользовательская документация не должна предполагать наличие этих кнопок на production/stage ветке.

## 6. Профиль

Раздел `/profile/` позволяет работать с данными текущего пользователя. Доступны основные операции профиля, смена пароля и удаление аккаунта через защищённые POST actions.

После изменения пароля используйте новый пароль при следующей авторизации. Не используйте один пароль для Workspace Organizer и внешних сервисов.

## 7. Admin panel

`/admin/` доступен только пользователям, которых `Config::isAdminRole()` признаёт администраторами.

Администратор может:
- просматривать/управлять пользователями в рамках текущей панели;
- блокировать/разблокировать пользователя;
- выполнять предусмотренное интерфейсом удаление пользователя;
- настраивать custom profile fields.

Наличие URL `/admin/` само по себе не даёт прав: route дополнительно закрыт `LoginRequared + IsAdmin`.

## 8. Безопасная работа пользователя

- Не пересылайте публичные share-ссылки заметок шире необходимого круга.
- Отключайте share после завершения совместной работы.
- Не загружайте секреты, ключи и пароли как обычные вложения, если внутренние правила организации этого не разрешают.
- При подозрении на компрометацию аккаунта смените пароль и сообщите администратору.
- Не пытайтесь использовать physical storage URL/path: поддерживаемый способ получения файла — только интерфейс приложения.

## 9. Что считать ошибкой

Сообщите администратору/разработчику, если:
- вы видите чужую заметку/файл/чат без предоставленного доступа;
- удалённая или просроченная share-ссылка продолжает отдавать вложения;
- browser отображает physical filesystem path;
- приложение показывает encrypted ciphertext как обычный текст;
- действие в Messenger появляется у пользователя, который не является участником диалога;
- upload принимает исполняемый HTML/JS/PHP/SVG как обычное вложение;
- задача/подзадача меняется у другого пользователя.

Такие случаи являются дефектами безопасности/ACL и не должны считаться допустимым поведением alpha-версии.
