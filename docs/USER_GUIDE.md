# Workspace Organizer — инструкция пользователя

Актуально на 13.09.2026. Документ описывает текущую корпоративную alpha-версию после hardening Messenger, Notes, Tasks и Profile.

## 1. Навигация и вход

После входа открывается dashboard с быстрыми переходами в Заметки, Задачи, Файлы, Messenger и Профиль.

На desktop основная навигация находится в левом sidebar; его можно свернуть. На телефоне sidebar открывается кнопкой меню и закрывается кнопкой, кликом по затемнению или `Esc`.

### Вход

1. Откройте `/auth/login`.
2. Введите **логин** и пароль.
3. Нажмите «Войти».

После успешной проверки создаётся рабочая session. Несколько неправильных попыток подряд могут временно включить rate limit.

### Регистрация

Самостоятельная открытая регистрация отключена. Администратор выдаёт invite URL вида:

```text
/auth/registration/<invite_code>
```

Если invite не настроен или неверен, форма недоступна. После регистрации аватар добавляется в Профиле.

## 2. Заметки

Раздел `/notes/` предназначен для личных рабочих заметок.

### Создать и изменить заметку

1. Введите название в верхней форме и нажмите «Создать».
2. На странице редактирования введите текст.
3. Сохраните изменения.

Текст заметки хранится в БД в зашифрованном виде. Название заметки не является частью encrypted text payload.

### Вложения

1. Откройте заметку на редактирование.
2. В блоке вложений выберите файл.
3. Загрузите его.
4. Открывайте или удаляйте вложение через элементы интерфейса.

Browser не получает physical storage path. Owner download идёт через protected endpoint после ACL-проверки. Сервер сам определяет MIME через `finfo`; тип из браузера не считается доверенным.

### Голосовое вложение

Если browser поддерживает `MediaRecorder/getUserMedia`, можно записать звук с микрофона, прослушать preview и загрузить запись. При запрете microphone permission запись не начнётся.

### Поделиться заметкой

1. Откройте заметку.
2. Создайте view-only share link и при необходимости задайте срок действия.
3. Передайте ссылку получателю.
4. После завершения совместной работы отключите sharing.

Share даёт только просмотр. Текст и вложения привязаны к активному token; после отключения или expiry ссылка перестаёт работать.

## 3. Задачи

Раздел `/tasks/` содержит персональные задачи.

Для задачи доступны:

- название и описание;
- `pending / in_progress / completed / cancelled`;
- priority `low / medium / high / urgent`;
- срок исполнения;
- подзадачи;
- категории;
- фильтры today/week/overdue/status.

### Рабочий сценарий

1. Создайте задачу.
2. Укажите приоритет и срок.
3. Меняйте статус в ходе работы.
4. Добавляйте подзадачи для крупных задач.
5. Используйте категории и фильтры для организации списка.

Tasks работает по canonical schema и per-user ACL: пользователь не должен иметь возможность изменять чужую задачу, подзадачу или личную категорию.

## 4. Личные файлы

Раздел `/files/` — private File Manager.

### Папки и файлы

- «Новая папка» создаёт каталог внутри текущего раздела;
- breadcrumb показывает текущий путь;
- «Загрузить файл» поддерживает server allowlist;
- rename/delete доступны из actions карточки;
- protected файл открывается через `/files/get/<id>/` только после ownership-проверки.

На touch/mobile actions видимы без hover.

### Media и текстовый preview

Double-click/Enter по поддерживаемому image/audio/video открывает встроенный viewer/player. Text/code-файлы открываются в **read-only preview**.

Workspace **не выполняет код из пользовательских файлов** и не предоставляет browser code runner/editor.

## 5. Messenger

Раздел `/messenger/` — корпоративные real-time сообщения.

### Личный и групповой чат

Создайте новый чат и выберите пользователя или несколько участников. В группах действуют роли:

- **owner** — владелец;
- **admin** — администратор группы;
- **member** — участник.

Owner может управлять ролями и передавать ownership. Перед деактивацией аккаунта владелец активной группы должен передать ownership.

### Сообщения

Доступны:

- reply;
- edit собственных сообщений;
- delete-for-me;
- sender-only delete-for-all;
- delivered/read state;
- reactions 👍 ❤️ 😂 😮 😢 🔥;
- forwarding;
- media и voice messages.

### Saved Messages

«Сохранённые сообщения» — single-user dialog для личных сообщений/пересылок внутри Workspace.

### Forwarding

Сообщение можно переслать в доступный чат или сохранить себе. Forwarded media создаёт независимую private copy в целевом диалоге, поэтому удаление исходного attachment не должно ломать уже пересланную копию.

### Голосовые сообщения

Кнопка микрофона запускает browser recording. Доступны timer/cancel/send, а player поддерживает seek и скорости 1x/1.5x/2x.

### Multi-device

Messenger синхронизирует realtime events со всеми активными WebSocket connections пользователя. Изменение из одной вкладки должно появиться в другой без повторного входа.

### Pin, mute, archive

Эти состояния персональны для пользователя и не меняют настройки диалога у остальных участников.

### Search

Encrypted search не создаёт plaintext index. Сервер выполняет bounded decrypt-scan доступной истории, поэтому очень старая история может не попадать в один запрос поиска.

## 6. Профиль

Раздел `/profile/` позволяет:

- изменить имя/фамилию/отчество/телефон/email;
- заполнить configured custom fields;
- загрузить или удалить private avatar;
- сменить пароль;
- деактивировать собственный аккаунт.

### Аватар

Новые avatars хранятся вне document root и выдаются через authenticated `/profile/avatar/<uid>`. Physical path пользователю не показывается.

### Пароль

Смена требует текущий пароль. Новый пароль должен содержать не менее 10 символов и отличаться от текущего.

### Деактивация

«Удаление аккаунта» в текущем contract — это **деактивация**, а не физический `DELETE users`. Notes/messages и связанные данные сохраняются. После деактивации вход и активные WebSocket actions блокируются.

Если пользователь владеет активной Messenger-группой, сначала необходимо передать ownership.

## 7. Admin panel

`/admin/` доступен только admin roles, определённым в `Config`.

Панель позволяет:

- просматривать пользователей;
- блокировать/разблокировать;
- выполнять предусмотренные admin account actions;
- управлять custom profile fields.

Знание URL не даёт доступа: route закрыт authentication + admin middleware.

## 8. Безопасная работа

- Не передавайте пароль или invite-code посторонним.
- Используйте «Выйти» на общих устройствах.
- Не пересылайте Notes share-link шире необходимого круга.
- Отключайте share после завершения работы.
- Не пытайтесь обращаться к physical storage path — поддерживается только защищённая выдача через приложение.
- При подозрении на компрометацию смените пароль и сообщите администратору.

## 9. Что сообщать как дефект

Security/ACL defect, если:

- открывается чужая Note/File/chat без предоставленного доступа;
- expired/disabled share продолжает отдавать данные;
- UI показывает physical filesystem path;
- encrypted ciphertext показывается пользователю как нормальный текст;
- Messenger event получает неучастник диалога;
- upload принимает запрещённый executable/mismatched MIME;
- пользователь может менять чужую Task/Subtask/Category;
- деактивированный/blocked user продолжает выполнять authenticated actions;
- File Manager пытается выполнить содержимое загруженного code-файла.

Такие случаи не являются допустимым поведением alpha-версии и должны фиксироваться как дефекты.
