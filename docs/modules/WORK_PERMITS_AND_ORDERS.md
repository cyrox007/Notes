# Модуль «Журнал нарядов-допусков и распоряжений»

## Статус документа

Этот документ фиксирует функциональные требования к отдельному модулю Workspace Organizer для регистрации, учета, сопровождения и закрытия нарядов-допусков и распоряжений при работах в электроустановках.

Требования сформированы по пользовательскому описанию модуля и двум заполненным примерам нарядов-допусков:

- ПС 35 кВ «Болдыревка», КРУН-10 кВ, ячейка № 4 В-10 Т-1 — проверка цепей управления выключателя, опробование РЗА и АУВ;
- ПС 110 кВ «Жилзона», ОПУ, панель автоматики АЧР — восстановление автоматики частотной разгрузки.

Заполненные документы использовать как контрольные примеры для проверки полноты формы и генерации PDF.

## Назначение

Модуль предназначен для:

- регистрации нарядов-допусков и распоряжений;
- ведения их жизненного цикла;
- учета участников работ и их ролей;
- формирования выборок и отчетов;
- хранения связанных справочников и шаблонов;
- формирования наряда-допуска в PDF по утвержденной форме;
- административного исправления ошибочных данных.

Для распоряжений формирование PDF не требуется.

## Главная страница журнала

По умолчанию показываются зарегистрированные наряды и распоряжения за последний месяц.

Фильтры должны поддерживать выборку как минимум по:

- дате;
- сотруднику, выдавшему документ;
- производителю работ;
- ответственному руководителю работ;
- объекту эксплуатации — подстанции или иному объекту;
- состоянию документа.

На странице размещаются действия:

- «Зарегистрировать наряд»;
- «Создать распоряжение».

### Отображение состояний

- черновик наряда — желтое выделение;
- выданный наряд / документ в работе — зеленое выделение;
- закрытые документы по умолчанию не показываются;
- закрытые документы доступны через соответствующий фильтр;
- закрытые наряды и распоряжения цветом не выделяются.

## Справочники

Повторно используемые данные должны выбираться из справочников, а не вводиться заново в каждом документе.

Справочники должны редактироваться на отдельной служебной странице, доступной пользователям с административными правами.

Необходимо предусмотреть как минимум следующие сущности:

- организации;
- подразделения;
- сотрудники;
- группы по электробезопасности;
- объекты эксплуатации / подстанции;
- шаблоны бригад;
- шаблоны заданий на производство работ;
- шаблоны условий производства работ;
- шаблоны отдельных указаний.

Для организации и подразделения необходимо запоминать последнее выбранное значение и предлагать его при создании следующего наряда.

## Участники и роли

В наряде используются роли:

- ответственный руководитель работ;
- допускающий;
- производитель работ;
- наблюдающий;
- работник, выдавший наряд;
- члены бригады.

Значение допускающего по умолчанию — «оперативному персоналу».

Значение наблюдающего по умолчанию — «не назначается».

Для членов бригады требуется множественный выбор.

Должны поддерживаться шаблоны бригад с возможностью последующего ручного изменения состава.

Один сотрудник может одновременно занимать несколько допустимых ролей в одном документе. Система не должна искусственно запрещать совпадение ответственного руководителя и производителя работ, поскольку такой вариант встречается в реальном заполненном наряде.

## Жизненный цикл наряда-допуска

### Этап 1. Регистрация

При создании наряду присваивается сквозной автоматический номер.

Обычный пользователь номер не редактирует. Пользователь с административными правами может изменить номер вручную, в том числе у существующего документа.

Форма регистрации группируется по смысловым блокам.

### Блок «Организация»

- организация;
- подразделение;
- номер наряда.

### Блок «Состав бригады»

- ответственный руководитель работ;
- допускающий;
- производитель работ;
- наблюдающий;
- члены бригады.

### Блок «Задание на производство работ»

- многострочное задание на производство работ;
- дата и время начала;
- дата и время окончания.

Для задания должны поддерживаться шаблоны и сохранение ранее введенного текста как нового шаблона. После выбора шаблона текст остается редактируемым.

### Блок «Условия производства работ»

Необходимо поддерживать набор строк / мероприятий, а не сводить условия к одному неструктурированному полю.

Для каждого набора условий должны храниться:

- наименование электроустановок, в которых необходимо провести отключения и установить заземления;
- что должно быть отключено и где заземлено;
- что должно быть изолировано или ограждено.

Значение по умолчанию для последнего поля:

> Оборудование и токоведущие части, оставшиеся в работе под напряжением.

Поля могут вводиться вручную или заполняться из шаблона с последующим редактированием.

Заполненный наряд по ПС «Болдыревка» подтверждает необходимость нескольких отдельных мероприятий по подготовке рабочего места: отключение выключателя, трансформатора и шинного разъединителя.

Заполненный наряд по ПС «Жилзона» подтверждает другой допустимый сценарий: подготовительные отключения не требуются, а первичное оборудование из работы не выводится. Поэтому модель данных не должна предполагать обязательное наличие отключений.

### Блок «Отдельные указания»

Многострочный текст с поддержкой:

- ручного ввода;
- выбора отдельного шаблона;
- сохранения введенного текста как шаблона;
- редактирования текста после выбора шаблона.

### Выдача и целевой инструктаж

Для поля «Наряд выдал» подставляются текущие дата и время.

ФИО выбирается из справочника.

В блоке целевого инструктажа:

- в «Целевой инструктаж провел» подставляется работник, выдавший наряд;
- в «Целевой инструктаж получил» подставляется ответственный руководитель работ;
- автоматически подставленные значения разрешается изменить вручную.

После заполнения документ сохраняется как черновик. До выдачи его разрешается редактировать без ограничений.

Когда обязательные данные заполнены, становится доступно действие «Выдать наряд».

### Этап 2. Выдача

После выдачи:

- документ получает состояние «В работе»;
- обычное редактирование блокируется;
- остаются разрешенными операции продления и закрытия.

### Этап 3. Выполнение, ежедневные допуски и закрытие

Необходимо хранить отдельно от исходных данных наряда:

- ежедневные допуски к работе;
- время начала и окончания работ по каждому допуску;
- целевые инструктажи;
- изменения состава бригады;
- продление наряда;
- окончательное закрытие наряда.

Поля «к работе приступили» и «работы окончены» должны поддерживать несколько записей, поскольку наряд может действовать несколько дней подряд.

Поля продления не являются обязательными и заполняются только при фактическом продлении.

После заполнения даты и времени закрытия становится доступно действие «Закрыть наряд».

После закрытия документ перестает отображаться в обычном списке и доступен через фильтр закрытых документов.

Пользователь с административными правами может редактировать и удалять наряд на любом этапе, включая закрытый.

## Распоряжения

Распоряжение отличается от наряда-допуска следующим:

- выдается только на один день / рабочую смену;
- не продлевается;
- не требует формирования PDF;
- содержит сокращенный набор полей.

Жизненный цикл распоряжения:

1. «Черновик»;
2. «Выдано»;
3. «Закрыто».

После выдачи редактирование блокируется, кроме операции закрытия.

Поля распоряжения:

- номер распоряжения;
- выдающий распоряжение;
- производитель работ;
- дата и время регистрации;
- задание на производство работ;
- члены бригады;
- меры безопасности;
- дата и время закрытия;
- ФИО закрывшего распоряжение.

Номер присваивается автоматически и сквозным образом. Администратор может изменить его вручную.

Для задания, состава бригады и мер безопасности должны использоваться те же принципы шаблонов и справочников, что и в нарядах.

После заполнения данных закрытия становится доступно действие «Закрыть распоряжение».

Администратор может редактировать и удалить распоряжение на любом этапе.

## Требования к PDF наряда

PDF формируется только для наряда-допуска.

Цель генератора — воспроизводить утвержденную форму документа, а не создавать произвольный отчет с теми же данными.

Необходимо корректно переносить в PDF:

- организацию и подразделение;
- номер наряда;
- роли и состав бригады;
- задание;
- сроки работ;
- таблицу мероприятий по подготовке рабочих мест;
- отдельные указания;
- сведения о выдаче и продлении;
- блоки целевого инструктажа;
- ежедневные допуски;
- изменения состава бригады;
- сведения о полном окончании работ.

Количество записей ежедневного допуска и изменений состава бригады является переменным. Генератор PDF должен корректно обрабатывать изменение объема этих разделов и переносы на следующие страницы.

## Контрольные сценарии

### ПС 35 кВ «Болдыревка»

Использовать для проверки сценария, где:

- работа выполняется в КРУН-10 кВ;
- требуется несколько отключений;
- проверяются цепи управления выключателя, РЗА и АУВ;
- присутствуют ответственный руководитель, производитель работ и член бригады.

### ПС 110 кВ «Жилзона»

Использовать для проверки сценария, где:

- первичное оборудование из работы не выводится;
- отключения не требуются;
- работа ведется с автоматикой АЧР;
- наряд многодневный;
- один сотрудник одновременно является ответственным руководителем и производителем работ;
- в бригаде несколько членов.

## Архитектурное ограничение

Модуль нельзя реализовывать как одну монолитную форму и одну таблицу БД.

Наряд, участники, роли, справочники, шаблоны, ежедневные допуски, продления, изменения состава бригады и события закрытия должны быть разделены на самостоятельные сущности с явными связями.

Это необходимо для поддержки реального жизненного цикла документа, повторного использования справочников и шаблонов, формирования отчетов и надежной генерации PDF.
