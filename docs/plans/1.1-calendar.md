# 1.1 — Календарь и ежедневник

Статус: **следующий продуктовый релиз**.

Календарь — отдельный модуль планирования времени, а не переименование Tasks.

## Целевой объём

- день / неделя / месяц;
- agenda и планирование дня;
- события;
- повторяющиеся события;
- напоминания через общий платформенный слой уведомлений;
- временные блоки;
- связи с Task/Note/File только через публичные capability;
- личные и, при подтверждении требований, общие календари;
- корректная работа часовых поясов;
- import/export как последующая возможность;
- собственные permissions, schema, migrations, storage и browser lifecycle.

Tasks отвечает за задачи и доски, Calendar — за время и календарный контекст.

## Уведомления — обязательная зависимость 1.1.0

В 1.1.0 Calendar не реализует собственные E-mail, Push, Telegram, Webhook или SMS-отправители.

Модуль публикует семантическое событие `calendar.reminder_due` через общий `NotificationService`. Сервис уведомлений:

- создаёт встроенное уведомление;
- применяет подписки пользователя;
- выполняет дедупликацию;
- ставит внешнюю доставку в очередь;
- повторяет временно неуспешную доставку;
- хранит итоговое состояние канала.

Полный контракт: [1.1-notifications.md](1.1-notifications.md).

## До начала реализации нужно зафиксировать

- модель повторяющихся событий и изменение одного экземпляра/серии;
- правила часовых поясов и переходов DST;
- модель общих календарей и их ACL, если они входят в первый этап;
- правила времени напоминаний и нескольких напоминаний одного события;
- правила пропущенных напоминаний после простоя сервера;
- идемпотентный ключ для конкретного экземпляра повторяющейся серии;
- границу первого релиза для import/export.

## Обязательные платформенные условия

- минимальная версия PHP линии 1.1 определяется политикой ROADMAP;
- типовые операции проектируются в рамках контракта 1000 активных пользователей;
- модуль должен полностью отсутствовать из composition без ошибок Core и соседних модулей;
- межмодульные ссылки не дают прямого доступа к внутренним таблицам соседних модулей;
- отсутствие или отказ внешнего канала уведомлений не должен ломать Calendar;
- напоминания должны корректно восстанавливаться после простоя shared-hosting/worker без дубликатов.

## Зафиксированная граница 1.1.0 (13.10.2026)

В первый выпуск входят личный календарь, день/неделя/месяц, agenda/ежедневник, события и повторы с изменением или удалением всей серии, часовые пояса/DST, несколько напоминаний, восстановление после простоя, временные блоки и безопасные связи с Tasks/Notes/Files.

Изменение одного экземпляра повторяющейся серии, общие календари и их ACL, import/export перенесены за пределы 1.1.0. Интерфейс не должен обещать эти операции: редактирование повторяющегося события относится ко всей серии. Telegram, Webhook, SMS и Web Push также не входят в обязательную поставку 1.1.0; поддерживаются встроенные уведомления и E-mail, а контракт каналов сохраняет расширяемость.

Нагрузочная приёмка 1000 активных пользователей перенесена на 1.2.0. Функциональная приёмка, ограничения запросов, install/update/rollback и сохранность данных остаются обязательными для 1.1.0.
