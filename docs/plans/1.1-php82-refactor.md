# 1.1 — Полный рефакторинг под PHP 8.2

Статус: **обязательная часть 1.1.0**.

Линия 1.1 повышает минимальную версию PHP с 8.1 до **8.2** и использует это повышение для последовательного упрощения всего серверного кода Workspace Organizer. Цель — не механическая замена синтаксиса, а уменьшение сложности, удаление устаревших конструкций и приведение ядра и модулей к единому современному стилю без изменения пользовательского поведения.

## Основные правила

- минимальная версия ветки 1.1 — PHP 8.2;
- линия 1.0.x сохраняет совместимость с PHP 8.1 и не получает этот рефакторинг обратным переносом;
- каждый проход должен сохранять существующие контракты данных, ACL, обновления и миграции;
- пирамидальная структура методов устраняется через ранний выход, небольшие методы и явные отдельные ветви;
- `readonly class` используется для неизменяемых DTO и value-object, когда состояние действительно не должно изменяться;
- свойства объявляются явно; динамические свойства не используются;
- типы аргументов, возвращаемых значений и свойств уточняются там, где контракт это позволяет;
- `match`, enum, constructor property promotion, nullsafe-оператор, first-class callable и другие современные конструкции применяются только если они делают код короче и понятнее;
- возможности PHP 8.2, включая `readonly class`, DNF-типы и самостоятельные типы `true`, `false`, `null`, используются там, где они выражают реальный контракт;
- не вводится магия ради уменьшения количества строк;
- комментарии, сообщения диагностики, документация и описание изменений остаются на русском языке;
- runtime по-прежнему не должен требовать каталог `vendor`.

## Что удалить

В рабочем коде 1.1 не должно остаться:

- `#[AllowDynamicProperties]` как способ скрыть необъявленное состояние;
- неявного создания свойств через `$this->...`;
- `utf8_encode()` и `utf8_decode()`;
- `FILTER_SANITIZE_STRING`;
- устаревшей интерполяции `${var}`;
- устаревших `strftime()` / `gmstrftime()`;
- совместимости с PHP 8.1, которая усложняет код 1.1;
- мёртвых приватных методов и классов без подтверждённого использования;
- глубокой вложенности, которую можно заменить guard-clause или выделенным методом.

## Этапы

### Этап 0. Новый технический минимум

- `composer.json` и `composer.lock` требуют PHP 8.2+;
- отдельный CI линии 1.1 запускается на PHP 8.2 и 8.3;
- добавляется автоматический аудит кандидатов на переработку;
- системные требования явно разделяют линии 1.0.x и 1.1.

### Этап 1. Ядро и bootstrap

Область:

- `core.php`;
- `core/`;
- `index.php`;
- `install.php`;
- `bin/`;
- runtime обновлятора и миграций.

Приоритет: сначала границы запросов, конфигурация, маршрутизация, БД, обновлятор и файловая система. Изменения обновлятора делаются небольшими проходами с существующими recovery-тестами после каждого изменения.

### Этап 2. Общие сервисы приложения

Область:

- `app/models/`;
- `app/services/`;
- контроллеры и общие вспомогательные классы;
- новый слой уведомлений.

Неизменяемые структуры переводятся на `readonly class`, зависимости — на явные типизированные конструкторы, повторяемая проверка входных данных выносится в небольшие методы.

### Этап 3. Модули

Каждый модуль проходит отдельно:

1. Admin;
2. Notes;
3. Tasks;
4. Files;
5. Profile;
6. Messenger;
7. Calendar и новые модули 1.1.

Для каждого модуля сначала фиксируются действующие интеграционные и браузерные контракты, затем выполняется рефакторинг без смешивания с новой функциональностью в одном изменении.

### Этап 4. Представления и HTTP-точки входа

Шаблоны с HTML не переводятся механически в классы. В них сокращается вычислительная логика, подготовка данных выносится в контроллеры/сервисы, ветвления упрощаются, а экранирование и ACL сохраняются явными.

### Этап 5. Удаление переходного кода

После прохождения всех областей:

- удаляются временные compatibility-ветви PHP 8.1;
- удаляются подтверждённо неиспользуемые символы;
- обновляется статический аудит ядра;
- документация синхронизируется с фактической архитектурой;
- аудит PHP 8.2 переводится из информационного режима в обязательный release gate.

## Автоматический аудит

`tools/release/php82_refactor_audit.php` формирует список:

- запрещённых устаревших конструкций;
- файлов с class-like объявлениями без `strict_types=1`;
- нетипизированных свойств;
- возможных динамических свойств;
- файлов и строк, требующих ручного прохода.

На первом этапе отчёт является картой работ. По мере очистки категорий их допустимый остаток снижается до нуля и закрепляется тестами.

## Критерии завершения 1.1.0

Рефакторинг считается законченным только если одновременно выполнено следующее:

- весь рабочий PHP-код проходит `php -l` на PHP 8.2 и 8.3;
- Composer требует PHP 8.2+ и lock согласован;
- в рабочем коде нет динамических свойств и перечисленных deprecated-конструкций;
- class-like файлы серверного слоя используют строгую типизацию, кроме отдельно обоснованных шаблонов/точек совместимости;
- все найденные аудитом нетипизированные свойства либо типизированы, либо имеют зафиксированное техническое обоснование;
- устранены подтверждённо мёртвые классы, функции и приватные методы;
- методы с избыточной вложенностью переработаны без пирамидальной структуры;
- существующие интеграционные, security, updater и браузерные проверки остаются зелёными;
- установка и обновление с последней 1.0.x на 1.1.0 проверены отдельно;
- Windows/OSPanel и shared-hosting приёмка выполняется уже на PHP 8.2+.

## Порядок работы с новой функциональностью

Новые функции 1.1 (уведомления, Calendar и последующие изменения) сразу пишутся по правилам PHP 8.2. Старый код перерабатывается последовательными областями. Это не блокирует разработку 1.1, но стабильный релиз 1.1.0 запрещён до завершения полного прохода.
