# Модульная платформа Workspace Organizer

Актуально для линии **1.0.14**.

Практическая инструкция: [MODULE_DEVELOPMENT.md](MODULE_DEVELOPMENT.md). Изоляция runtime: [MODULE_RUNTIME_ISOLATION_1.0.md](MODULE_RUNTIME_ISOLATION_1.0.md).

## Граница Core

Core владеет платформенными механизмами: bootstrap, Router/Request/View, аутентификация и сессии, RBAC, БД и транзакции, lifecycle модулей, лицензирование, updater/recovery и общий интерфейс.

Прикладные функции живут в модулях. Встроенные модули: `admin`, `files`, `messenger`, `notes`, `profile`, `tasks`.

## Manifest и runtime

Каждый модуль находится в `modules/<id>/` и имеет `module.json`.

Production-модуль:

- использует `runtime.mode = isolated`;
- объявляет entrypoint;
- объявляет зависимости и capability;
- объявляет storage/schema ownership;
- объявляет `license.feature`;
- не исполняется только потому, что его файлы присутствуют на диске.

`ModuleRegistry` проверяет manifest, зависимости, совместимость и порядок загрузки. `ModuleRuntimeLoader` загружает provider только для фактически активной композиции.

## Жизненный цикл

Платформа различает:

- `configured_state` — намерение оператора;
- `effective_state` — фактическое состояние после лицензии, совместимости и зависимостей.

К фактическим состояниям относятся в том числе `unlicensed` и `incompatible`.

Отключение или отсутствие лицензии не удаляет пользовательские данные, RBAC и сохранённые настройки модуля.

## Лицензия

Модуль запускается только при явном наличии его `license.feature` в действующей подписанной лицензии.

Для встроенных модулей, начиная с 1.0.13, используются:

- `workspace.admin`;
- `workspace.notes`;
- `workspace.tasks`;
- `workspace.files`;
- `workspace.messenger`;
- `workspace.profile`.

Пустой или отсутствующий список `features` не означает полный доступ.

## Обязательный Admin

Решение о неотключаемом системном модуле принадлежит Core. Начиная с 1.0.13 таким модулем является только `admin`. Сторонний пакет не может самостоятельно сделать себя обязательным.

При отсутствии `workspace.admin` Admin runtime не загружается, но core-маршрут восстановления лицензии остаётся доступным пользователю с правом управления лицензией.

## Межмодульные связи

Модули взаимодействуют через capability/service contracts. Прямое чтение внутренних таблиц, файлов или сервисов соседнего модуля не является поддерживаемой границей.

Потребитель обязан корректно работать при отсутствии необязательной capability.

## База данных и storage

Каждый модуль владеет собственной схемой, миграциями и private storage namespace. Отключение не означает физическое удаление данных.

## Будущее платформы

Подписанные устанавливаемые пакеты, publisher trust, resolver версий, полноценные install/uninstall hooks, каталоги и health-state относятся к развитию после 1.0 и отслеживаются в [ROADMAP.md](ROADMAP.md).
